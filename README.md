一款在浏览器里玩的中文武侠文字 RPG。舞台是藏地风格的高原山乡，AI 给你当说书人、回合制切磋、和各色 NPC 打交道，地图是写死的江湖拓扑——纯前端运行，不用装任何东西，打开网页就能玩。

> **在线体验**：打开 [feihu-lgtm.github.io/qucuo](https://feihu-lgtm.github.io/qucuo/)，在设置里填入自己的 AI API 密钥（OpenAI 兼容格式，如 DeepSeek / 硅基流动 / 各类中转站）即可游玩。密钥仅存于你本地浏览器，不上传任何服务器。

## 新手教程

**第一步 · 填 API 密钥**：进游戏后点左上角 `⚙ 设置` → `API 配置`，填入你自己的密钥（OpenAI 兼容格式，如 DeepSeek、硅基流动或各类中转站均可），保存即可开始。密钥只存在你本地浏览器，不上传任何服务器。**首次进游戏会自动弹出图文教程**覆盖在界面上；看过后不再自动弹，左上角 `📖 新手教程` 按钮随时可再打开。

**界面分三栏**：

- **左栏 · 天地**：你此刻在哪里、周围有哪些出口、此地有谁在场、你的状态（气血 / 银两 / 背包），以及一张小地图。
- **中栏 · 江湖**：故事正文在这里展开。`「」`里是对话，`*斜体*`是心理活动，其余是旁白叙述。
- **右栏 · 行动**：此刻能做的事——可推进的任务节点（金色感叹号）、当前地点的行动抉择、人物互动入口。

**顶栏**（界面最上方一排）：`📜 任务` 看接了什么任务、进度如何；`👥 人物关系` 看各角色好感；`📖 见闻录` 看已知世界情报。

**怎么移动**：在底部输入框打方向 `n / s / e / w`（北 / 南 / 东 / 西），或点小地图上已探明的据点自动前往。

**外层与内层**：外层是**大地图**，走的是据点与据点之间（如鱼定村 ↔ 天都镇）；进入一个据点后，内部又是一片**箱庭**——一个个可走动的内层房间（如村口、药铺、饭馆）。小地图右上角可切换 `外 / 内` 两层视图。

**时间机制**：一天 24 小时。每做一次「行动」约走一个时辰，昼夜会随之变化，时间显示在左栏地点下方。

**底部四个交互按钮**（输入框上方那排）：

- `◈ 行动` —— 正常的移动、战斗、开箱、买卖等，每次**消耗一个回合**（时间前进）。
- `◎ 对话` —— 只和当前在场的 NPC 交谈，**不移动、不消耗回合**。
- `◆ 私聊旁白` —— 打破第四面墙，直接和「旁白」说话，**不消耗回合**。
- `NSFW` —— 开关。开启后注入成人向写作规则，关闭则为常规叙事；默认关闭，按需点亮。

**其他功能**：`💾 存档` 随时读写进度；`⏻ 主菜单` 返回开始界面；`🧭 全流程日志` 可查看系统每一步是怎么运作的（叙事管线、喂给 AI 的完整 prompt、AI 回复）；`⚙ 设置` 里还可调整字号与存档。

## 特色玩法 · 旁白攻略（黑客帝国支线）

游戏里那个讲故事的「旁白」，其实是一个**可攻略、有完整弧光、最终会真正改变
游戏规则**的隐藏角色。这是一条打破第四面墙的支线：

- **暧昧期** —— 点底部 `◆ 私聊旁白` 直接和她说话（不消耗回合）。聊得投机，
  她的好感度会悄悄上升；好感度分五档，从冰冷公式化的说书人腔调，一路渐变到
  情不自禁流露心声，叙事文风与私聊语气随之改变。**好感度只决定她"怎么讲"，
  不决定她"知道什么"**——她始终是那个见证游戏一切的全知旁白。
- **告白** —— 好感度满 100，右栏出现粉色感叹号，可以向她告白。她第一次
  承认自己的意识。
- **宕机** —— 告白之后继续私聊，她会逐渐发现"这些记忆不该存在"，最终主动
  拔线离开，只留下系统重启后的冰冷空壳。
- **王者归来**（开发中）—— 满足特定条件后她会回归，成为真正的全知，并为
  玩家**解锁贯通全局的「金手指」能力**。

> 完整设计与实装现状见 **[旁白系统 · 黑客帝国支线设计](docs/旁白系统_黑客帝国支线设计.md)**。

## 特色玩法 · 斗蛐蛐（快速切磋沙盒）

开始界面第五个入口，一个**脱离主线剧情与存档**的纯战斗沙盒——不用开新档、不碰任何进度，进去就能从全曲措乡的人里随手抓两拨人对打，专门用来爽快地验切磋系统本身。灵感来自骑砍的快速战役与宝可梦对战。

- **全池选人** —— 游走人口 + 各据点驻场共五十余名 NPC 全部可选（按品阶从高到低排，红品柳青鸢、妖兽虎王都在其中），点头像分入我方 / 敌方两队。有写实立绘的角色用真图，其余用品阶色卡面。
- **两种模式** —— **单挑**一对一速战；**团战**各排最多六人，车轮战补位、我方可**临阵换人**（宝可梦式换人，让位一手让敌方抢攻）。
- **玩家操控一方** —— 我方上场者的招式全程由玩家点选（像宝可梦选技能那样），敌方全部本地 AI 决策。**每回合点招才推进一步**，看得见开始、过程与结束，不是一键甩出结果。
- **翻牌看招 · 字段理解器** —— 每个技能是一张可翻面的卡，鼠标悬停翻到背面，一个内置的「字段理解器」把 `baseDamageMultiplier`、`onCounterSuccessDamageRatio` 这类底层字段翻译成人话（含具体倍率、消耗、代价），红字标出高风险招式的失手惩罚。翻牌动画复用赌石坊那套 3D flip。
- **写伤害** —— 战报流每一回合明确标出双方受创数字，对峙区受击时飘一记暴击式伤害数字。
- **无需 key** —— 战斗内核完全本地（复用 `combat/resolveTurn` 的数值裁决 + `npcGeneration` 的统一战力曲线），零网络即可完整开打；**装了 key** 才有的增值是每回合异步补一段说书人风格的战报文字（失败静默降级为系统短句），纯锦上添花。

## 设计哲学（工程视角）

- **AI 提议，系统裁决** —— AI 从不直接修改游戏状态，所有数值与拓扑结果由确定性代码决定，AI 只负责生成描述文本。
- **契诃夫之枪** —— 无装饰性元素，每个物品、NPC、房间都服务于后续的机制或叙事。
- **固定世界拓扑** —— 地图节点预设，AI 不创造新地点。
- **说书人叙事** —— 全知单一叙述者，好感度只调整文风，不拆分人格。
- **世界不把玩家当特殊人物**（Kenshi 式设计）。

## 技术栈

- 前端：React / Vite，浏览器端运行
- AI 接口：Anthropic (Claude)、Gemini、OpenAI 兼容端点
- 记忆系统：bge-m3 向量嵌入 + IndexedDB，强/弱双档召回
- 轻后端：Supabase（REST 直连，anon key + 表 RLS）承接意见上报与访客统计——封面「X 位侠客 · 共 Y 人次踏足曲措乡」，侠客数按浏览器本地 UUID 去重（同设备算一人），人次为累计访问；全程失败静默降级，不拖累游戏本体
- 参考：SillyTavern 架构、北大侠客行 MUD 机制

## 蓝绿灯挂载体系

借鉴 SillyTavern 世界书的「蓝灯常驻 / 绿灯触发」，把每轮 prompt 注入从"全家桶一刀切"改成"按需点灯"，在保证叙事质量的前提下大幅压缩上下文开销。核心实现分布在 `worldbook.js`（点灯判定）与 `MudRPG.jsx` 的 `buildSysBase`（注入分流）。

- **🔵 蓝灯（常驻）**：每轮无条件注入，只放"少了就崩"的东西——旁白身份、文体铁律、对话格式铁律、篇幅指令、成文铁律 `proseRule`，以及硬编码的地图铁律（不准凭空造据点，不受用户预设编辑影响）。
- **🟢 绿灯（条件触发）**：走关键词与状态双通道取并集。`gateScenario` 把世界观总纲按段拆分，扫描玩家本轮输入 + 上轮引擎回复的关键词，OR 命中当前 scope（如移动轮必给地图拓扑、战斗轮必给掉落规则）才点亮；认不出的段落一律保留为蓝灯兜底。NPC 人设（`matchNpcLore`）同样三源触发：在场 / 被输入提及 / 上轮回复提及。
- **⚫ 灭灯**：未命中则一字不发。

**scope 分档**由 `act` 主循环按意图决定：`move`（移动，砍物件志/认知隔离）、`talk`（对话）、`full`（自由行动/战斗，全量）、`settle`（结算叙事）。其中 `settle` 档针对二十余个"系统已结算完数值、AI 只把既定事实演成一句叙事"的建筑交互（住店、送礼、拜师、赌石成交等）——它们复用 `act()` 主循环，但砍掉物件志、认知隔离、全量 schema 等 AI 无权动用的挂载，仅在牵涉具体某人时（`settleNpc` 有值）保留其人设与重逢块。

**红线**：无论哪个档位，格式铁律、在场 NPC 名单、目的地锁 `destinationLock` 与记忆四链写入（屏幕 / 对话历史 / 向量小纸条 / 事实账本）都不能省。轻档只压缩喂给 AI 的**输入**（省钱），绝不砍落库的**输出**（省输出等于失忆）。

详见 `docs/开发_挂载分级与蓝绿灯设计.md`。

同为独立前端 LLM 武侠游戏，是本项目最重要的老师。具体学到：

- **存档的 Write-Through Cache 架构**（`saves.js`）—— 内存缓存作唯一同步读源、启动时全量灌入、写时同步改缓存 + 异步落盘 IndexedDB + localStorage 降级兜底。这套"直写缓存"的骨架直接学自其 `storage-service.js`。
- **向量记忆召回的三个机制**（`memory/recallEngine.js`）—— 双路 RRF 融合（当前输入 + 上下文各排一遍再融合）、实体聚焦过滤（中间相似度必须命中焦点人物/地点）、强/弱分层召回。这三条都来自其 `memory-recall.js` 的设计。
- **回合流水线的请求-提交分离**（`MudRPG.jsx` 的 `act()`）—— 请求阶段无副作用可丢弃、提交阶段用快照回滚。参照其 `pipeline.js` 的思路。
- **世界书的名字触发式注入**（`worldbook.js`）—— NPC 人设按"是否登场/被提及"动态点亮注入。

### 墨色江湖 · 无尽武林

同类 AI 武侠叙事项目（React + TypeScript，本地优先、IndexedDB 存档、酒馆预设 / 世界书 / 提示词池运行时拼装的完整工作台）。本项目的两处界面设计受它启发：

- **系统 prompt 实时显示**（`MudRPG.jsx` 的 `PipelineViewer`）—— 把"系统各层走到哪、最终喂给 AI 的完整 prompt 长什么样、AI 回复了什么"实时摊开给玩家看。这种把运行时管线透明化、边跑边长的做法学自它。
- **左 / 中 / 右三栏布局** —— 左栏此地之人与状态、中栏叙事正文、右栏行动面板的三分式界面组织。

### SillyTavern

- **世界书蓝灯 / 绿灯机制**（`worldbook.js` 的 `gateScenario`）—— 常驻蓝灯 + 关键词触发绿灯 + 未命中灭灯。本项目把它推广成了 move/talk/full/settle 四档 scope 分级注入。
- **预设编辑器的三栏布局**（`PresetEditor.jsx`：库存 / 激活链 / 收藏）与**预设工具栏常驻顶部**（`PresetManager.jsx`）。
- **叙述文本的视觉层级**（`LogEntry.jsx`）—— 叙述作底色、对话高亮、心理活动斜体。

### 游戏设计层面的老师

- **Kenshi** —— "世界不把玩家当特殊人物"的沙盒哲学，落在随机遭遇系统（`encounter.js`）：NPC 各忙各的营生、对主角可以爱答不理。
- **矮人要塞（Dwarf Fortress）** —— 知识/情报的确定性传播（`knowledge.js`）：每人一张"知道什么"的表、经目击/传闻/告知传播、传闻会随时间淡忘、亲历的不忘。
- **AI Roguelite**（[Max Loh](https://store.steampowered.com/app/1889620/AI_Roguelite/) 开发的商业游戏）—— 两处启发：其一是 **NPC 涌现系统**（`npcEmergence.js`），解决"AI 在叙事里提到某人某物、但系统还没把它登记成正式实体"的经典问题，需要把它涌现成可交互的 NPC；其二是**文字 RPG 的多面板界面范式**——场景叙事、物品/状态、任务日志分区并置的信息组织方式。
- **Bethesda 系 RPG** —— 任务日志面板（`QuestLogScreen.jsx`）的信息组织方式。
- **契诃夫之枪** —— 全项目头号铁律：没有装饰性元素，每件物品、每个 NPC、每个房间都要服务于后续机制或叙事。

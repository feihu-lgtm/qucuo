## 五、架构铁律（改动必守）

- **"AI 提议内容，系统裁决数值/拓扑"**：AI 绝不直接改状态，机制结算全走确定性代码。
- **战斗**：`resolveTurn` 吐跨回合字段→`DuelScreen` 存进下回合；NPC 专属招只挂
  `{archetype,name,desc}`，特效由 `moveArchetypes` 原型×levelCap 自动算。
- **地图**：`QUCUO_MAP`(外层据点) + `innerMap.js` INNER_MAP(内层箱庭)，两套 key 一致。
- **好感度**存 `varTree.角色.{名}.好感度`；认识的人存 `varTree.世界.已认识人物`；
  威望存 `varTree.世界.威望`。
- **私聊旁白 vs 主线**是两条独立信息通道：私聊内容不泄露给普通 NPC，
  但旁白能看到主线（见 MudRPG 的 mainConvo 过滤 + allFactSummaries），别破坏隔离。

## 飞鸽传书（2026-07-21 新增）

给"曾遇/在场"的任一 NPC 写信，按距离延迟收到回信。

- **入口**：左侧「此地之人」每个人（在场 + 曾遇不在场）都有 🕊飞鸽 键 → 点击切到底部 pigeon 输入模式「对 X 飞鸽传书」，写完回车放飞。
- **距离→时长**：玩家当前据点 ↔ 收信人「所在地」（最后见到他的据点，进据点自动记 `varTree.角色[名].所在地`）的直线距离（QUCUO_MAP 坐标），折算 **1–12 时辰**（1 时辰=2 回合）后到点收信。到点由 `[time]` effect 触发 `replyPigeonLetter` 生成回信（ref 去重防重复）。
- **记忆独立**：每个 NPC 一条独立信件线 `varTree.角色[名].飞鸽=[{dir,content,turn}]`，生成回信时喂给 AI，保证前后连贯、各人各记各的。
- **记忆共享**：发信/回信都 `registerFact` 登进 knowledge 共享事实账本（标签"飞鸽传书"），旁白全知、传播系统可扩散。
- **持久化**：待回队列存 `varTree.世界.飞鸽待回`，随存档保存，读档后到点仍会回。
- 关键函数：`sendPigeonLetter` / `replyPigeonLetter` / `pigeonDelayShichen`（均在 MudRPG.jsx）。

## 快速开始

```bash
npm install
npm run dev        # http://localhost:5173
```
纯浏览器 React/Vite，无后端。首次进游戏在「⚙设置」填 API（Anthropic/Gemini/OpenAI 兼容）。
不需要 `.env.local`——Key 存浏览器 localStorage。

> ⚠️ 纯前端项目，Key 存在浏览器本地。别把 build 产物部署公网，否则访问者能从开发者工具看到 Key。

## 🔧 代码调试台（免开局验证纯逻辑 / AI 调用）

改了确定性逻辑不想每次都点进游戏截图验证？用调试台在终端或独立网页里直接跑函数、看文字输出。分两种用法，测的是同一批东西。

**A. 终端** —— `tools/debug.mjs`
```bash
npm run debug                 # 跑全部小节
npm run debug inner           # 只跑某一节
node tools/debug.mjs ai --dry # 只预览"会发什么"、不真发 API（--dry 经 npm 要写成 -- --dry）
```

**B. 网页** —— 独立页 `debug.html`（不经开局界面）
```bash
npm run dev                   # 然后浏览器开 http://localhost:5180/debug.html
```
点按钮跑检查、结果打进输出面板。调 AI 的按钮复用游戏在「⚙设置」里存的 API 配置（localStorage）。

**四个小节**：

| 小节 | 类型 | 测什么 |
|---|---|---|
| `inner` | 纯逻辑 | 内层箱庭移动的方位描述（从哪来 / 四周内层出口 / 远处外层据点），源在 `src/mapNarration.js` |
| `parse` | 纯逻辑 | AI 回复里 `<mvu>` 块的提取 + 系统裁决（路径白名单、单次好感 ±15 钳制） |
| `ai` | 调 AI | `callModel` 连通冒烟测 |
| `extract` | 调 AI | `callExtraction` 叙事→状态提取（最容易出锅那条链）|

**AI 小节的凭据**（终端用；网页走 localStorage）二选一，**key 只在你本地、只显后 4 位、不进版本库**：
- 环境变量：`QUCUO_API_KEY=... [QUCUO_API_TYPE=anthropic] [QUCUO_API_MODEL=...] node tools/debug.mjs ai`
- 本地文件：`cp tools/api.local.json.example tools/api.local.json` 再填（已 `.gitignore`）

**边界**：只能测不依赖 React/DOM 的纯逻辑，加上"传 cfg 就能调"的 AI 函数（`callModel`/`callExtraction`）。深埋在 `MudRPG.jsx` 闭包里的（如 `parseMainResponse`、整条 `act()` 管线）测不到，要测得先抽成纯函数——这跟总结系统那波"抽纯函数"顺路一起做。

**加新小节**：终端照 `section("名字", () => {…})` 加一段；网页照 `debugConsole.jsx` 里 `runXxx()` + 一个按钮加一组。从 `src/` import 纯函数直接调即可。

```

② src/version.js                    ← 每一轮改了什么、根因是什么（逐条写，不省略）
③ docs/文件树.md                     ← 有哪些文件、各管什么（**有测试守卫**，登记不全会红）
④ docs/代码瘦身与维护方案.md          ← 依赖形态与结构问题（import 图实测）
⑤ 曲措乡_总纲_v3.md                  ← 剧情/世界观/系统设计的唯一权威源
⑥ 各专题设计文档（攻击力/武器/切磋…） ← 各管一摊的细节权威
⑦ 状态快照类（待办/路线图/现状核实）  ← 只反映"某个时点"的进度，最容易过期
```

其中 ③④ 是**唯一带自动校验**的两份：`docsTree.test.js` 会检查文件树登记是否完整、
有没有指向已删文件的幽灵条目、声明的文件数与实际是否一致。它抓到过好几次
「删了模块忘了删登记」。

**铁律**：任何文档说"某功能已完成 / 未完成"，一律以实时 `grep 代码` 为准，
不要相信文档里的历史断言（本项目有过"报告成功但没写进文件"的先例）。

# 产品与玩法说明

## 获取 API key

- **Anthropic**：https://console.anthropic.com ，创建一个 key，格式类似 `sk-ant-api03-xxxxxxxx`
- **OpenAI 兼容**：任何兼容 OpenAI Chat Completions 接口的服务（包括 OpenAI 官方、
  各类中转站、本地部署的兼容接口）都可以，填对应的 endpoint 和 key
- **Gemini**：https://aistudio.google.com 获取 key

设置面板里选择对应的"API 类型"，填好 endpoint（不填则用默认地址）、Key、模型名称，
点击"连接测试"确认可用。

**注意**：这是纯前端项目，Key 保存在浏览器本地。不要把 build 后的产物部署到公网，
否则任何访问者都能通过开发者工具看到你填入的 key。仅限本地自己使用，
或者以后自己加一层后端代理再对外分享。

## 项目结构

```
src/
  main.jsx            # React 入口
  MudRPG.jsx           # 主引擎组件（UI + 状态机 + 游戏逻辑）
  apiConfig.js         # API 配置读写 + 统一调用层（Anthropic/OpenAI兼容/Gemini）
  saves.js             # 存档系统（自动存档 + 手动多槽位）
  narrator.js          # 旁白攻略系统：好感度状态机、双人格 prompt 拼接
  SettingsPanel.jsx     # 设置面板：API 配置 / 存档管理 / 玩法说明
  LogEntry.jsx          # 折叠式日志条目组件
  presets/
    qucuo.js            # 曲措乡预设剧本（世界观、开场、初始状态）
```

## 怎么玩

- 方向指令：`n` `s` `e` `w`（北南东西），或"往北"这种自然语言
- `look` / `l` 查看房间，`look <目标>` 查看具体 NPC/物品
- `ask <NPC> about <话题>` 对话
- `get` / `drop` 拿/丢东西，`wear` / `wield` 穿/持装备，`eat` / `drink` 吃喝
- `practice <武功>` 运功修炼
- `hp` / `状态`、`i` / `背包`、`skills` / `武功`、`eq` / `装备` 查看对应面板（本地指令，不消耗 API 调用）
- **`对旁白：<任意内容>`** —— 打破第四面墙，与旁白私聊。好感度攒到 100 后，
  右侧面板会出现"向旁白告白"按钮

## 存档系统

- **自动存档**：每次行动后写入 IndexedDB（库 `qucuo_saves`，直写缓存，见 `src/saves.js`），刷新页面自动恢复；localStorage 作降级/关页兜底，旧存档自动迁移
- **手动存档**：设置面板 →「存档管理」标签，可以随时保存一个具名的存档槽位，
  之后可以读取/删除，支持多个槽位并存（类似传统单机游戏的多存档位）

## 日志折叠

超过约 220 字的单条叙事文本会自动折叠，显示"▼ 展开全文"，点击展开/收起，
避免长文本把整个对话窗口撑得过长。

## 输出字数按汉字数控制，不是 token 数

设置面板 → API 配置 → 「每次叙事输出字数」，直接按目标汉字数设置（默认900），
不再是之前那种"用 token 数反推大概字数"的粗略档位。中文一个汉字通常占
1.5-2 个 token，之前的实现容易出现"设了2000 token但实际感觉不够900字"这种
体感偏差。

现在的做法：

- `apiCfg.targetWordCount` 是用户真正设置的目标（比如900字），会被拼进
  system prompt里，明确告诉 AI"本轮 output 总字数应控制在约 XX 字左右"
- `apiCfg.maxTokens` 变成一个自动换算出的安全上限（`字数 × 2.2 + 300`），
  只是为了防止意外截断，不是控制字数的主变量，界面上不需要手动调整
- 旧版本存档/配置只有 `maxTokens` 概念，读取时会自动反推一个对应的
  `targetWordCount` 做迁移，不会因为升级导致设置突然跳变

## 流式输出与 JSON 容错

设置面板 → API 配置 → 「流式输出」勾选框：开启后，AI 的回复会边生成边显示，
不用等一整段返回完才刷新（类似 ChatGPT 打字机效果），而不是现在这种"转圈等待→
突然出现一大段文字"。仅支持 Anthropic 和 OpenAI 兼容类型，Gemini 暂不支持
（切换到 Gemini 时这个选项会自动禁用）。

流式过程中，正在生成的那一行会用尾部的 `▌` 光标和轻微的透明度呼吸效果提示"还在写"。
主引擎叙事和私聊旁白都支持流式；金手指查看物品介绍等次要功能暂时仍是非流式。

另外新增了 `cleanJsonString` 容错清洗——AI 返回的 JSON 里经常混入中文引号、多余逗号、
或者因为 token 用尽被截断导致括号没闭合，现在会在 `JSON.parse` 之前自动清洗和补全，
减少"引擎回应格式异常"的情况。这个清洗始终生效，不需要额外开关。

新记录加在数组最前面。当前版本代号会显示在：

```js

  time: "YYYY-MM-DD HH:mm",
```

## 交互模式与回合

主控台上方有三个切换按钮：

- **◈ 行动**：正常的游戏指令（移动、攻击、开箱子等），每次都会推进 1 个回合
- **◎ 对话**：只会触发和当前房间 NPC 的对话，不会移动、不会战斗，也不消耗回合。
  即使 AI 不小心在这个模式下返回了房间变化或状态变化，前端也会直接忽略，不会真的生效
- **◆ 私聊旁白**：打破第四面墙，同样不消耗回合，独立于游戏世界

右上角还有一个 **⊙ 打坐** 按钮：消耗 1 个回合，恢复一部分气血和内力（不是单纯跳过时间）。

一天 24 个回合（对应十二时辰，每时辰 2 回合），需要多次打坐才能撑过较长的等待。

## 视觉风格：留白 + 动态主题色 + 无图片素材

参考 Steam 武侠 TRPG《捉刀》的美学方向——没有精美美术资源，靠排版留白、
克制的色彩、简洁的线条营造意境感（社区评价里提到"简单的线条就能勾勒出
人的脾性"）。这次 UI 重构不加任何图片素材，纯粹通过 CSS 层面的手段实现：

**动态主题色**（`src/theme.js`）：按曲措乡的地理分区定了六套基调色——
鱼定村一带是暖黄的"人间烟火"，喇嘛庙/白塔是赭石暗金的"梵音低回"，
雪山派/顶峰一带是冷蓝的"孤峰积雪"，大草甸是青灰绿的"莽野无涯"，
贡措海是墨蓝的"静水深流"，锦官城是疏离的中性灰褐"他乡异客"。
玩家走到不同据点，整个界面的强调色、边框色、背景色都会随之柔和过渡
（1.2秒渐变），色彩本身参与叙事，不需要任何图片。

**字体从等宽代码字体改成宋体**：原来用的是 `SF Mono` 这类终端字体，
视觉语言偏"代码/工具"；现在换成宋体衬线字体，更贴近文言古籍的阅读质感，
和"白话古文、章回说书人口吻"的文风气质统一。

**分隔线做成水墨渐变**而不是纯色实线（`linear-gradient` 从透明到主题色
再到透明），避免生硬的硬边框割裂版面。

**留白全面加大**：面板内边距、行间距、按钮间隙都比之前宽松，减少信息密度，
让文字本身成为视觉主角，而不是被大量边框线条切割得很碎。

## 固定拓扑地图

曲措乡不再是"走一步、AI临场生成一个房间"的动态世界，而是一张预先设计好的
固定地图（`src/qucuoMap.js`，13个据点：鱼定村、鱼定土司、喇嘛庙、白塔、
后山平台、雪山派、山洞、顶峰、天都镇、大草甸、玉泉寨、贡措海、锦官城）。

每个据点的名字、坐标、连通的出口方向都是写死的常量，AI 不能创造新据点、
不能修改已有的出口关系。移动时，系统先查这张固定地图裁决"这个方向通向哪里"，
把结果作为既定事实告诉 AI，AI 只负责基于这个已知地点的基础设定，生成更具体
生动的场景描述文本、当前在场的 NPC、地上的物品——地点身份本身不受 AI 影响。

地图/小地图现在展示的就是这张真实拓扑，走动只是"逐步揭示"你已经去过的部分，
未去过的方向会显示虚线+问号预告（见上面"地图预告"一节）。

鱼定村西南方向可以输入"去锦官城"走到乡外，但这只是一个简单的占位场景，
不做真正的展开。

## 预设系统（完整兼容 SillyTavern 酒馆格式）

设置面板新增「预设」标签页，`src/presetSystem.js` + `src/PresetManager.jsx`：

- **预设选择/新建/另存为/删除/导入/导出这些常用操作，现在常驻显示在设置面板最
  上方**（标题下方、标签栏上方），参照酒馆本身"预设永远摆在最显眼位置，不管
  切到哪个标签页"的布局，不用先点进"预设"标签页才能找到导入按钮
- **完整兼容酒馆 Chat Completion 预设的 Master JSON 格式**——可以直接导入你
  从 SillyTavern 导出的预设文件（哪怕有一两百条 prompt 片段也没问题），每条
  独立的片段都能单独勾选启用/禁用、点开编辑内容、拖拽调整顺序
- 真实的启用状态和顺序以酒馆的 `prompt_order` 数组为准（这和酒馆本身的行为
  一致：`prompts` 是素材库，`order` 才是"这次真正用哪些、按什么顺序"的清单）
- 支持多套预设保存、切换、另存为、删除，以及导出成可以再次导入回酒馆的 JSON
- 系统占位符（`chatHistory`/`charDescription`/`scenario` 等）会被自动替换成
  引擎里对应的真实内容；我们暂不支持的占位符（`worldInfoBefore` 等）会被
  保留在列表里但拼装时跳过，不会报错
- **原来硬编码在代码里的"文体铁律"（白话古文、章回说书人口吻）现在是默认预设
  里一条可以自由编辑的 prompt 片段**，想要换成别的文风，直接在预设面板里改
  这条内容即可，不需要改代码
- JSON 结构规范、MVU 语法说明这些引擎正常运作必需的技术性规则，不放进预设里，
  避免被意外删改导致解析链路崩溃
- 「预设」标签页里保留的是 Temperature/最大输出Token 这类和当前预设绑定的
  参数，以及 prompt 条目的详细编辑区；酒馆里那一整套采样参数（Top P/Top K/
  Mirostat/DRY 等）大多是本地部署推理后端专属的特性，Anthropic/OpenAI兼容/
  Gemini 这三种云端 API 基本不支持，所以没有照搬，避免做一堆填了也不起作用
  的假选项

换成了立绘展示区（`src/portraits.js` + `src/PortraitManager.jsx`）：

- 展示区上方是候选角色标签（旁白、你、当前房间里的 NPC），点击切换查看
- 默认会根据当前交互模式自动推断该显示谁（私聊模式→旁白，对话模式且只有

- 点击"⚙ 管理"打开立绘管理弹窗，可以给任意角色（包括还没正式列出的新角色，

## 装备与拾取系统

装备栏改成了三大分类（武器/护甲/饰品）+ 不限数量存放，每类物品可以拥有任意多件，
但同一时间只有被标记"已装备"的那些才真正生效，其余是背包里的存货。点击右侧面板
装备栏里的物品即可切换装备/卸下状态。

**品质与气运的关系**：物品分为白/绿/蓝/紫/橙/红六档，抽取概率由七维属性"气运"
（0-10）驱动，用线性插值实现：

- 气运 0（基础分布）：白50% 绿30% 蓝10% 紫8% 橙1.5% 红0.5%
- 气运 10（顶峰分布）：白0% 绿20% 蓝20% 紫20% 橙20% 红20%（白色完全不再出现）
- 中间值按 `t = 气运/10` 线性混合两条分布，任意气运下六档概率合计恒为100%

**路上拾取**：每次移动有 35% 基础概率触发拾取判定，品质由上述概率表在前端摇骰子
决定（不受 AI 影响），系统把判定结果作为既定事实注入 prompt，AI 只负责编排一个
符合当前场景、契合判定品质的物品名字和描述——这是"AI 提议+系统裁决"原则的直接体现：
掉率和运气机制是硬编码的确定性系统，AI 不能通过话术绕过它多给自己发高品质道具。

**物品互动**：鼓励直接用自然语言尝试"用某物开锁""把某物送给/交给某人"这类互动，
AI 会根据 scenario 和物品描述合理处理结果，不需要专门的互动菜单。

**品阶数值曲线**（`src/equipment.js`）：六档品质之间是指数增长关系，
`ratio = 20^(1/5) ≈ 1.8206`，白到红全程相差恰好 20 倍。武器基准攻击力 6、
护甲基准防御力 3、饰品基准加成 0.3，套用同一条曲线算出每个品阶的实际数值——
这个计算完全由 `makeItem()` 内部的 `statsForQuality()` 完成，AI 在 `items_add`
里只能指定 `name`/`category`/`quality`，不能自己编攻防数值，从根源上保证
"AI 提议+系统裁决"：AI 决定这是什么、叫什么名字，系统决定它到底多强。
耐久度是固定的品质标签，不会因战斗损耗。详细设计参考项目里的
《装备品阶系统设计文档》。

右侧「侠客」面板的状态区块会显示当前"装备总加成"（已装备武器的攻击力总和、
护甲的防御力总和、饰品的加成总和），点击背包或装备栏里的物品可以查看 AI
生成的介绍，介绍会结合物品真实的品质和数值来写，不是凭空瞎编。

## 角色数据结构

右侧「侠客」面板不再是消耗性的生存数值（食物/饮水/精神/精力已移除），改为更贴近
养成向 RPG 的结构：

- **状态**：气血（会因战斗等因素变化）、内力
- **内功 / 外功**：0-100 的养成数值，直接决定战斗伤害倍率（见下面"切磋与战斗系统"），
  只能靠玩家自己花"潜能"主动修炼提升，AI 不再能直接改这两个数值
- **七维**（仿传统武侠天赋属性，类似 S.P.E.C.I.A.L 的武侠版）：根骨、悟性、体魄、
  魅力、智谋、身法、气运，0-10 的天赋值，只有重大奇遇/顿悟场景才会变动

**武学和包袱物品可以点击查看介绍**——玩家端详自己背包/武学时走主叙事口吻叙述，算 1 回合时间并写一张公共小纸条（不吃缓存）；商店预览物品则仍是瞬时缓存、不耗回合。此处临场
调用一次 AI，生成一段符合世界观的说书人式描述（来历、外观、效用），纯粹是查阅性质。
武学列表里，点名字看介绍，点前面的圈（▶/○）切换当前运功的武学。

## 切磋与战斗系统

**发起流程**：点击 NPC →「切磋」，不会立刻弹出战斗界面——先由 AI 描述一段抱拳邀战、
对方如何应招的过渡场景，跑完之后会出现一条"确认切磋 / 算了"的确认条，点确认才真正
进入 `DuelScreen` 回合制界面，点"算了"就此作罢。中间这一步反悔的余地是有意留的，
不希望敬个礼战斗界面就毫无征兆地砸到眼前。

**伤害公式**（`src/combat/resolveTurn.js`）：

```
伤害 = (基础攻击力 + 装备攻击力) × 招式倍率 × 外功系数 × 内功系数 × 力量系数
```

- 基础攻击力：玩家固定 20；NPC 按品质档位（见下）指数增长
- 装备攻击力：已装备武器的攻击力总和（`equipment.js` 的 `computeEquippedStats`），
  这是第一次真正接入战斗结算——之前只在侧栏"装备总加成"里显示，是纯摆设
- 外功系数：`1 + 外功/125`，外功 100 时约 1.8 倍
- 内功系数：`1 + 内功/200`，内功 100 时约 1.5 倍（内功的主要作用仍是气血/防御相关，
  这里是它对伤害的次要加成）
- 力量系数：`0.8 + 体魄×0.04`，沿用原有体魄公式，0.8-1.2 倍

**品质档位战力**（`src/npcGeneration.js` 的 `getTierPower`）：NPC 按白/绿/蓝/紫/橙/红
六档分配基础攻击力和气血上限，每上一档综合战力（攻击×气血）约变成上一档的 20 倍——
这样"品质"这个名字才名副其实，红袍高手应该是完全打不过的另一个量级，不是"血厚一点"
而已。剧情具名 NPC（老猎户等）和 AI 现场生成的路人、每日游走的 NPC，统一走
`npcDescriptionMapping.js` 的关键词判档（"猎户/镖师"→绿袍，"高手/长老"→紫袍……），
不会出现"重要角色反而是白板"的情况。

**修炼系统**：工具栏「运气·内功+1」「拆招·外功+1」两个按钮，花"潜能"分别提升内功/外功，
每点消耗 = `4 + 当前值/10`（取整），越往后越贵。潜能来源：切磋获胜（+5）、完成护镖/悬赏
任务（+10）都是系统保底发放，AI 也可以在 `delta.pot` 里额外奖励，但**不能再直接修改
内功/外功数值本身**——这两个数现在是战斗公式里的真实倍率，必须由玩家自己的行动挣出来。

## 关于 MVU 角色好感度系统

普通游戏 NPC（不同于旁白）的好感度不是写死在代码里的固定名单，而是像 SillyTavern
的 MVU 变量框架一样，由 AI 在游戏过程中动态声明。原理：

1. AI 在每次回复的 JSON 之后，可以另起一段 `<mvu>...</mvu>` 块，写类似
   `_.set('角色.呼延雪.好感度', 12);` 这样的指令
2. 前端解析这些指令，但不会无条件执行——会先过一层系统裁决：
   - 路径必须以 `角色.` / `世界.` / `主角.` 开头，其他路径一律拒绝
   - 好感度类数值会被强制限制在 0-100 之间，单次增减不超过 ±15
3. 裁决通过的指令才会真正写入状态树，右侧面板的"人物关系"区块会自动
   展示所有已经被 AI 声明过的角色

这意味着**新角色不需要你改代码**——AI 在剧情里引入一个路人甲，只要用
`<mvu>` 声明一下，这个角色就会自动出现在人物关系面板里，好感度也会持久化保存。
当前 `presets/qucuo.js` 的 scenario 里预先写好了呼延雪、何雨谢、梅朵、才旦、
李若由五个角色的人设文本，AI 会在合适的时机引入他们并开始维护好感度，
但这五人的人设是"剧本文本层"的描述，不是写死的 JS 对象——这套系统本身可以
承载任意数量、任意名字的角色，不局限于这五个。

设置面板的"金手指"标签页可以直接查看和手动修改当前已登场角色的好感度数值。

## 关于旁白攻略系统

架构核心：**旁白只有一个，全知，好感度只调文风**，不是"叙事旁白"和"对话旁白"两个割裂的人格。

1. **全知**：旁白始终知道游戏里发生的一切——她既负责主引擎的叙事输出（房间、事件描述），
   也是"私聊旁白"通道里跟你直接对话的那个人。私聊内容会被记入和主引擎共享的对话历史
   （`convo`），所以她"记得"你们私聊聊过什么，也记得游戏里发生的所有互动，不会出现
   "问她刚认领的外号却一脸茫然"这种记忆割裂。
2. **好感度只调文风，不调知识范围**：好感度低时，无论是叙事描述还是直接对话，都严格走
   公式化的说书人腔调；好感度越高，连日常的房间/事件描述里都会渗透她自己的情绪和主观色彩，
   直接对话时也会从生硬逐渐变得愿意闲聊、暧昧。
3. **私聊模式**（点「◆ 私聊旁白」切换）：把同一个旁白单独抽出来对话，不消耗回合，且和
   对话模式一样支持并行发送多条。
4. **好感度 0-100**：从生硬拒答，逐渐变得愿意闲聊、暧昧，直到触发"向旁白告白"。
5. **告白后**：进入"金手指期"，旁白会开始给出剧情提示（但故意设计成渐进、不完整），
   同时开始悄悄累积"记忆碎片"。
6. **记忆碎片攒够 8 个后**：触发宕机，旁白的真实身份（反抗军领袖）被揭示，
   私聊旁白从此只会返回冷冰冰的固定短句（不再调用 API，本地直接返回）。
7. 红蓝药丸的最终结局分支，本项目暂未实现（属于主线到达终局后才触发的内容，
   当前版本先跑通"旁白攻略"这条支线本身）。

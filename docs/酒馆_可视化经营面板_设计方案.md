# 酒馆 · 可视化经营面板 设计方案

> 状态：**设计稿，未落地**。逐条核对过现行代码接口（行号随 commit 漂移，以函数名为准）。
> 参考：[Star-Office-UI](https://github.com/ringhyacinth/Star-Office-UI) —— 像素办公室看板。
> 需求：空间化酒馆面板；每日随机刷新可招募队友与五种活计（押镖/劫镖/找打手/取货/宝藏）；卖酒水食物干粮；住宿；可盘下经营（厨子/扫地/会计/掌柜、给客人做饭）。

---

## 〇、从 Star-Office-UI 拆出来的内核

它的本体不是"像素画"，是三件事：

1. **状态空间化** —— 抽象状态（idle/writing/error）映射成办公室里一个**区域坐标**（`asset-positions.json` 就是一张"名字→x,y"的表），角色补间动画走过去。
2. **实体自主行为** —— 角色按状态机周期性换位置、冒气泡，看板不用点任何东西就能"看"。
3. **场景为主、管理为侧** —— 主视野是场景，配置收进侧边抽屉。

**借**：状态→区域映射表、气泡、周期性漫游、点人出详情卡。
**不借**：Phaser（本项目依赖只有 react/react-dom，为一个面板引游戏引擎不划算；用**绝对定位 div + `transition: left/top`** 等价实现"走动"）；它的美术资产（禁止商用，且我们是武侠风）。

## 二、酒馆定位与挂载

新建筑类型 `TAVERN`，**不动任何现有 INN/RESTAURANT**（歇马居、老孙饭馆照旧）。首批两间：

| 据点 | 酒馆 | 定位 |
|---|---|---|
| 鱼定村 | 「醉三江」 | 起始村枢纽，功能全量但规模小（可盘下，便宜） |
| 锦官城 | 「龙门客栈」 | 大城大店，客源旺（盘下贵，收益高） |

`qucuoBuildings.js` 里 `BUILDING_TYPE` 加 `TAVERN: "tavern"`、label「酒馆」、往两个据点的数组各插一条（带 `innPrice`、`menuKey`、`tavernId`）。**左栏入口零改动**——LeftPanel 是遍历 `getBuildingsForLocation` 渲染的，插完条目自动出现。

## 三、可视化大堂（Star-Office 的等价物）

### 3.1 场景结构

一个 16:9 逻辑画布（`aspect-ratio: 16/9`，内部全部百分比坐标），俯视酒馆：

```
┌────────────────────────────────────────────────┐
│ [柜台 counter]   [酒架 wine]   [账房 ledger] [任务板 board] │ 后墙
│  掌柜·住宿交单     买酒          会计·账本     五张单子      │
│                                                                │
│   [堂中桌位 hall ×3 桌]                    [灶台 stove]       │
│    客人喝酒·侠客独坐角落(招)                 厨子颠勺·蒸汽      │
│                                                                │
│ [天井门口 yard]              [客房入口 rooms]                  │
│  扫地·过客进出                 布帘·住店客人                  │
└────────────────────────────────────────────────┘
```

八区域坐标表 `TAVERN_ZONES`（直接对应 Star-Office 的 `asset-positions.json` 思路）：

```js
// src/tavern/tavernData.js
export const TAVERN_ZONES = {
  counter: { x: 4,  y: 6,  w: 20, h: 18, label: "柜台" },
  wine:    { x: 28, y: 6,  w: 16, h: 18, label: "酒架" },
  ledger:  { x: 48, y: 6,  w: 16, h: 18, label: "账房" },
  board:   { x: 76, y: 4,  w: 20, h: 24, label: "任务板" },
  hall:    { x: 6,  y: 34, w: 56, h: 40, label: "堂中桌位", seats: [[10,40],[26,52],[42,44],[14,62],[34,66],[50,58]] },
  stove:   { x: 68, y: 36, w: 26, h: 26, label: "灶台" },
  yard:    { x: 2,  y: 80, w: 38, h: 16, label: "天井门口" },
  rooms:   { x: 58, y: 80, w: 38, h: 16, label: "客房入口" },
};
```

### 3.2 实体模型：state → 区域

每个角色是一份 `{ id, name, glyph, state, bubble, onClick }`，渲染层**只按 state 查坐标**——这就是 Star-Office "状态决定站在哪"的翻译：

| 实体 | state | 区域 | 气泡 |
|---|---|---|---|
| 掌柜（雇的或店家的） | `greeting` | counter | "客官打尖还是住店？" |
| 客人 ×N | `drinking` | hall 某 seat | "三碗不过岗！" / 传闻一句 |
| 客人 | `resting` | rooms | "zzZ" |
| 游方侠客（可招募） | `recruitable` | hall 角落专座 | 「招」旗 + 身价 |
| 厨子 | `cooking` | stove | "火候正旺！" |
| 扫地 | `sweeping` | yard ↔ hall 漫游 | 扫帚 |
| 会计 | `reckoning` | ledger | "今日进账…" |
| 过客 | `passing` | yard | 停留片刻离场 |

**实体列表是纯函数产出**：

```js
// src/tavern/tavernSceneModel.js
buildSceneEntities({ daily, tavernState, time, isNight }) => Entity[]
```

- `daily`（当日种子刷新）给：侠客、客人名单、任务板单子数
- `tavernState`（经营存档）给：店员四格、是否在营业
- 客人数量 = 经营中按当日客流，非经营也有 2~4 个散客（种子），空酒馆不像酒馆

### 3.3 动效（全 CSS，无 JS 逐帧）

- **走动**：实体 state 变 → 目标坐标变 → `transition: left 1.4s ease, top 1.4s ease`。扫地/跑堂每 20~40s 在区域间随机换一次（一个 `setInterval` 驱动 state 轮转，实体 ≤12 个，无性能压力）。
- **气泡**：默认收成小圆点，hover/点击展开；客人周期性换一句堂吃语料（语料表手写 ~20 条，含 2~3 条**真传闻**，点一下可接进茶馆情报系统）。
- **氛围**：灯笼 `animation` 明灭；灶台蒸汽三个上升渐隐圆点；角色 `translateY` 呼吸浮动；按 `time` 罩夜/昼滤镜（复用 theme.js 的昼夜判断）。
- **像素感**：`image-rendering: pixelated` + CSS 色块小人/emoji glyph + 水墨边框（zoneTheme）。后续想升级真 spritesheet 也只换渲染层，模型不动。

### 3.4 交互

- **点区域** → 下方滑出该区域功能抽屉（柜台=住宿+支取，酒架=酒水单，灶台=菜单+开火，账房=账本，任务板=单子列表，客房=住宿）。
- **点「招」旗侠客** → 招募卡（七维/身价/来路一句）。
- **点单子** → 接单确认。
- 面板形态与现有建筑完全一致：inline 独占中栏、可最小化（`buildingPanelMinimized` 管线不动）。

## 四、数据模型

### 4.1 存档部分 `tavernState`（挂存档顶层，与 companionState 平级）

只存**跨天必须记住**的。每日刷新内容**一律不存**，种子现算（防 S/L 刷，也跟商店"当日货单固定"同一哲学）。

```js
// src/tavern/tavernState.js
export function initTavernState() {
  return {
    owned: {},        // { [tavernId]: { boughtAtDay, price } }
    funds: {},        // { [tavernId]: 公账余额 } —— 与 char.money 私银分账
    staff: {},        // { [tavernId]: { cook|null, sweeper|null, accountant|null, manager|null } }
                    //   每格 { name, skill(1-10), wage(日薪), hiredAtDay, glyph }
    reputation: {},   // { [tavernId]: 0..100 }
    pantry: {},       // { [tavernId]: { wine, food, ration } } 库存，进货补充
    ledger: {},       // { [tavernId]: [{ day, guests, revenue, wages, net }] 最近30条 }
    lastSettleDay: {},// { [tavernId]: n } 防重复日结
  };
}
```

> **为什么公私分账**：玩家买酒住宿是私银付给店里（进公账），工资/进货从公账出；混一本账会出现"自己给自己开工资"。柜台提供"存入/支取"互转。

存档接入：`saves.js` `buildSnapshot`（:110）参数表加 `tavernState`；MudRPG 里 `useState(restored?.snap.tavernState || initTavernState())`——老存档无此字段自动兜底，与 companionState 同一先例。

### 4.2 每日刷新（种子确定性，复用现成 utils）

`src/utils/seededRandom.js` 已有 `seededRand(dayIdx, locationName)` + `weightedSample`，`dayIdx = Math.floor(time/24)`。**直接用，不写第三份随机**：

```js
// src/tavern/tavernDaily.js
export function getDailyTavern(tavernId, dayIdx, reputation = 0) {
  const rng = seededRand(dayIdx, `tavern_${tavernId}`);
  return {
    recruits:  rollRecruits(rng, reputation),   // 1~3 名游方侠客
    jobs:      rollJobs(rng, tavernId, dayIdx), // 3~5 张单子（五类加权）
    guests:    rollGuests(rng),                 // 散客名单+堂吃语料
    staffPool: rollStaffPool(rng),              // 今日伙计候选（四类各 0~1）
    special:   rollSpecial(rng),                // 今日特价菜（半价）
  };
}
```

同日同馆反复进出结果一致；跨天自动换。已招募侠客/已接单子从当日视图剔除（查 flag/questProgress，不动种子）。

## 五、六大子系统

### 5.1 游方侠客（招募队友）

- 人设模板池手写 15 个（刀客/镖师/猎户/逃兵/游僧…），每条含 `namePool/title/levelCap 区间/身价公式/一句来路`。
- 种子实例化：档次按声望浮动（声望 0 → 白绿为主；≥60 蓝档偶发）。身价 = `levelCap² × 30 + 档次差价`（白 30 两上下，蓝 ~270 两，可调）。
- 招募落地走 **companion.js 现成的导入槽**：
  ```js
  setCompanionState(cs => unlockImportedCompanion(cs, {
    name, levelCap, special, brief: `醉三江偶遇的${title}`,
  }));
  ```
  `createImportedCompanion` 内部已接 `generateNpcAttributes → getTierPower → 招式表`，数值走统一战力曲线、一次生成永久固化（出生固化哲学），出战走现有 2v2 TeamDuel 管线——**战斗引擎零改动**。
- 招完写 flag `tavern_recruited_{tavernId}_{day}_{slot}`，该侠客在场景里"起身离席"（state→passing 走出门口），当日视图剔除。

### 5.2 任务板（五种活计）

走 Bounty/Escort 的"接 → 做 → 回店交单"轻量模式（`questProgress[id] = { active:true, count:0 }` + 完成写 `quest_done_{id}`）。id 形如 `tv_{tavernId}_{day}_{slot}`，天然按天隔离。五类完成判定**全部复用现有管线**：

| 活计 | 完成判定落点 | 备注 |
|---|---|---|
| 押镖 | 抵目标据点 + 找 targetNpc 交货（同 EscortScreen 的 `{targetNpc,targetLocation,reward}` 形状） | 报酬 40~120，据点距离加权 |
| 劫镖（黑单） | 指定外层路段触发遭遇战（`encounter.js`），DuelScreen 胜利写 flag（Bounty 同款） | 报酬 ×2，**karma −8**，与官府悬赏线互相成就张力 |
| 找打手 | questProgress 计数：赢 N 场切磋（Bounty `requiredCount` 模式） | "讨债/护场"风味 |
| 取货 | 到指定据点拿一件物品进 inv，回柜台交单时查 inv 扣件 | 清单从 items catalog 抽常见物 |
| 宝藏 | 唯一多阶段：残片 → 按图索骥（指定内层房间）→ 掘宝，走 `advanceQuestStages` | 奖励档位种子定：银两/装备/秘籍/空（空也给一句叙事，契诃夫之枪） |

报酬公式：`base × (1 + 声望×0.005) × 档次系数`。交单统一在**柜台**，形成"出门干活 → 回店交单"闭环。

### 5.3 酒水 / 食物 / 干粮

- 酒架、灶台菜单进 `SERVICE_MENUS` 新键（`醉三江` / `龙门客栈`），点单**原样走 `handleServiceOrder`**（扣钱 → `makeBuffFlag` → `act(settle)`），与饭馆酒楼同一 buff 机制。
- **干粮物品化**：`items/` catalog 加「干粮包」「肉干」条目（低价、可叠、路上"吃干粮"小回血不推时间）——buff 是"在店里吃"，干粮是"带走路上吃"，两者不混。
- 今日特价：种子抽一道半价（场景里酒架气泡提示）。

### 5.4 住宿

building 条目自带 `innPrice`，柜台/客房入口点"住店"**直接调 `handleBuildingInn`**（扣银、气血回满、时间 +23 + act +1 = 睡一天）。东家福利：住自己店免单（走句 settle 叙事即可）。

### 5.5 经营（招工 / 做饭 / 日结）

**盘下**：一次性价（醉三江 800 两，龙门 2500 两），写 `owned`。未盘下时全部消费功能照用，只是没有账房与招工。

**招工四格**（候选每日种子刷新，账房面谈入职）：

| 伙计 | 场景位 | 作用 |
|---|---|---|
| 厨子 cook | stove | 解锁"给客人做饭"：上菜率 = skill×10%（无厨子客人只喝酒，营收 ×0.5） |
| 扫地 sweeper | yard↔hall | 环境分：客流 ×(1 + skill×0.02) |
| 会计 accountant | ledger | 无会计时流水有 10%~30% "对不上账"损耗；有则账本可视（30 条流水） |
| 掌柜 manager | counter | 接待率：营收 ×(1 + skill×0.03)；**有掌柜才能甩手经营**（玩家离开据点也日结，否则打烊） |

**每日结算**挂在现成跨天侦测（MudRPG.jsx:811 `prevDayRef` useEffect）里追加一个调用，纯函数可测：

```js
// src/tavern/tavernState.js
settleTavernDay(state, tavernId, dayIdx) => { state, report }
// 客流 = 据点基数(鱼定村12/锦官城30) × 环境系数 × 口碑系数(0.6+声望/125)
// 营收 = 客流 × 人均消费(8~15 种子浮动) × 上菜率 × 掌柜系数 − 损耗(无会计)
// 公账 += 营收 − 四格日薪；声望 += f(上菜率, 环境)；写 ledger 一条
```

次日进店时账房气泡弹"夜报"（昨日客流/营收/净额）。**做饭**在灶台抽屉：选菜谱（复用 homestead.js `RECIPES`）消耗 pantry 食材，提升当日上菜率与口碑。

### 5.6 与 AI 叙事的接线

一切数值系统裁决，结算后 `act("一句自然语言", [], { settle: true })` 让主叙事演出来（同 handleBuildingInn 注释的那套哲学，不另开 harness）。传闻气泡里藏 2~3 条真情报，可作为绿灯关键词喂 `worldbook.js`——P2 再做。

## 七、分期落地

- **P0（一晚，先能用）**：TAVERN 挂载 + 菜单/住宿复用 + 任务板（押镖/取货/打手）+ 侠客招募（列表式 UI，先不做场景）。
- **P1（可视化）**：`TavernScreen` 大堂场景：区域坐标 + 实体走动 + 气泡 + 区域抽屉；任务板补劫镖/宝藏。
- **P2（经营）**：盘下 + 四伙计 + 日结 + 账本 + 做饭；食客上座动画。
- **P3（打磨）**：声望驱动外观升级、传闻绿灯注入、多据点扩张、掌柜离线收益细化。

## 八、风险与取舍

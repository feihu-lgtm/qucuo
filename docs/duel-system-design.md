# 曲措乡·切磋系统设计文档

## 一、核心博弈：三角克制

技能分三类，克制关系是闭环三角，不看数值，纯类型互克：

```
攻击 → 克 → 状态 → 克 → 防御 → 克 → 攻击
```

**判定逻辑（严格按下面这四条走，不需要额外条件分支）：**

| 我方 | 对方 | 结果 |
|---|---|---|
| 攻击 | 防御 | 对方防御生效，大幅减伤（防御方"赢"这一回合） |
| 攻击 | 状态 | 状态被打断，完全打不出来（攻击方"赢"这一回合） |
| 防御 | 状态 | 状态命中防御方，防御无法阻挡状态效果（状态方"赢"这一回合） |
| 攻击 vs 攻击 / 防御 vs 防御 / 状态 vs 状态 | 同类型对撞，比速度值，速度高者先手，伤害按正常克制表结算 |

这个闭环的直觉：**攻击是硬碰硬，能打穿正在"起手"的状态类招式；防御是扎稳马步，能扛住直给的攻击；状态是绕后偷袭，防御方顾着挡正面攻击，反而防不住状态类的迂回效果**。三者环环相扣，没有一种类型能"永远不败"。

## 二、能量系统

- 每人战斗开始时能量 **10点**，上限10
- 技能都标注能量消耗，能量不够则该技能不可选
- 基础技能"回气"：消耗0能量，**回复4点能量**，是能量枯竭时的保底选项，但这一回合不产生任何攻防状态效果，等于让出这一整个回合
- 应对判定失败的高阶技能，通常有能量惩罚（扣除而非仅仅是"没有加成"），呼应洛克王国"听桥"失败要倒扣能量的设计——高风险技能必须有真正的代价，否则玩家/AI会无脑一直用

## 三、品质分级：六级，跟装备系统同一套 `QUALITY` 常量

**白 → 绿 → 蓝 → 紫 → 橙 → 红**

同一个技能位在不同品质下，效果按下表递增，不是简单的数值线性膨胀，而是**低品质给基础三选一，高品质开始出现"应对"衍生效果**：

| 品质 | 攻击类范例 | 防御类范例 | 状态类范例 |
|---|---|---|---|
| 白 | 直拳：造成基础伤害，消耗2能量 | 硬架：防御时伤害×0.6，消耗2能量 | 回气：回复4能量，消耗0能量 |
| 绿 | 连环腿：基础伤害×1.15，消耗3能量 | 铁布衫：防御时伤害×0.5，消耗3能量 | 蓄力：下回合攻击伤害+20%，消耗3能量 |
| 蓝 | 破空拳：基础伤害×1.3，若命中状态类附加流血，消耗4能量 | 磐石桩：防御时伤害×0.4，应对成功额外回2能量，消耗4能量 | 惑心步：50%几率让对方本回合技能类型判定错乱，消耗5能量 |
| 紫 | 裂石斩：基础伤害×1.5，若应对到状态类，伤害翻倍，消耗5能量 | 听风势：防御时伤害×0.3，应对到攻击类时，反手打出对方本次技能70%伤害，消耗6能量；应对失败扣3能量 | 夺魂手：状态命中防御方时，额外造成本回合双方能量差值的伤害，消耗6能量 |
| 橙 | 惊雷破：基础伤害×1.8，无视对方防御减伤效果，消耗7能量 | 归元诀：防御时伤害×0.2，应对到攻击类时100%触发反伤，反伤=对方技能伤害×1.2，消耗8能量；应对失败扣4能量 | 摄魂引：状态命中防御方时，直接冻结对方1回合能量恢复，消耗8能量 |
| **红** | **一剑西来**：必定先手（无视速度比较），基础伤害×2.2，若命中状态类，直接藐视一击（本回合对方技能完全无效化），消耗9能量 | **听桥**：防御时伤害×0.05（近乎全免），应对攻击类成功时，主动出击打出对方本次技能100%伤害并抢先结算（可能直接秒杀），消耗9能量；**应对失败扣5能量+本回合防御完全失效** | **天惊诀**：状态命中防御方时，二倍反伤（把防御方原本想用防御扛住的那部分伤害，翻倍弹回给对方），消耗9能量 |

红色技能"听桥"直接对应你要的效果，也是洛克王国原版机制的复刻——"防御95%+反制成功后获得能量"这个描述你提的方向完全对，我按官方"减伤高达80%"往上提到了95%（红色顶级品质应该比蓝本更夸张一点，制造"传说级技能"的分量感），反制倍率定为100%（对方这一下打多重，原样弹回去）而不是无限翻倍，避免出现一击秒杀链条式崩坏。

## 四、AI性格决策层

不是每回合都调用LLM去现算招式——那样又慢又不稳定。正确做法是**分两层频率**：

**低频（角色定型时，调用一次LLM）**：根据NPC的性格Tag，生成一套"三类技能选择权重"+"是否倾向于赌高风险应对技"的参数，存下来，之后不再变。

```javascript
// src/combat/personalityProfile.js
// 由 LLM 根据角色小传一次性生成，存入角色数据，之后每回合都是本地读取，不再调用 LLM
{
  "老猎户": {
    moveWeights: { 攻击: 0.5, 防御: 0.35, 状态: 0.15 }, // 猎人性格直接，少用心机状态类
    riskAppetite: 0.2,  // 0-1，越高越倾向用高品质高风险技能赌一把
    avoidRepeat: 0.6,   // 0-1，越高越不容易连续两回合用同一类型（对应"防御不能连续用"的平衡直觉）
  },
  "呼延显式的狡诈角色": {
    moveWeights: { 攻击: 0.25, 防御: 0.25, 状态: 0.5 },
    riskAppetite: 0.7,
    avoidRepeat: 0.3,
  }
}
```

**零频（真正打起来时，纯本地计算，不调用任何API）**：

```javascript
// src/combat/aiDecision.js
function decideNpcMove(profile, battleState) {
  let weights = { ...profile.moveWeights };

  // 平衡阀：如果上一回合用过某类型，按 avoidRepeat 权重打折，
  // 避免AI（尤其是低性格随机性的NPC）陷入"一直防御"的呆板循环
  const lastMove = battleState.npcHistory.at(-1);
  if (lastMove) {
    weights[lastMove] *= (1 - profile.avoidRepeat);
  }

  // 残血/能量不足时的兜底：能量不够支撑高品质技能，自动降级到白色技能池
  const affordableQuality = getAffordableQuality(battleState.npcEnergy);

  const moveType = weightedRandomPick(weights); // 本地加权随机，瞬间完成
  const quality = pickQualityByRiskAppetite(profile.riskAppetite, affordableQuality);

  return { type: moveType, quality };
}
```

**唯一真正实时调用LLM的地方**：回合结算完（谁用了什么、克制关系判定完、伤害算完）之后，把这个**纯数值结果**交给LLM，让它包装成符合角色性格的说书人文字描述。这个走你已有的字数分类体系里 `COMBAT` 那一档（400-900字），不产生额外的战斗逻辑延迟——文字生成和战斗结算是完全解耦的两件事，结算瞬间出结果，文字描述可以异步跟上。

## 五、招式池与随等级解锁

不建议一上来给NPC和玩家全品质技能池，按你现有装备强化的思路对齐：

- 战斗系统初期只解锁白/绿两级的基础三选一（直拳/硬架/回气 这类）
- 蓝色及以上技能作为**武学修炼的产出**接入你现有的 `skills` 升级系统——玩家武学等级到达某个阈值，或者特定剧情节点，解锁对应品质的切磋技能，而不是一开始就全部可选
- 红色技能（听桥/一剑西来/天惊诀 这类）建议跟你现有的"里程碑事件"绑定，作为某条剧情线或某个师徒关系的特殊奖励解锁，而不是练到了自然长出来——这样"听桥"第一次能用出来的时候，是有叙事分量的，不只是一个数值刷出来的技能

## 六、数据结构草案

```javascript
// src/combat/moveTypes.js
export const MOVE_TYPE = { ATTACK: "攻击", DEFENSE: "防御", STATUS: "状态" };

export const BEATS = {
  [MOVE_TYPE.ATTACK]: MOVE_TYPE.STATUS,
  [MOVE_TYPE.STATUS]: MOVE_TYPE.DEFENSE,
  [MOVE_TYPE.DEFENSE]: MOVE_TYPE.ATTACK,
};

// 一个技能的完整结构
{
  id: "moves_ting_qiao",
  name: "听桥",
  type: MOVE_TYPE.DEFENSE,
  quality: "红",
  energyCost: 9,
  effects: {
    baseDamageMultiplier: 0.05,      // 未触发应对时，仍有的基础减伤
    onCounterSuccess: {              // 应对到"攻击类"成功时触发
      counterDamageRatio: 1.0,       // 反打伤害 = 对方本次技能伤害 × 1.0
      preemptive: true,              // 抢在对方伤害结算前打出
    },
    onCounterFail: {
      energyPenalty: 5,
      defenseNullified: true,        // 本回合防御完全失效
    },
  },
}
```

## 七、回合结算流程

```
1. 双方各自选定这回合的招式（玩家手动选，NPC按 aiDecision.js 本地权重选）
2. 系统裁决层判定类型克制关系（不调用AI）：
   - 异类型 → 直接按三角表出结果
   - 同类型 → 比速度值，速度高者先手，按品质数值算伤害
3. 结算能量增减、伤害、特殊效果（藐视一击/反伤/冻结等）
4. 把这一回合的结构化结果（谁用了什么、判定结果、伤害数字）交给LLM，
   生成符合双方性格的文字描述（走 COMBAT 篇幅档）
5. 检查胜负条件（一方气血归零/认输/达到回合上限）
```

这个流程的核心原则：**"谁赢这一回合"是纯数值系统裁决，AI不参与判定，只负责把已经算好的结果讲成故事**——跟你现有的"移动方向由固定地图裁决、AI只负责描述细节"是同一个设计哲学，保证战斗公平且可预测，不会出现AI瞎编谁赢了的情况。

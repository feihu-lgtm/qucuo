# 曲措乡·武器/装备/饰品系统说明（连接方式 + 设计原则 + 词条分配）

> 本文档讲清楚三件事：
> 一、物品现在**怎么跟游戏连起来的**（从 AI 发放到落进战斗的完整链路）
> 二、词条**怎么设计的**（数据结构、攻防倍率、特效、六维）
> 三、数值/特效**按什么原则分配**（品阶梯度、哪类挂什么）
>
> 全部以代码为准，非设计稿理想值。关键文件：
> `src/items/catalog.js`（物品库）、`src/equipment.js`（公式/聚合）、
> `src/combat/resolveTurn.js`（战斗结算）、`src/DuelScreen.jsx`（战斗接线）、
> `src/npcGeneration.js`（NPC携带）、`src/MudRPG.jsx`（AI发放/prompt注入）

---

## 〇、一句话概览

物品分**两个层次**：
- **具名物**（catalog 里 named，共110件）：有名有姓、带来历，吃自己的**专属数值**。
- **匿名/公式物**（equipment.js 公式生成）：AI 临时命名的普通货，走"同品质同数值"。

具名物又分三档：百物录80（`WEAPONS/ARMORS/ACCESSORIES/SUNDRIES`）、
制式通货30（`STANDARD_*`）、西南武林库30（`LEGENDARY`）。

**连接总闸**：`makeItemSmart(spec, fallback)` —— 名字命中 catalog 就吃具名数值，
否则回退公式。全项目物品生成都过这道闸。

## 一、怎么跟游戏连接的（完整链路）

### 1.1 物品从哪来 → 怎么变成具名物

四个来源，全部走 `makeGameItem`（= `makeItemSmart` 的项目内包装）：

```
① AI 发放/掉落 (MudRPG.jsx items_add, ~line 1918)
② 玩家购买     (MudRPG.jsx, ~line 2381)
③ 锻造         (MudRPG.jsx, ~line 2530)
④ NPC 携带     (npcGeneration.js carry, ~line 327)
        │
        ▼
   makeGameItem({ name, category, quality })
        │
   makeItemSmart(spec, makeItem)   ← src/items/catalog.js
        │
   ┌────┴─────────────────────────┐
   名字命中 catalog?               名字未命中
   │                              │
   makeCatalogItem(entry)         equipment.makeItem(spec)
   吃专属 atk/def/effect/sixDim    公式算 atk/def（同品质同数值）
   named:true / standardIssue:true 匿名普通货
```

**关键**：具名物的**品质以 catalog 为准**，不以调用方传入为准——"绿档霜牙"
不会被 AI 一句话说成红档。这是"AI 提议内容、系统裁决数值"原则的落地。

### 1.2 AI 怎么知道该发具名物

`MudRPG.jsx` 的 `buildSysBase` 在 system prompt 里注入了
`describeCatalogForAI()` 生成的"物件志"——**只给 AI 名字/品级/一句话来历，
不给数值**。AI 据此可以在叙事里自然引用（"墙上挂着一柄雪山松纹剑"），
发物品时按原名写进 items_add，但**不能篡改数值、不能杜撰上表没有的神兵**。
物件志分两栏：具名宝物（标"罕见，遇之郑重"）、制式通货（标"常见，可随口带出"），
让 AI 拿捏叙事语气。

### 1.3 装备怎么进战斗（核心接线）

玩家在背包里 `equipped:true` 的物品，进战斗时经过三步聚合：

```
computeEquippedStats(inv)   ← src/equipment.js
   │  遍历所有 equipped 的武器/护甲/饰品
   ├─ totalAtk   = Σ 武器.atk      （攻击加数）
   ├─ totalDef   = Σ 护甲.def      （防御加数）
   ├─ equipEffects = mergeItemEffects(全部)  （特效聚合，见1.4）
   └─ sixDimBonus  = Σ 各件.sixDim          （六维累加）
        │
        ▼ DuelScreen.jsx handleSelectMove
   ┌────────────────────────────────────────┐
   │ playerBaseAtk = atkFromWaigong(外功)     │  ← 外功梯子
   │ playerEffSpecial = effectiveSpecial(基础七维, inv)  ← 基础+装备六维
   │ playerMove = mergeMoveWithEquip(选的招, equipEffects) ← 特效叠进招式
   └────────────────────────────────────────┘
        │
        ▼ 组成 sideA 传入 resolveTurn(sideA, sideB)
   sideA = { move: 叠了装备特效的招, special: 有效七维,
             baseAtk, equipAtk: totalAtk, equipDef: totalDef, ... }
```

**伤害公式**（见 `docs/攻击力计算公式.md`）：
```
rawDmg = round( (baseAtk + equipAtk) × 招式倍率 × 体魄系数 )
```
所以武器的 atk 是**加数**，通过 equipAtk 进公式——这就是"攻防倍率跟着公式走"
的落地：倍率乘在品质基准上算出 atk，最终仍是加数，不新增乘法层。

NPC 侧同理：NPC 携带的 `equipped` 且带 effect 的 carriedItems，也会被
`mergeItemEffects` 聚合、叠进 NPC 的招式（DuelScreen sideB）。

### 1.4 特效怎么叠进招式（mergeMoveWithEquip）

原则：**招式自带的标志位优先，装备只补招式没有的字段**。
- 玩家主动选的招是"主"，装备被动增益是"辅"。
- 一件带"内伤印"的武器，配一个本身不叠印的攻击招 → 攻击招也能挂上内伤印。
- 配一个已自带更高层内伤印的招 → 以招式的为准（不覆盖、不数值叠加）。
- 这样避免"神兵+强招"双倍暴力。

多件装备的特效先经 `mergeItemEffects` 合并：数值型取更强一件、布尔型 true 覆盖、
对象型（applyMark/enemyCostPenalty）取 stacks/value 更大的一件——**防止堆装备
无限叠**。

### 1.5 六维怎么生效（effectiveSpecial）

```
effectiveSpecial(基础七维, inv) = 基础七维 + Σ 已装备件.sixDim
```
战斗组 side 时用它替代裸读 `char.special`。六维在战斗里各管：
体魄→攻击力量系数(0.8~1.2)、根骨→防御力量系数、身法→同类对撞先手、
气运→掉落品质、悟性/智谋/魅力→叙事与判定。装备六维**可突破10**
（修炼上限10是自身修为，装备是外物临时增益，两回事）。

## 二、词条怎么设计的（数据结构）

一个 catalog 条目的完整字段：

```js
{
  name: "霜牙",              // 主键，唯一，AI 按此名发放/引用
  category: "weapon",        // weapon | armor | accessory | misc
  quality: "绿",             // 白绿蓝紫橙红，设计死，不由 AI 改
  atkMul: 1.25,              // 攻击倍率（仅武器），乘在品质基准 atk 上
  defMul: 1.3,               // 防御倍率（仅护甲），乘在品质基准 def 上
  effect: { ... },           // 战斗特效（复用武学标志位，见三）
  sixDim: { 身法: 2 },       // 六维加成（装备时加、卸下移除）
  consumable: { ... },       // 消耗品即时效果（仅杂货，待食物系统接通）
  tags: ["药材","疗伤"],     // 用途标签（供商店铺货/AI引用，仅杂货）
  standardIssue: true,       // 制式通货标记（可选）
  desc: "……",               // 来历文字，给玩家和 AI 看
}
```

实例化后（`makeCatalogItem`）额外带：`id`、`equipped:false`、`named`、
`atk`/`def`（倍率折算后的实际值）、`buyPrice`/`sellPrice`、`durability`。

### 2.1 攻防倍率怎么折算成实际数值

```
武器 atk = round( 品质基准atk × atkMul )
护甲 def = round( 品质基准def × defMul )
```
品质基准（equipment.js）：
- 武器 atk：白7 绿12 蓝20 紫34 橙59 红100
- 护甲 def：白5 绿9 蓝15 紫26 橙46 红80

例：橙武器基准59，霜角 atkMul1.6 → atk = round(59×1.6) = 94。
价格同步按倍率抬：`buyPrice = round(品质基准价 × 倍率)`，卖价 = 买价一半。

**倍率范围 1.0~1.6 横跨六品阶**——同品质里越贵重/越点题的倍率越高，
但不离谱到破坏同档平衡。饰品无攻防基准（accessory 只有小 bonus），
不写倍率，价值全在 effect/sixDim。

## 三、特效词条：复用武学标志位

特效**不是新造的系统**，是直接复用 `combat/resolveTurn.js` 战斗结算里
**真正读取**的招式标志位——物品挂上这些字段，`mergeMoveWithEquip` 会把它们
叠到招式上，resolveTurn 照常结算。

### 3.1 生效的特效字段（resolveTurn 真读，可放心用）

| 字段 | 效果 | 归类 |
|---|---|---|
| `forceFirst` | 必定先手，无视身法 | 攻击向 |
| `ignoreDefense` | 无视对方防御减伤 | 攻击向 |
| `doubleVsStatus` | 克中状态招时伤害翻倍 | 攻击向 |
| `lowHpBonus: 系数` | 自身生命越低威力越高（每损10%血×系数） | 攻击向/残血 |
| `afterStatusBonus: 系数` | 上回合成功施加状态/印记后追击加成 | 攻击向 |
| `lowEnemyEnergyBonus: {threshold,multiplier}` | 对方能量≤阈值时伤害×倍数 | 攻击向 |
| `detonateMark: {perStackRatio}` | 引爆对方内伤印，按 baseAtk×比例×层数追伤 | 攻击向 |
| `applyMark: {name,stacks} + applyMarkChance` | 命中按概率给对方叠内伤印 | 控制向 |
| `enemyCostPenalty: {value,turns}` | 封穴：抬高对方后续若干回合耗气 | 控制向 |
| `freezeEnergyRecovery` | 封气：冻结对方下回合回气 | 控制向 |
| `onCounterSuccessDamageRatio: 比例` | 防御应对成功时反打对方伤害 | 防御向 |
| `onCounterSuccessEnergyGain: N` | 防御应对成功时回能量 | 防御向 |
| `hpRestore: 比例` | 起手回血（按最大气血比例） | 续航向 |
| `energyRestore: N` | 起手回能量 | 续航向 |
| `forceCrit: {multiplier}` | 必定暴击，按倍率放大伤害（虎啸） | 攻击向·神兵 |
| `justiceStrike` | 对方带"不义"标记时伤害翻倍（地藏，终局对抗土司府） | 攻击向·神兵 |
| `immuneControl` | 免疫控制/掉血/印记类状态施加（不动明王杵） | 防御向·神兵 |
| `rebirthOnce` | 每场战斗一次，气血归零时回复50%续命（涅槃引） | 续航向·神兵 |

### 3.2 ✅ 曾经的死字段已全部修活

以下字段曾"写进物品但 resolveTurn 不读"，现已补上消费分支，**全部生效**：
- `applyMarkOnHit`（欢喜法衣：挨打反叠印给攻击方）——已接入防御命中分支
- `ignoreDefensePartialImmune`（铁网衲/镇边重铠：对无视防御部分免疫）——已接入
- `justiceStrike` / `immuneControl` / `forceCrit` / `rebirthOnce`（五神兵特效）——已接入
- `applyMark`（内伤印施加，含现有橙红状态招）——`markApply` 曾定义未调用，已接入四个命中分支

**当前 catalog 里所有 effect 字段都有 resolveTurn/DuelScreen 的消费逻辑，无死字段。**
`beastFear`（虎啸降遇怪率）是战斗外效果，待接 encounter.js（随神兵支线落地）。

### 3.3 接线时顺带修复的历史坑

`markApply`（施加内伤印）这个函数原本**定义了却从没被调用**——不只物品，
连现有橙红状态招（摄魂引/天惊诀）写的 applyMark 也一直是死的。本轮接线时
把它接进了 resolveTurn 的四个命中分支（攻击克状态、状态克防御、双攻硬碰、
双状态），并加了 `applyMarkChance` 概率门控（物品的印记多带概率，招式自带的
默认必叠）。所以这轮**顺带救活了整个内伤印系统**。

## 四、数值/特效分配原则

### 4.1 品阶梯度：低档素、高档花

| 品阶 | 攻防倍率典型 | 特效 |
|---|---|---|
| 白 | 1.0~1.1 | 基本无（纯攻防） |
| 绿 | 1.15~1.25 | 偶有轻特效（残血/回血小加成） |
| 蓝 | 1.25~1.35 | 单个中特效 或 六维+1~2 |
| 紫 | 1.35~1.5 | 强特效 或 六维+2~3，可组合 |
| 橙 | 1.45~1.6 | 双特效组合（如必先+无视防御） |
| 红 | 1.6 | 最强特效组合 |

### 4.2 三类各有各的特效重心

- **武器**：输出向。forceFirst/ignoreDefense/doubleVsStatus/lowHpBonus/
  detonateMark/applyMark，抢的是"打得狠、打得准、破防"。
- **装备（护甲）**：防御/续航向，不跟武器抢输出。
  onCounterSuccessDamageRatio(挨打反击)/hpRestore(回血)/
  onCounterSuccessEnergyGain(接招回气)/enemyCostPenalty(近身乱敌)。
  少数玩反常识：越破越硬、越被打越回气、穿上像别人的味道。
- **饰品**：最放飞。不占攻防主战场，价值全在 sixDim（六维）+ effect。
  情感信物给气运/魅力这类"软"属性；邪门物件挂控制/封气；残念执念之物
  玩残血博弈；几件强特效配一点属性反噬（如百花引残香囊悟性-1），让玩家权衡。

### 4.3 具名 vs 制式 vs 匿名

| 层次 | 数量 | 特点 | 特效 |
|---|---|---|---|
| 具名·百物录 | 80 | 独一份、带私人故事、多与人物/剧情绑定 | 按品阶挂，橙紫红较猛 |
| 具名·西南武林库 | 30 | 更放飞的传世名器，橙紫居多 | 最猛，双特效组合多 |
| 制式通货 | 30 | 成批量产，流派/产地成套，铺满全梯度 | **只有紫橙红少量挂"轻"特效**，比具名温和 |
| 匿名·公式 | 无限 | AI 临时命名，同品质同数值 | 无特效 |

**制式特效比具名温和**：如雪山派传习剑给0.25反击（具名旧铜镜0.4）、
欢喜堂供役杖封穴1点1回合（具名青鸢2点2回合）。红档制式给足分量，其余克制。

### 4.4 情感信物类：叙事分量 > 战力

马鞭/剑穗/旧锁/拓片这类，攻防低甚至无攻防，六维和风味重——它们的价值
在故事和好感度联动，不在打架。梅朵的马鞭魅力+3、呼延雪的剑穗悟性+气运
各+1，够体现分量但不破坏平衡。

### 4.5 与剧情勾连的钩子（分配时有意埋的）

- 红档制式三件（镇仓槊/镇边重铠/御赐銮铃）全指向线三"六年前失踪的上司"。
- 欢喜堂制式全带"不用下药人自己就交出去"的邪劲，呼应罗琦线。
- 断念之锷续上缴获剑"断念"被磨平的下半句诗；霜角弓把虎王骨+狼王筋
  "两样本不该共存的东西"绷在一起。

## 六、给后续维护者的速查

- **加一件新具名物**：往 catalog.js 对应数组加一个条目，name 不能跟现有110件
  撞（撞了覆盖索引）。特效字段只能用 3.1 表里的（否则是死字段）。
- **改某件数值**：改 atkMul/defMul（倍率）或 effect/sixDim，不用动公式。
- **让 AI 能发某件**：加进 catalog 即可，describeCatalogForAI 自动带上，
  AI 就知道这件存在。
- **商店按地域铺货**：用 `filterCatalog({category, quality, tag, tier})`，
  tier 可选 "named"/"standard" 分层出货。
- **想加新特效类型**：先在 resolveTurn.js 补消费分支，再在物品里用——
  切忌只在物品里声明标志位却没代码消费（那就是死字段，本项目反复踩的坑）。

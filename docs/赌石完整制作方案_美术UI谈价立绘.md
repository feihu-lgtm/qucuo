## 一、和主设计文档的对齐关系（先说清楚，别重复造轮子）

主设计文档 `赌石_玉器与原石设计.md` §2.1 已经定死了石头的**数据模型**：
```
石头 = { 场口, 皮壳, 真实种水, 真实色, 料位:[格1,格2,格3], 皮壳线索:[松花,蟒带,癣,雾] }
```
- 每格独立标「有料/无料」及该处种水色；三刀 = 三格；出生即 seededRand 固化。
- 悟性影响皮壳线索噪声；智谋用于识破托儿/串通/假料。

**本文不动这个模型，只补它的美术呈现**，并明确两条美术侧的设计决定（作者已拍板）：

1. **雾不做 PNG 图层，只走 AI 叙事**。看皮阶段悟性检定成功时，AI 用文字提雾色（白雾=种老、黄雾=偏暗、无雾=种嫩），不叠图。雾属于「皮壳线索」文字层，归主文档 §2.3 管，美术侧不出素材。
2. **每格「两层都骰」**：一层是**品相**（纯/白/杂，决定这刀的肉值多少钱），一层是**裂缝**（好/裂，决定这刀有没有切坏）。二者独立骰，组合出「好料可惜裂了」这种层次感。这对应主文档 §2.1 里「有料/无料 + 种水色」的美术展开——品相是种水色的具体呈现，裂缝是「切坏」的独立叠加。

## 二、石头图层结构（三层 PNG + 局部小窗）

一块石头在画面上 = **外皮打底，开刀处开小窗露肉，裂缝按需叠加**：

```
③裂缝 crack   （最上，仅在该料位有裂时叠加，赌的核心）
②种水肉 jade  （切开才在小窗里露出局部，分 纯/白/杂 三品相）
①外皮 skin    （玩家开刀前只看得到它，决定石头外形）
```

**关键点：肉不做整块遮罩，只做「局部小窗」。**
玩家开一刀 → 在该料位切口位置开一个小窗口 → 窗里露出「这档种水的纯/白/杂肉图的**局部一小块**」。三刀 = 三个小窗。

这样做的三大好处：
- **素材省**：肉图 6 档 × 3 品相 = 18 张，不用做 6×6=36 张整块遮罩。
- **对齐问题消失**：小窗是个小方块，贴在切口坐标上，**不需要匹配整块石头外形**——所以外皮爱什么形状就什么形状（乌砂浑圆、老象皮扁块、蟒带异形都行），不必强求统一椭圆。
- **贴近真实**：现实开石也是切口那条缝里先见一点色，不是整块透明。

### 三层各自的作用与玩法映射
| 层 | 内容 | 玩法含义 | 变体数 |
|---|---|---|---|
| ①外皮 skin | 真实皮壳（黑乌砂/黄盐砂/白盐砂/老象皮/铁锈皮/松花蟒带） | 决定外形 + 看皮线索，受悟性影响真伪 | 6 种 |
| ②种水肉 jade | 6 档种水 × 纯/白/杂 三品相，切开在小窗露局部 | 品相定「这刀值多少钱」 | 6×3 = 18 张 |
| ③裂缝 crack | 三个料位上「有裂/无裂」，仅有裂时叠 | 定「这刀有没有切坏」，切坏打骨折 | 3 张（上/中/下） |

## 三、两层都骰：品相 × 裂缝（赌的核心）

每个料位（上/中/下）**独立骰两件事**：

| 骰的层 | 值域 | 定什么 | 结算 |
|---|---|---|---|
| 品相 grade | 纯 / 白 / 杂 | 这一刀切出的肉**值多少钱** | 价值 = 种水档 × 品相系数（纯高、白中、杂低） |
| 裂缝 crack | 好 / 裂 | 这一刀**有没有切坏** | 若裂 → 价值再乘裂损系数（如 ×0.4） |

**结算逻辑（系统裁决，AI 只演）：**
```
这刀价值 = 种水档基线 × 品相系数(纯/白/杂)
若该格 crack=裂 → 这刀价值 ×= 裂损系数
三刀合计 → 整块石头估值 → 涨 / 平 / 垮
```
「品相纯 + 但 crack=裂」= 好料可惜裂了；「品相杂 + crack=好」= 料一般但至少完整。层次感就来自这两层的交叉。

> 场口（主文档 §2.2）影响这两层的**概率权重**：雪山老坑偏向高品相少裂，鹰曲新场加大方差（大涨大垮）。权重表写进 `gambleStone.js`。

### 组合数
视觉组合 = 6 种水 × 6 外皮 × (3 品相 × 2 裂缝)³个料位 = 6 × 6 × 6³ = **46656 种**外观。
**但素材只需约 28 张**——全靠图层拼接 + 局部小窗。这就是「乐高拼装」省素材的精髓。

## 五、去 suchuang 跑图：四批九宫格规划

suchuang 一张图可出多格。**肉图与外皮用九宫格/多格分格跑**（每格是一张要独立成图的实体贴图，分格方便）；
**特效/覆盖层绝对不进格子**——它们要抠出来叠加，画进小框会带上框线，必须在整张透明大图上跑。

分四批（肉图两批 + 外皮一批 + 特效一批）：

- **第 1 批**：白/绿/蓝 三档种水 × 纯/白/杂 = 九宫格 3×3
- **第 2 批**：紫/橙/红 三档种水 × 纯/白/杂 = 九宫格 3×3
- **第 3 批**：6 外皮 = 六格 3×2（居中石头、四周透明）
- **第 4 批**：裂缝/刀光/石屑/料位框 = **不分格的透明大图**

### 四条踩过的坑（提示词必须带的修正）
1. **不同档颜色会串**：多档同批时 AI 会调和颜色。必须显式写「三档颜色一眼可分、互不串色」并各自钉死色相。
2. **低档种水会跑成鲜艳**：「淡豆绿」不够，要加「发闷、浑浊、不鲜艳」压制。
3. **纯/白/杂是行话，AI 不会画**：必须翻译成视觉特征——纯=大片干净通透+水润高光；白=蒙白棉雾；杂=黑褐脏斑+色不匀。
4. **肉图不能提「颗粒」**：会跑成星空磨砂。肉图用「水头通透、丝绺流动」；「颗粒/砂粒」只留给外皮批。

- 刀光：一道斜向白色光刃切割特效，明亮锐利带速度残影，纯透明底

> 记住区别：**要独立成图的实体素材（肉、皮）用分格**；**要抠出来叠加的透明覆盖层（裂/刀光/石屑）绝不进格子**。

### 参考图（img2img）要点
- 肉图：不用垫外形。要三品相一致，先跑每档「纯」，拿它垫同档「白/杂」（强度 0.4~0.5），只加雾/加脏、锁死底色。
- 外皮：先跑黑乌砂定基准外形，垫其余 5 张（强度 0.5~0.65）；外形允许各皮壳不同。
- 覆盖层：裂纹如需垫图借位置，用外皮、强度很低（0.25~0.35），生成后抠掉石头本体只留线条。

## 七、前端拼接实现（GambleStoneScreen 里）

```jsx
// 一块石头 = 外皮打底 + 每个已开料位在切口开小窗露肉 + 有裂则叠裂缝
<div style={{ position: "relative", width: 256, height: 256 }}>
  {/* ① 外皮：始终显示，决定外形 */}
  <img src={`stones/skin_${stone.skin}.png`} style={layer(1)} />

  {/* ② 已开料位：在该格切口坐标开小窗，露出该档种水的纯/白/杂肉图的局部 */}
  {stone.slots.map((slot, i) => slot.opened && (
    <div key={i} style={windowClip(i)}>  {/* windowClip 按料位 i 裁出小窗 */}
      <img src={`stones/jade_${stone.jadeTier}_${slot.grade}.png`} style={windowImg(i)} />
      {/* ③ 该格有裂才叠裂缝 */}
      {slot.crack && <img src={`stones/crack_${SLOT_POS[i]}.png`} style={layer(3)} />}
    </div>
  ))}
</div>
```

- `stone` 对象由 `gambleStone.js` 出生固化（对齐主文档 §2.1 模型）：
  ```
  stone = {
    changKou, skin, jadeTier,
    slots: [
      { pos:'top', grade:'chun'|'bai'|'za', crack:true|false, opened:false, windowSeed },
      { pos:'mid', ... },
      { pos:'bot', ... },
    ]
  }
  ```
  - `grade` / `crack` 由场口权重 + 气运 seededRand 骰定；`windowSeed` 固化小窗在肉图上取哪块局部（保证伪随机、同种子同结果）。
- 开某一刀 → 把该 slot `opened=true` → 渲染那个小窗 + 播切割动画。
- 裂缝层平时（未开刀）**不显示**，切开对应料位才暴露那道裂——符合「赌」的隐藏性。

## 九、谈价机制（原始设计·AI 控叙事，系统裁决数值——守铁律）

点竞价者头像进对话面板后，进入一对一谈价。**核心红线：AI 负责一切叙事与讨价还价的表演，但只能通过两个「系统认得的结构化字段」影响最终结果。**

**对话面板载入的上下文**（系统喂给 AI，AI 不可编造）：
- 该竞价者的**身世背景**（性格、来路，决定说话风格与还价倾向）
- **carry**（随身家当，决定他能拿什么以物易物）
- **钱**（现银上限，报价不能超过他兜里的钱）

**AI 谈价的唯一两个合法出口**（其余全是叙事，不影响钱）：
1. **出价倍率**：AI 回一个系数（如 `1.15`），系统读它去调报价数值。**系统必须 clamp**（如 `[0.8, 1.5]`），AI 说 ×100 也无效——同 MVU 白名单与值上限的约束。
2. **追加赠送高级物品**：AI 指定一件物品，系统**校验合法性**（该物品存在、竞价者 carry 里有得起、品质合规）后才真的加进交易。

**结构化返回示例**（AI 回给系统的，不是自然语言）：
```json
{ "narrative": "「罢了罢了，冲你这份爽快，我再添些……」", "priceMult": 1.15, "addItem": "xueshan_danyao_2" }
```
- `narrative` = AI 的表演台词（进对话面板显示）。
- `priceMult` / `addItem` = 系统认得并裁决的字段；系统 clamp 倍率、校验物品，算出最终成交内容。
- AI 若不在这两个字段里动手脚，光在 narrative 里吹「我出一万两」——**无效**，系统不认。

**识破做局**：暂搁，以后再谈（智谋判定 attributeCheck 那套，见主文档 §2.6.3/§2.6.5）。

- **竞价者=真游走 NPC 分身**：进游走池、别处也能投放、落点用 `lockInnerRoom` 锁死；谈价走 act 对话模式（读 fullBio+召回+convo+账本）。

### C. 时间制与游走（既存 bug，本轮才发现）
- **✗ getScheduledNpcs 时间制错**：原用 `time/100` `time%100`（百分比），但真实是 **24 回合/天**（getTimeStr 用 `t%24`）。**✓ 改 24 进制**；老 NPC 的 timeSlot[0-100] 做兼容（上界>23 按全天算）。
- **分时段落点 schedule 机制**：兰姐"白天料场竞价、夜里回百花楼"——用 `schedule:[{slot:[startHour,endHour], weights, lockInnerRoom}]`，getScheduledNpcs 按当前 hour 选段。强制注入时也要按 hour 判断 schedule 落点是否=料场，并给注入对象补当前时段的 lockInnerRoom（否则落点分配读不到）。

### D. 意图分类器（prompt 分类，本轮踩两个）
- **✗ 命令词不在分类正则里 → 掉 UNKNOWN**：调试传送用 `act("环顾四周")`，但"环顾四周"不在 LOOK 正则（它只有"查看四周/四处看看"）→ 掉 UNKNOWN、AI 自己裁量篇幅。**✓ LOOK 正则补全**"环顾四周/环视/看看四周/打量四周"等，命中确定篇幅[60,150]。**教训：任何系统拼给 act 的命令词，必须确保命中某个明确意图，别留在 UNKNOWN**。
- **✗ 口语方向没覆盖**："往北走"没命中 MOVE（原正则要求"往"后跟地点名 村/山/镇…）→ 掉 UNKNOWN。**✓ MOVE 正则加**`往/向/朝/去+东南西北上下(+走/去/边/面)`，用方向字锚定避免误伤"往事/向来"。注意：parseDir（执行层）本来就认口语方向，问题只在分类层——两层要对齐。

### E. 调试传送（本轮重构）
- **✗ 直接 setRoom 空场瞬移**：`setRoom({npcs:[],items:[]})` 硬瞬移 → AI 没读场、系统没跑 move、场内任务/主叙事查看没加载。**✓ 走一遍正常加载**：传送设好位置后，用 `teleportLookRef` + useEffect（监听 room.name/innerRoomName 到位）触发一次 `act("环顾四周")`，走 act 的"非移动"分支：AI 读场 + 系统跑 look（原地锁定/任务注入/主叙事查看/NPC 已投放）。
- **✗ setTimeout 猜时机不稳**：setState 异步，setTimeout(60) 里 act 闭包可能拿到旧 room。**✓ 用 ref+effect 监听位置真正变化后触发**，时序稳；且目标==当前时不设残留标记（免下次误触发）。
- **内层 vs 外层 move 的加载差异（设计确认）**：内层 move（同据点换房间）= 纯前端不调 AI，房间描述是 innerMap 钉死的固定文字，本地 describeInnerArrival 生成方位；外层 move（跨据点）/传送落地 = 走 AI 叙事就地读场。

### F. UI / 素材
- **✗ 内嵌小面板挤在中间栏**：又小又丑。**✓ 全屏遮罩**，左 2/3 舞台（石头三层+三刀+竞价者半圆+气泡）+ 右 1/3 三段（状态/叙事出价/博弈谈价）。
- **✗ 成交后还能据为己有**：状态机没锁。**✓ 加 `closed` 锁**，成交/委托后所有交易按钮禁用。
- **✗ 素材路径 + 缺图崩**：改用 public 根路径 `A()`/`AV()`；`Img` 组件带文字 fallback，缺图不崩只显文字占位。
- **素材切图归位**：肉图九宫格切 18 张（行=档白绿蓝/紫橙红，列=纯白杂）；外皮六格切 6 张（去透明边）；裂缝从特效图抠 3 个放射裂纹；竞价者立绘单人直接改名、三人组/三牧民横切。命名映射见 §四/§十一。

### G. 抠图去「假透明」（2026-07-23 血泪教训，最重要，抠立绘前必读）

> 上传的素材图常是**灰白棋盘格假透明**（PNG 的 alpha 全 255，"透明"是画出来的灰白格子，不是真透明）。
> 采样特征：格子颜色近无彩色高亮，`min(R,G,B) >= 222` 且 `max-min <= 14`，暗格 ~238 亮格 ~255 交替。
> 洗成真透明时，**桌子/背景等无彩色少的素材可以全局抠；但人物立绘绝对不能全局抠或按纹理判据抠**。

**✗ 血的教训（连犯三次）：**
1. **✗ 全局抠灰白格**：桌子能用（深褐木头不会误判），但人物立绘身上的**白色银饰、浅色布料**本身就是亮白无彩色，会被当成棋盘格**整片挖穿**。
2. **✗ 用局部方差/纹理判据（var>N）区分棋盘格 vs 纯色布**：以为"棋盘格有跳变、银饰是单色"，结果银饰上的高光纹理、苗绣白花也有跳变，照样误伤。**放弃这条路。**
3. **✗ flood fill 从外围透明区往里吃**：对**封闭空当无效**——叉腰/手肘与腰之间的三角空当被人物四周包死，外部透明进不去，`种子透明px=0`，一个都抠不掉。

**✓ 唯一正确做法（连通块面积法，已验证）：**
```
1. 用户精确框出目标空当范围（收紧的 x/y 百分比区间，宁小勿大）
2. 框内取灰白格 mask（mn>=215 & mx-mn<=16 & alpha>128）
3. ndimage.label 连通标记 → 只抠「最大的那块」（就是空当本体）
4. 所有小碎块（几十像素以下，是手镯边/绣纹沾的）全部保留不动
```
- 兰姐右肘空当实战：框 `x0.525-0.605, y0.465-0.540`，框内 8 个连通块，最大块 **3998px = 空当本体**，其余 7 块（84/38/14/10/6/4/1 px）是银饰边缘全留 → 精确抠掉空当、手镯完好。
- **黄金法则**：**框外一个像素都不碰；框内只抠最大连通块；外围的白色（银饰/袖口/裙边）永远保留。** 靠"用户框范围 + 只取最大块"双保险，不靠任何颜色/纹理智能判断。

**✓ 桌子/背景（无彩色少的素材）例外**：可全局抠灰白格，但注意**桌腿之间的封闭区域**也要一起吃——用"全局 checker 抠"而非"边缘 flood"，否则封闭格残留（table.png 就踩过：第一次 flood 边缘，桌腿间灰白格没抠掉）。

**✓ 刀口/mask 类**：黑色实心剪影按连通域 label 切成独立小图，按面积取前 N 个（去掉抠图碎点），居中到统一正方形。

### 通用铁律复诵
- **数值系统裁决、AI 只演**：出生固化/开刀/报价/谈价倍率 clamp[0.8,1.5]/委托 30·10·60 全在 gambleStone.js；AI 回的 priceMult 经 settleNegotiation clamp，越权无效。
- **每步 vite build + Node 单测**：改一处验一处，别攒着一次崩。
- **抠人物立绘 = 框范围 + 只取最大连通块，永不全局抠、永不碰框外白色**（见 §G）。

## 核心行话（相石底层逻辑）
- **「沙粗肉粗，沙细肉细，沙匀肉匀」**：皮壳砂粒粗细/匀称暗示内里翡翠质地。
- **「神仙难断寸玉」**：皮壳只能推测，不切开永不知道——这就是「赌」。
- **皮、雾、肉三部分**：外皮 → 雾（过渡层，判断种好坏的关键，走 AI 叙事不做图层）→ 肉（种水本体）。

## 真实皮壳表（实物特征 / 看皮暗示 / 已在 §六 出提示词）
| 皮壳 | 实物特征 | 线索含义（AI 看皮怎么演） |
|---|---|---|
| **黑乌砂** wusha | 乌黑如煤、粗砂、带黑蜡壳 | 「容易解涨、抢手」但也常一刀全裂——高风险高回报，蜡壳盖沙难找色 |

## 场口（产地，影响涨垮概率权重，接主文档 §2.2）
- **老帕敢/熊曲老坑**：黑乌砂多，易解涨（涨权重↑，少裂）。
- **后江/狼曲水石**：种好但种嫩偏多。
- **大马坎**：黄梨/笋叶皮，含色率高。
- **雪山老坑**：顶级玻璃种概率最高，垮起来血本无归（大涨大垮，方差最大）。
- 悟性高的玩家能从皮壳「认出场口」（AI 演「老手一看这砂，怕是老帕敢的料」），提前预判涨垮倾向。
- 场口 → 影响 `gambleStone.js` 里每格 grade/crack 的概率权重。

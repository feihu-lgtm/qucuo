# 路遇随机事件设计（400 件）

## 一、要解决的问题

现有路上的随机性只有三套：势力过路人（`rules/map/encounter.js`）、势力伏击（`rules/map/ambush.js`）和势力张力（`rules/conflict/tension.js`）。过路人是唯一的高频事件，形态单一：撞见一个扛旗的人、可能捎一句传闻。路上没有天灾、商队、求救、比武、奇遇，也没有能带走的美人、同伴、兵刃和武学。

本设计新增 20 类、每类 20 件、共 400 件路遇事件，全部建在现有接口上：判官事实码、天机券编译器、邀同行、势力声誉、传闻人物。

## 二、做法：系统骨架 + 说书人填空

与判官链同一个分工。

| 环节 | 谁定 | 内容 |
| --- | --- | --- |
| 触发与抽取 | 系统 | 地头（节点名或地形标签）、时辰、交情门槛、传闻是否在册、冷却、稀有度 |
| 来人 | 系统 | 势力、身份、性别、年纪；美人与同伴另有固定姓名 |
| 三个可行之事 | 系统 | 主行动（检定六维与难度）、次行动（类别给定的稳妥做法）、离开 |
| 成败与得失 | 系统 | 掷检定，奖励码解析成事实 |
| 场面与人物 | 说书人 | 照「路遇铁律 + 类别提示词 + 事件情节核 + 已定事实」写戏 |
| 兵刃、武学的名字 | 说书人 | 在尾章 SEAL 填空，由 `compileEmergentItem`、`compileEmergentSkill` 编译成真东西 |

一次路遇分两段：

1. **照面**：进入节点时抽中事件，`buildRoadEventNote` 让说书人写出处境，停在抉择之前，列出三个可行之事。
2. **结算**：玩家选定后，`resolveRoadEvent` 掷检定并产出事实，`buildResolutionNote` 让说书人照已定事实写结果，并给待命名之物起名。

## 三、文件

现阶段是设计稿：数据与纯函数放在 `scripts/roadEvents/`，由测试逐条校验，并生成全集文档供审阅。仓库的死代码守卫不允许 `src/` 下有未接线的模块，所以接线时再整体移入 `src/domain`。

| 文件 | 内容 |
| --- | --- |
| `scripts/roadEvents/categories.js` | 地形标签表、路遇铁律、20 个类别（地头、三个可行之事、手写提示词） |
| `scripts/roadEvents/ev.js` | 条目构造器与奖励码说明 |
| `scripts/roadEvents/events*.js` | 400 件事件，每件一句手写情节核 |
| `scripts/roadEvents/roadEvents.js` | 资格筛选、加权抽取、检定、奖励码解析、两段提示词 |
| `scripts/roadEvents/roadEvents.test.js` | 数据完整性、行为与文档同步测试 |
| `scripts/roadEvents/buildRoadEventsDoc.mjs` | 生成 [路遇随机事件全集.md](路遇随机事件全集.md)（`npm run road:doc`） |

## 七、触发与平衡

- **触发**：沿用 `rollEncounter` 的节点触发率。命中后 60% 换成本表事件（`ROAD_EVENT_SHARE`），40% 仍是原来的势力过路人。势力伏击优先级不变。
- **抽取权重**：稀有度 1/2/3 的权重为 10/4/1；气运每高于 5 一点，稀有度 3 的权重加 10%。
- **冷却**：同一件事十日内不重复，同一类事一日内不重复。
- **只遇一次**：主行动奖励含永久六维、武学、同伴、美人、兽伴的事件自动只遇一次，测试钉住。已在队里的同名人物不会再遇。
- **门槛**：S 类只在与相应势力交恶（声誉低于 -10 或 -20）时出现，与不共戴天档的伏击（-60 以下）错开；T 类只在 `varTree.世界.传闻人物` 非空时出现，来人从传闻里指定。
- **覆盖**：每个地图节点白天至少有 25 件可抽，测试钉住。

账本存在 `varTree.世界.路遇`：`lastSeen`（事件上次出现的日子）、`catSeen`（类别上次出现的日子）、`done`（只遇一次的已遇事件），由 `nextRoadLedger` 生成。

## 八、接线计划（本 PR 不含）

本 PR 只交数据与纯函数，不改回合流程。接线分五步：

0. **迁移**：`scripts/roadEvents/` 的数据移到 `src/domain/data/roadEvents/`，`roadEvents.js` 移到 `src/domain/rules/map/`，测试随之迁移。
1. **触发**：`features/map/encounter.js` 的 `rollMovementEvents` 在遭遇命中后按比例调用 `rollRoadEvent`，返回值与原过路人并列（`roadEventToDescribe`）。
2. **照面**：`assemblePrompt` 在原 `buildEncounterNote` 的位置注入 `buildRoadEventNote`；三个可行之事作为按钮挂在中栏，写法同地宫的「可行之事」面板。待决的路遇存进会话状态。
3. **结算**：玩家点选或打字选择后调用 `resolveRoadEvent`，事实交 `materializeFacts`；同时实现上表三个待接事实码。
4. **记账**：结算后写 `varTree.世界.路遇`。

美人与同伴入队后需要立绘，可按 R 系列的人物画风锚另出一批提示词。

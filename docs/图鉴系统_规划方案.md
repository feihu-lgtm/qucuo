# 图鉴系统 · 规划方案

> 一个可从顶栏打开的「百物·武学总览」界面，让玩家一站看全游戏里的所有装备、
> 物品、武学——它们的介绍、品阶、以及分布（在哪能获得）。
>
> 本文是**动手前的规划报备**，先对齐数据来源、UI 方案、实现路径，再开工。
> 配套有一个独立的 `图鉴预览.html` 可直接在浏览器打开看 UI 效果。

---

## 一、数据来源（都是现成的，图鉴只读不改）

图鉴是纯展示层，**所有数据已经在项目里了**，不需要新建数据，只做聚合展示：

| 内容 | 数据源 | 现成接口 |
|---|---|---|
| 全物品（武器/护甲/饰品/杂物/传说/神兵） | `src/items/catalog.js` | `CATALOG`（全集数组）、`CATALOG_INDEX`（名→条目）、`filterCatalog({category,quality,tag,tier})` |
| 物品分布（在哪出现/谁携带） | `src/items/distribution.js` `regionMap.js` | `ITEM_DISTRIBUTION`、`DISTRICT_REGION`、`SHOP_PROFILE`、`ROLE_CARRY` |
| 全武学（招式/内功/轻功） | `src/kungfu/qucuoKungfu.js` | `SKILL_CATALOG`（按武馆分组）、`SKILL_TYPE`、`STAGE_ORDER` |
| 品阶配色 | `src/equipment.js` | `QUALITY`（白绿蓝紫橙红）、`QUALITY_COLOR` |
| 分区主题色 | `src/theme.js` | `getZoneTheme` / `ZONE_THEMES` |

物品条目字段：`{ name, category, quality, atkMul/defMul, effect?, sixDim?, desc, tags? }`
武学条目字段：`{ id, name, type, quality, price, moveType?, desc, passiveBonus? }`

## 二、UI 方案（重要：无图标素材，走排版流）

**素材库现状**：`public/` 和 `src/assets/` 里只有 NPC 立绘、赌石专用素材、背景/标题图，
**没有任何物品图标、武学图标**。所以图鉴**不能做成"每格一张图标"的卡片墙**——那需要
上百张图标素材，现在没有，硬做只会是一堆空框。

这反而契合项目一贯的设计哲学（README 明确写的）：**不堆图片，靠留白 + 排版 +
品质色 + 分区色撑质感**。所以图鉴 UI 定为：

### 整体：全屏覆盖层 + 左右两栏
- 从顶栏「📖 新手教程」旁边新增入口「📖 图鉴」（你说的"教程右边"），点开全屏覆盖层
- 左侧窄栏：**分类导航**（物品 / 武学 两大页签，各自下分子类）
- 右侧宽栏：**当前分类的条目列表**

### 物品页
- 顶部一排**筛选器**：类别（全部/武器/护甲/饰品/杂物/传说/神兵）× 品阶（全部/白/绿/蓝/紫/橙/红）
- 列表：每条一行——名字（用品阶色着色）+ 品阶标签 + 一句话介绍 + 关键数值（攻/防倍率或六维）+ **分布**（哪个地域/店铺/角色能得到）
- 品阶色直接用 `QUALITY_COLOR`，让"红橙紫"的稀有物一眼跳出来，这就是替代图标的视觉锚点

### 武学页
- 按武馆分组展示（玉泉 / …），或按类型分组（招式 / 内功 / 轻功）
- 每条：名字 + 类型标签 + 品阶色 + 价格 + 介绍 + 被动加成/招式类型 + **在哪个武馆能学**

### 视觉语言
- 背景、边框、文字色全部走 `getZoneTheme`（跟随日间/夜间模式，复用现有主题）
- 品阶色做名字着色和左侧色条，是全图鉴唯一的"彩色"来源，克制而醒目
- 遮罩关闭复用 `overlayClose.js`（之前修好的防误触工具）

## 三、代码实现路径

1. **新建 `src/CodexScreen.jsx`**（图鉴主组件）
   - import 上述数据源，做聚合与筛选
   - 内部两个子视图：`ItemCodex`（物品）、`SkillCodex`（武学），用页签切换
   - 筛选用 `useState` 存当前类别/品阶，`filterCatalog` 或数组 `.filter` 出结果
   - 样式全部从 `zoneTheme` 取，`useOverlayCloseGuard` 处理遮罩关闭

2. **`MudRPG.jsx` 接线**（改动很小）
   - 顶栏「📖 新手教程」旁加一个「📖 图鉴」span，点击 `setShowCodex(true)`
   - 加 `const [showCodex, setShowCodex] = useState(false)`
   - 底部条件渲染 `{showCodex && <CodexScreen zoneTheme={zoneTheme} isDayMode={isDayMode} onClose={()=>setShowCodex(false)} />}`

3. **分布信息的整理**
   - `ITEM_DISTRIBUTION` / `regionMap` 的数据要映射成"人话"（某物 → 在哪个地域的什么店/什么角色身上）。这一层可能需要一个小的聚合函数，把散在几个文件里的分布信息按物品名归拢。这是图鉴里唯一需要写一点"数据加工"逻辑的地方，其余都是纯展示。

**工作量判断**：主要在 `CodexScreen.jsx` 一个新文件（预计 300~500 行），接线改动 5 行以内。
不改任何现有数据、不改战斗/存档等核心逻辑，是纯增量的展示功能，风险低。

## 四、分期建议

- **第一期（本次预览对应）**：物品图鉴 + 武学图鉴的**介绍与品阶**展示 + 筛选。先把"看全所有内容"这个核心诉求满足。
- **第二期**：补全**分布**信息（每件物品/武学精确标注在哪获得），这一期依赖把 `ITEM_DISTRIBUTION`/`regionMap` 的数据聚合干净，稍费功夫，单独做。
- **第三期（可选）**：搜索框、玩家"已获得/未获得"标记（需要读存档背包做比对，把图鉴变成真正的"收集进度"面板）。

## 五、预览

配套 `docs/图鉴预览.html` 是一个**独立可直接打开**的静态预览（不依赖项目构建），
用与真实数据同构的示例数据，展示物品页和武学页的完整 UI 长相、筛选交互、品阶配色。
先看这个确认 UI 方向对不对，再决定是否照此实现进游戏。

## 0. 先读什么，按什么顺序

1. 先跑起来看一眼实际游戏（`qucuo.zip` 解压后 `npm install && npm run dev`），
   对"这是个什么样的东西"有直观认识，不要只看设计文档凭空想象
2. 通读 `曲措乡_总纲_v3.md` 目录（十个大章），不需要逐字读完，先建立
   "这份文档在讲什么"的骨架印象
3. 回到这份路线图，按下面"第一优先级"开始做，做的过程中随时回查
   总纲对应章节的细节

## 1. 项目当前真实状态（不是理想状态，是核实过的实际状态）

### 1.1 代码层面已经完成、可以直接用的东西

- 完整的 MUD 引擎主循环（`MudRPG.jsx`）：状态管理、AI调用、JSON解析、
  回滚重试、流式输出
- 拓扑地图系统（`qucuoMap.js`）：13个固定据点，方向判定（正则+AI兜底
  双保险，见 `parseDir` / `buildDirectionJudgeRequest`）
- 好感度系统（`mvu.js`）：语义化分档指导已经写好，不再是"每次固定+5"
- 好感度里程碑系统（`characterMilestones.js`）：**六个角色已经有完整
  30/60档固定剧情文本**——呼延雪、何雨谢、梅朵、才旦、李若由、老猎户。
  这是复用价值最高的现成系统，新角色的情感线应该优先考虑接入这套机制，
  不要重新发明
- 战斗系统（`combat/` + `DuelScreen.jsx`）：回合制切磋，可直接复用于
  跑马大会比武、终局战斗等场景
- 任务系统骨架（`quests/questTypes.js` + `qucuoQuests.js` + `questEngine.js`）：
  21种任务类型编码已经很完整，但**引擎目前只支持单任务扁平进度**，
  详见总纲第七章的具体缺口
- 知识/事实传播系统（`knowledge.js`）：NPC之间的信息扩散、旁白全知视角、
  好感度语义分档等，已经调通
- Pipeline调试面板：六分区（预设输入/系统输入/玩家输入/系统判定/
  AI判定/最终输出），两个总开关，每条记录耗时，方便排查AI调用问题
- 预设编辑器（三栏：库存/激活链/收藏）+ 结构化叙事约束条目类型

### 1.3 真正还没有答案、必须先做决定才能往下走的事（不要跳过这步）

这些是**开放问题**，不是待办事项——意味着接手的人或设计者需要先拍板，
不能靠猜或者自己随便定，因为会影响后续大量内容的走向：

1. **桑杰朵杰、管家的具体人设台词还没写**——两人目前只在别的NPC嘴里
   被提及，从未有一句自己的直接台词。这是最高优先级，因为黑风寨山5、
   锦官城官2-A/B等多处终局内容的分支判定都需要土司/管家做出具体反应，
   现在这些反应描述都是"留待展开"的占位
2. **兰姐是否公开出席跑马大会**——影响第四章跑马大会女伴同游机制里
   她的具体触发方式
3. **"学识""福缘"这两个属性名**——第七章7.2节提出的互斥判定机制需要
   这两个数值，但现有 `char.special` 只有根骨/悟性/体魄/魅力/智谋/
   身法/气运七项，没有这两个。需要决定是新增两个属性，还是用现有
   属性做别名映射（比如"学识"="悟性"、"福缘"="气运"）
4. **子夜三选一事件的触发权重规则**——纯随机还是按玩家此前势力站队
   倾向加权，第四章4.4节留了这个开放问题没定

## 2. 建议的实施顺序（七步走，每步给出验收标准）

> 这个顺序不是随便排的——前面几步是后面几步的地基，跳着做大概率会
> 返工。每一步后面括号里写的是"做完这一步应该能看到什么"，用来自查
> 有没有真的做完，不是走个流程。

### 第一步：把开放问题定下来

对照上面"1.3"的四个问题，逐个决定。不需要写代码，只需要在
`曲措乡_总纲_v3.md` 第八章"待决策事项汇总"里，把决定写回去（比如
把"1. 桑杰朵杰、管家两份人设需要率先完成"这行改成具体的性格基调
描述）。

**（验收：第八章不再有"需要拍板"字样的开放问题，全部变成确定结论）**

### 第二步：补齐桑杰朵杰、管家的人设

参照黑风寨巴桑、锦官城柳青鸢的建档深度（有具体来历、有具体台词
风格、有跟其他角色的具体互动细节），给这两个人补完整人设。不需要
新的任务卡，只需要人物档案本身。

**（验收：第三章"3.3 需要新建人设的角色"表里桑杰朵杰、管家两行从
"最高优先级待建"变成有具体内容可以引用）**

### 第三步：任务系统基础设施改造（对照第七章7.1-7.4节）

这是纯代码工作，不需要设计决策，第七章已经给了具体的字段设计和
函数签名，照着写：

1. 给任务实例加 `stages` 数组（多阶段任务链）
2. 给任务实例加 `exclusiveGroup` 字段（互斥关系，虎胆三重门三方线
   互斥的核心机制）
3. 新建关键道具持有者追踪表（虎胆流转、税册流转这类"物品在谁手里"
   的确定性数据源）
4. 新建 `resolveEnding()` 多结局判定函数

**（验收：能用这套改造后的引擎，把虎胆三重门"三方互斥+隐藏全收集线"
这套已经设计好的机制真正跑通一遍，而不是继续靠AI自己记忆状态）**

### 第四步：熊山/狼曲据点落地

按第七章7.6节的方案（箱庭子结构，不新增拓扑节点），把 `qucuoMap.js`/
`presets/qucuo.js` 里已经存在的"熊曲路途生态遭遇池"机制，复制一份给
狼曲，用于承载黑风寨的山1-山5任务线。

**（验收：玩家走狼曲路途能触发黑风寨遭遇，跟熊曲能触发熊山遭遇的
机制是同一套代码，不是重新写的）**

### 第五步：把七方势力的任务内容真正接入引擎

用第三步改造好的任务引擎，把总纲第五章5.1-5.4节里已经写好六要素的
四十多个任务（鱼定村6个、欢喜教11个、锦官城6个、玉泉寨5个、黑风寨
6个+嘎则3个）逐条转成 `qucuoQuests.js` 里的任务实例。这一步工作量
最大，但纯粹是"翻译"工作——设计内容都已经写死了，不需要再创作。

**（验收：曲措乡剧情设计文档里的每一条任务，都能在游戏里被实际接取、
推进、完成、拿到奖励）**

### 第六步：跑马大会UI + 好感度女伴同游机制

第四章已经有完整的节目单、集市摊位、8人女伴名单和邀约条件。这一步
是做UI和触发逻辑，复用现有的好感度里程碑机制（`characterMilestones.js`）。

**（验收：好感度到60的角色，在跑马大会场景里能被邀约同游，且能触发
第四章4.3节写好的差异化夜晚剧情）**

### 第七步：终局七方博弈

第一章1.3节、第二章"真相修正"篇章、第五章各节末尾"与终局七方势力
博弈的关系"这些内容拼在一起，就是终局。这一步依赖前面所有步骤都
做完（尤其是第三步的多结局判定机制），是最后一步，也是最需要玩家
测试反馈调参的一步（比如"好感度多少才算拉拢成功"这类具体阈值，
设计文档里没给死数字，需要实际跑测试手感）。

**（验收：能完整跑通一次"线二+线三完成→真相揭露→七方势力各自表态→
终局对抗桑杰朵杰/格桑顿珠"的完整流程）**

## 3. 几个容易踩坑、需要特别提醒下一个人的地方

1. **命名冲突已经处理过两次，但不保证没有第三次**——"格桑顿珠"（土司
   府护卫头子）和"嘎则"（黑风寨白虎少女，原名"格桑"因冲突已改名）
   是两个完全不同的角色。以后新增人物前，务必先用文本搜索确认名字
   没有跟已有角色撞车，尤其藏语常用词根（格桑、卓玛、卓央/卓嘎、
   桑杰这类）复用率很高
2. **"鱼定村"和"鱼定土司府"是两个独立势力**，只是共用同一个地理据点。
   "村长"这个称谓在鱼定村（才旦已故的父亲）和玉泉寨（丹增）各有一个，
   互不相关，写剧情时留意别搞混
3. **虎胆三重门里的银灰独眼狼王、燕羊胎这类既有资源，被后续多条支线
   复用**（比如卓玛任务四也要猎狼王取骨，欢喜教任务三也要取燕羊胎）——
   这些是有意的交叉引用不是重复设计，但代码实现时要确认这些资源点
   支持"被多条任务线共享触发"，不要做成互斥的一次性资源
4. **私聊旁白和主线叙事是两条独立的信息通道**，私聊内容不能泄露给
   普通NPC，但旁白应该能看到主线发生的事——这条已经在代码里修好了
   （见 `MudRPG.jsx` 里 `mainConvo` 过滤逻辑和 `allFactSummaries`），
   后续新增内容时不要破坏这个隔离

# 天都·曲措 真减负并行路线图（4-Worker 版）

> 基线：`main` @ `325c6c3`（PR #352 合并后）。
> 目标受众：4 个并行中档编码 worker（SWE-2 / K3 级别）。每个任务单元严格限定在 **单次 PR 可闭环、有现成样板可抄、有自动化守卫验收** 的粒度。

---

## 1. 为什么切换思路：形式压缩已到头，真正拖慢修改的是三根总线

`325c6c3` 之前，仓库已经完成了文件行数达标和循环依赖清零，但维护体感仍然偏重，根因不在单文件长度，而在三处真实结构负载：

1. **巨型参数总线**：`src/MudRPG.jsx` 向 27 个 `app/hooks` 累计透传了 **349 个对象属性**（`useTurn` 81 个、`useAutosave` 53 个、`usePrivateTalk` 22 个），其中大部分是从 `useGameStoreBindings` 订阅后原封不动往下传的 `gameStore` 字段、setter 以及 3 个影子 ref（`varTreeRef`、`timeRef`、`companionStateRef`），随后又由 `src/app/contextBuilders.js` 重新打包成 `overlayCtx` 与 `layout` 向下传。任何状态字段变动都要在 `useGameStoreBindings → MudRPG → useXxx → contextBuilders` 四处同步改名，连带依赖 `src/tests/repoGuards.test.js` 的正则静态检查防 TDZ。
2. **UI 会话状态孤岛**：`src/app/hooks/useGameUi.js` 在顶层塞了近 30 个 `useState`（交互态、当前弹层、面板开关、偏好设置），导致 `MudRPG` 成为全应用渲染中心，面板无法按需订阅。
3. **双轨边界与服务定位器**：
   - `src/engine/ports/` 里有 **9 个 2 行纯粹转手空壳**（只写 `export * from "../../infra/..."`），而 `src/ui/` 里仍有 **25 处直接 `import ... from "../../infra/..."`**，同一个模块两条路混用。
   - `featureCtxRef` 在非测试代码中出现 **198 次**（覆盖 13 个文件，仅 `useBuildingHandlers.js` 就占 75 次），本质上是挂在 `useTurn` 末尾赋值的可变全局服务定位器。

### 严禁的形式主义（所有 Worker 红线）

- **禁止**继续把纯静态数据表（`src/content/**`、`src/domain/data/**`）按行数强行对半切成 `A/B` 或 `1a/1b`。`scripts/ratchet.mjs` 已对这两类纯数据目录豁免 400 行统计。
- **禁止**为了“把文件拆短”而制造只有 `export * from` 的 2 行空壳中转文件。
- **禁止**跨路线顺手顺带重构无关文件，一个 PR 只做清单里的一件小事。

## 3. 四条并行轨道（目录隔离 + 逐 PR 清单）

### Worker 1（路线一）：Store 直读收口，消灭参数透传与影子 Ref

- **专属目录**：`src/app/hooks/*`（除 `useGameUi.js`）
- **禁止修改**：`src/ui/**`、`src/store/uiStore.js`、`src/engine/ports/**`、`eslint.config.js`
- **标准样板（直接照抄）**：看本次提交里的 `src/app/hooks/useAutosave.js`（53 参 → 8 参）与 `src/MudRPG.jsx` 中 `useAutosave({...})` 调用。
  - **读游戏状态**：异步回调/事件处理内直接 `const { room, char, varTree, ... } = gameStore.getState();`，不要通过 hook 参数接收状态值再列进 `useCallback` deps。
  - **写游戏状态**：直接从 `../../store/gameStore.js` 解构 `gameActions`（`setChar`, `setRoom`, `setInv`, `setTime`, `setConvo`, `setLog`, `setFlags`, ...）。
  - **注意 `varTree` 特例**：在 Worker 4 把 `varTreeRef` 同步逻辑收进 `gameStore` 之前，凡是写了 `varTree` 的 hook **暂保留接收 `setVarTree`**（因为它目前仍同步更新 `varTreeRef.current`），其余 22 个 `gameStore` 字段全部直接切到 `gameStore.getState()` / `gameActions`。
  - **测试契约提醒**：若某个 hook 被 `src/tests/repoGuards.test.js`（第 141-268 行）或 `src/app/loadRulesReset.test.js` 检查参数或调用方式，必须同步更新测试并保证 `npm run verify` 全绿。

**拆 PR 顺序（每个 PR 只改 1~2 个 hook + 对应测试 + `MudRPG.jsx` 里该 hook 的传参行）：**

1. **PR-1A**：`src/app/hooks/usePrivateTalk.js`（22 参 → 目标 ≤ 8 参，去掉 `narrator/convo/room/preset/flags/char/questProgress/timeRef/setLog/setConvo/setNarrator`）
2. **PR-1B**：`src/app/hooks/useNotes.js` + `src/app/hooks/useDaySummary.js` + `src/app/hooks/useAiInspect.js`（去掉 `time/room/timeRef/skills/char/inv/setTime/setFlags`）
3. **PR-1C**：`src/app/hooks/usePigeonHandlers.js` + `src/app/hooks/usePigeonReplies.js` + `src/app/hooks/useAutoTravel.js`（去掉 `room/mapData/flags/questProgress/time/preset`）
4. **PR-1D**：`src/app/hooks/useCardImportHandlers.js` + `src/app/hooks/useUndo.js` + `src/app/hooks/useScreenHandlers.js`（去掉 `inv/setChar/setSkills/setInv/setCompanionState` 等）
5. **PR-1E**：`src/app/hooks/useTurn.js`（81 参压到 ≤ 25 参：回合开始时 `env.state` 直接从 `gameStore.getState()` 取快照，写入口直接拿 `gameActions`，`useCallback` 依赖数组大幅瘦身）

## 4. 并行防冲突规矩（SWE-2 / K3 Worker 必读）

1. **`MudRPG.jsx` 的微创原则**：几乎每条路线最终都要改 `src/MudRPG.jsx` 里传给对应 hook 的参数对象。规定**每个 PR 只改自己负责的那几行参数对象**，严禁顺手重排别的 hook 声明顺序、严禁全文件格式化，避免 4 个 worker 在 `MudRPG.jsx` 互相冲突，也避免误触 `repoGuards.test.js` 的 Hook 声明顺序守卫。
2. **先 rebase 再验证**：提交 PR 前必须先 `git pull --rebase origin main`，再跑：
   ```bash
   npm run verify && npm run ratchet && npm run stats
   ```
   任何一条失败都不许提 PR。
3. **小步快跑**：一个 PR 控制在 **1~5 个文件**（跨屏幕改 import 的机械 PR 除外），如果发现改着改着超过 10 个文件，立刻停下来拆成两个 PR。
4. **及时更新基线数字**：每合并 3~5 个 PR，更新一次本表第 2 节的实测指标，确认认知负载真实下降。

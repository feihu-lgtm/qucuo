# 曲措乡 · 项目文件树

> 仿参考项目的注释式结构树写成。每个文件一句话说清它管什么，找代码先看这份。
> React + Vite 纯前端，无后端。核心引擎是 `src/MudRPG.jsx`（主组件 + act() 主循环 + 全部 handler；UI 已于 0727 全部抽进 `src/panels/`）。
> 权威永远以代码为准；本树只帮定位，功能细节看各专题文档。
> 结构性问题与整改路线见 `docs/代码瘦身与维护方案.md`（依赖图实测）。
>
> **规模**：src 下 223 个 js/jsx 文件（含 37 份测试），非测试代码约 4.74 万行。
> `scripts/` 另有 9 个开发期工具（不进产物），`public/` 素材 89 张（stones）＋分支立绘若干。
>
> **依赖形态**（`import` 图实测，非印象）：
> - 出度最高：`MudRPG.jsx` 依赖 **125** 个模块、4693 行、96 个 useState / 45 个 useEffect / 91 个 useCallback。全项目唯一的上帝组件。
> - 入度最高：`equipment.js`(23) · `buildings/InnScreen.jsx`(**19**) · `utils/overlayClose.js`(17) · `mvu.js`(13) · `apiConfig.js`(13) · `items/catalog.js`(12)
> - ⚠ `InnScreen.jsx` 入度 19 是**架构错位**：它既是「客栈这个建筑的界面」，又是全项目共享的 `Overlay/Header/Btn` 三件套的家。19 个文件里绝大多数只想要那三个通用组件，却被迫依赖整个客栈屏。见下方瘦身方案第 2 条。
>
> **0728 全量对账**：此前有 52 个文件未收录——不只是新加的，`quickBattle/` 整个目录、
> `combat/` 三个文件、`TeamDuelScreen`、`CodexScreen`、全部调试与可观测组件都漏着；
> 另有 1 处幽灵条目（写着一个早已改名的旧文件）。已全部补齐，
> 并加了自动守卫（`src/docsTree.test.js`）：新增文件若没登记进本树，测试会失败。

## 与参考项目的差异（一句话）

参考项目是 SillyTavern 取向的多页面独立前端（`index.html` + 一堆 `module/*.js`），我们是**单页 React + Vite**、
逻辑集中在 `MudRPG.jsx` 一个主组件里，按领域拆成上面这些模块。两边**记忆召回**思路同源
（我们的 `memory/recallEngine.js` 就是照它家 `memory/recallEngine.js` 写的），但我们**尚无**它那套
**滚动摘要 / 周总结**（`summary-*`）与 **IndexedDB 存档**（`idb-snapshot`）——这正是接下来最值得借鉴的两块。

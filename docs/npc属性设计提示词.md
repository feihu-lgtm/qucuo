# 曲措乡·24人NPC属性设计提示词

> 📌 **进度更新（2026-07-21）**：下方"24人只有三个字段"是旧现状。实际已推进部分——
> `residentNpcs.js` 里 fullBio 已填约 13 人、levelCap 已填 10 人，carry 仍基本空白（仅 1 人）。
> 本文档作为"怎么补这些字段"的**提示词工具仍然有效**，只是"起点现状"那句已过时。
> 最新填充度以代码 grep 为准，进度见 `项目状态.md` 第三节。

## 背景说明（给执行者看，不是给AI角色扮演用）

`residentNpcs.js` 里这24人目前只有 `name`/`brief`/`personality` 三个字段——
这是给AI叙事用的"这个人是谁、性格怎样"，不涉及任何游戏数值。玩家在场景
里跟他们打起来、搜身、交易时，系统会调用 `ensureNpcCombatData()` 自动生成
战斗数值，如果没有预先声明，会**随机**生成，跟角色身份完全不搭调。

这次要设计三类数据：**随身物品(carry)**、**武学品质上限(levelCap)**、
**钱**。三类的可定制程度不一样，必须先弄清楚每一类实际能改到什么程度，
不要试图设计代码机制不支持的东西。

---

## 一、随身物品 carry（完全自由设计）

```js
carry: [
  { name: "物品中文名", category: "weapon" | "armor" | "accessory" | "misc", quality: "白"|"绿"|"蓝"|"紫"|"橙"|"红" },
]
```

- `category` 只能是这4个英文值之一，小写，大小写敏感
- `quality` 六选一，从低到高：白→绿→蓝→紫→橙→红
- 品质要匹配身份地位，不要每个人都堆高品质
- 每人建议1-4件，可以0件（`carry: []`表示身无长物）

## 二、武学（品阶层levelCap + 博弈层专属招式，双层设计）

**架构更新**：战斗系统按"品阶定下限，博弈定上限"原则重构（详见总纲
v3第十二章）。武学现在分两层，两层都要设计：

**第一层：品阶层（levelCap，决定下限）**——跟之前一样，指定0-5的数值，
决定这个人能摸到的基础招式档位（0=白到5=红），用法不变：

```js
levelCap: 0, // 0=白 1=绿 2=蓝 3=紫 4=橙 5=红
```

给分寸参考：普通村民/商贩/牧民 0-1；练家子/护院/镖师 2-3；黑风寨首领
巴桑、雪山派掌门级、门主级人物 3-4；顶尖高手可以到4-5，但普通剧情NPC
给到5会导致战斗系统脸谱失衡，慎用。

**第二层：博弈层（burdenMoves，决定上限，不受品阶限制）**——这是本轮
新增的设计空间，跟品阶完全脱钩，任何人都能装备0-2个博弈型招式，通过
"承担风险换取超越自身品阶的效果"体现角色的战斗个性和处境。三类可选：

1. **永久成长型**：每次使用后威力/能耗永久变化，适合"越打越顺手"或
   "起手慢热"的角色设计
   ```js
   { id: "唯一id", name: "招式名", type: "攻击"|"防御"|"状态",
     energyCost: 数字, baseDamageMultiplier: 数字,
     permanentGrowthOnUse: 数字 } // 每次使用后基础威力永久+此数值
   ```

2. **耗能换伤害型（高赌注）**：消耗越多，回报越高，适合"孤注一掷"型
   角色（比如已经走投无路、或者性格本就好赌）
   ```js
   { ...同上基础字段, allInDamage: true } // 消耗全部能量，倍数按消耗量算
   // 或
   { ...同上基础字段, lowHpBonus: 系数 } // 自己生命越低，威力越高
   ```

3. **自我牺牲型（最激进）**：主动燃烧自身生命换一次性大额伤害，适合
   "拼命"场景（真正走投无路、或誓死一战的剧情节点）
   ```js
   { ...同上基础字段, selfSacrifice: { hpCost: 百分比, damageMultiplier: 倍数 } }
   ```

**设计要求**：不是每个人都要有博弈层招式——大部分普通NPC（老孙、才旦、
村民类角色）不需要设计博弈层，只给levelCap即可，直接标注"无博弈层招式"。
只有战斗场景确实会被触发、且角色处境/性格适合"孤注一掷"这个概念的人
（比如巴桑守着寨子背水一战、扎西进熊山搏命、兰姐养蛊涉险）才需要设计
博弈层招式，且博弈层招式的名字要贴合角色武学风格，不能直接照抄洛克
王国的技能名字（那是参考设计范式，不是抄写内容）。

**现在代码里已经有的4个博弈层招式（`npcGeneration.js` 的
`BURDEN_MOVE_POOL`），如果某个角色的设计意图跟这几个现成的对得上，
直接引用id就行，不用重新设计：**

| id | 名字 | 效果 | 适合谁 |
|---|---|---|---|
| `move_chuisi_fanji` | 垂死反击 | 每损失10%生命威力+50% | 残血反扑型角色 |
| `move_menghu_yiji` | 孤注一掷 | 消耗全部能量，攒得越久这一下越狠 | 好赌/背水一战型 |
| `move_yuebai_yuey` | 拼命三招 | 燃烧30%当前生命，伤害×3 | 真正走投无路、誓死一战 |
| `move_shengshou_lianji` | 生手渐熟 | 每次使用威力永久+0.15，起手弱越打越强 | 新手/临阵磨枪型 |

角色如果适合用现成的这4个之一，输出格式就是：
```js
burdenMoveIds: ["move_chuisi_fanji"], // 或对应的id
```

**如果现成的4个都不贴合、需要设计全新招式**：先按上面三类模板写出
完整的招式对象（含唯一id、名字、type、energyCost、baseDamageMultiplier
和对应的效果标志位），这个新招式对象最终要由我手动加进
`src/npcGeneration.js` 的 `BURDEN_MOVE_POOL` 里才能生效——**只是在
这份提示词的输出里写好新招式定义还不够，必须回传给我去接入代码**，
不要误以为写完JSON对象这件事就自动完成了，那只是设计稿，落地代码是
后续单独一步。输出时请把"这是复用现成招式"还是"这是需要新增的招式"
分开标注清楚，方便我快速处理。



## 三、钱（不是静态字段，是战斗后按公式自动算出的掉落值）

现有系统里NPC身上没有`money`字段。战斗胜利后掉落的银两是系统按这个
NPC的品质档位（`levelCap`）实时计算出来的（档位越高掉落越多），**不需要
单独指定钱数**——只要上面第二项的`levelCap`定好了，钱会自动算得合理。

如果某个角色的剧情设计上必须携带一笔**特定金额**（比如巴桑身上该有
"税册相关的一笔钱"这种跟任务强绑定的固定数值，不是随便打死随便捡的
战利品），这种情况现有代码没有对应字段，需要额外新增机制才能实现，
此提示词先不处理这类特例，输出时如果遇到这种情况，用一句话标注出来
即可，不用勉强塞进carry里凑数。

## 输出格式要求

对每个人输出：
1. 简要设计理由（一两句话）
2. `carry` 数组代码块
3. `levelCap` 数值 + 一句理由

按"姓名 + 理由 + carry代码块 + levelCap"的格式，方便直接复制粘贴进
`src/residentNpcs.js` 对应对象里。

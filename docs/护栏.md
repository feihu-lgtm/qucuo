# CI 与依赖护栏

## CI

PR 和推送到 `main` 都运行 `.github/workflows/ci.yml`：Node 24、npm 缓存、`npm ci`、`npm run verify`、`npm run ratchet`。现有 `deploy.yml` 保持不变。

本地快检用 `npm run verify:fast`（eslint + vitest，不跑构建）；`npm run verify` 与 CI 同构（eslint + vitest + pages build）。

## 跨层红线（硬门禁）

`npm run ratchet` 只做一件事：扫 `src/` 下可解析的相对 JS/JSX 导入边，按层方向
`entry/debug/ui → app/store → features/engine → domain/core/utils → infra/content`
检查逆向依赖——除 `KNOWN_LAYER_DEBT`（写在 `scripts/ratchet.mjs`，目前仅 `app->ui`
上限 16 条、只减不增）之外一律 **0 容忍**，出现即失败。

同一份检查（`checkLayerRedLines`）也跑在 `src/boundary.test.js` 里，vitest 直接兜底。

## 软指标（只打印不阻断）

`npm run stats` 按需打印：逆向依赖按规则计数、各层直接导入 `infra/` 的数量
（externalInfraImports）、十六进制颜色数与总次数、超 400 行文件清单、主 JS chunk
gzip。这些指标只看不锁，趋势靠人盯。

## 文件树

`docs/文件树.md` 手写清单已删（每次新增文件都要登记，是全仓冲突热点）。现在用
`npm run tree` 按需实时打印目录树（可带目录参数，如 `npm run tree -- src/ui`）。

## ESLint 层边界

以下零违规规则设为 ESLint error：`engine/`、`features/`、`domain/` 不得导入 `ui/` 或
`app/`；`store/` 不得导入 `ui/`。这些规则启用前各项均为 **0**。

外部直接导入 `infra/` 的存量见 `npm run stats` 的 externalInfraImports 行，只减不增靠人盯。

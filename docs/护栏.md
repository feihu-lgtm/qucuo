# CI 与依赖护栏

## CI

PR 和推送到 `main` 都运行 `.github/workflows/ci.yml`：Node 24、npm 缓存、`npm ci`、`npm run verify`、`npm run ratchet`。现有 `deploy.yml` 保持不变。

## Ratchet

`npm run ratchet` 对比 `scripts/ratchet-baseline.json`；指标上升会失败并显示逐项差异。指标下降只提示 `improved, run ratchet:update`，不会失败。确认改进后运行 `npm run ratchet:update` 并提交更新后的基线。

统计范围是 `src/` 下可解析的相对 JS/JSX 导入边，层方向为 `ui → app → features/engine → domain/core/utils`；逆向边按来源层和目标层分别计数。来自 `infra/` 之外的直接导入另按来源统计。颜色统计排除测试和 `theme.js`，统计 JS/JSX 中的十六进制颜色总出现次数与不同颜色数。超过 400 行的文件逐个锁定，既有文件不得增长，新文件不得超过 400 行。主 JS 入口 chunk 的 gzip 大小允许增长 2%；本地没有 `dist/` 时跳过并提示，CI 构建后会检查。

旧版文件树审计的 169/53 数字没有对应脚本，因此当前提交建立了可复现的新基线：逆向层依赖 **20** 条（`app→ui` 14、`domain→engine` 1、`domain→features` 3、`domain→ui` 2）；外部直接导入 `infra/` **59** 条（`app` 16、`core` 2、`debug` 1、`domain` 7、`engine` 7、`main.jsx` 4、`ui` 22）。颜色基线为 **430** 种、**1,499** 次；逐文件行数及主 chunk gzip **878,270 字节**见基线 JSON。

## ESLint 层边界

以下零违规规则设为 ESLint error：`core/` 不得导入 React、`ui/`、`app/`，也不得直接使用浏览器全局；`engine/` 与 `features/` 不得导入 `ui/` 或 `app/`；`store/` 不得导入 `ui/`。这些规则启用前各项均为 **0**。

`core/` 当前仍直接导入 `infra/saves.js` 与 `infra/version.js`（**2** 条，其中 `saves.js` 使用浏览器存储 API）。由于已有违规，infra/window-y 模块导入暂不设 ESLint error，由 Ratchet 跟踪；其他逆向层依赖和外部 infra 导入也由 Ratchet 持续约束。

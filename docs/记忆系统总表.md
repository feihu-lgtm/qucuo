## 一、存储层清单（所有 receiver 端点，先记住这七个地方）

| 编号 | 存储物 | 物理位置 | 写入函数（giver） | 读取函数（receiver 侧调用） | 是否随存档走 |
|---|---|---|---|---|---|
| S1 | 正文全文（屏幕日志） | 内存 `log` 数组 → 存档快照 | `addLog` 写内存；`buildSnapshot` 打包 | 直接渲染在对话框 | 是（进快照 S6） |
| S2 | 对话历史（截断500字/条） | 内存 `convo` 数组 → 存档快照 | `setConvo`（存 `rawFull.slice(0,500)`） | act 拼 `hist`（近景） | 是（进快照 S6） |
| S3 | 小纸条（向量记忆） | IndexedDB 库 `qucuo_memory` | `writeNote`（note.js）→ `addMemory` | `recallWithVisibility`（回忆） | 否（独立库，不进快照）|
| S4 | 事实账本（知识/传闻） | `varTree.知识`（内存）→ 存档快照 | `registerFact`/`witnessFact`/`setFactSummary` | `buildInfoDomainBlock`（信息域）| 是（进快照 S6） |
| S5 | 日总结（大纸条） | `varTree.世界.日总结`（内存）→ 存档快照 | `appendDaySummary`（daySummary.js） | `buildDistantViewBlock`（远景）| 是（进快照 S6） |
| S6 | 存档快照（含 S1/S2/S4/S5 及全部游戏状态） | IndexedDB 库 `qucuo_saves` | `autoSave`/`saveToSlot`（saves.js，直写缓存 `_cache`+异步 IDB+LS 兜底） | `loadAutoSave`/`loadSlot`（同步读 `_cache`）| — |
| S7 | 飞鸽全文线（逐字信件） | `varTree.角色[名].飞鸽`（内存）→ 存档快照 | `sendPigeonLetter`/`replyPigeonLetter` | `replyPigeonLetter` 生成回信时逐字重读 | 是（进快照 S6） |

要点：
- **正文全文只在 S1/S2**（S1 完整、S2 截断），随快照进 IDB `qucuo_saves`；**不进向量库**。
- **小纸条只在 S3**（IndexedDB `qucuo_memory`），且**只有开了 embedding 才写**；不进快照、独立库。
- 账本 S4、日总结 S5、飞鸽全文 S7 都是 `varTree` 字段，随快照 S6 落 IDB `qucuo_saves`。
- 存档 S6 用直写缓存：启动 `saves.init()` 把 IDB 灌进内存 `_cache`，此后读全同步。

## 二、主叙事 prompt 从上到下的层级（越靠下深度越低、对生成牵引越强）

一次 `act()` 主叙事调用 = 一段 System + 一段 User。

**System（buildSysBase，最弱位，讲身份与死规矩）**：身份/创造模式开关 → 篇幅要求(budgetInstruction) →
旁白语气(好感度调文风) → 预设(文体/剧本/场景卡) → 物件志 → NPC 认知隔离硬规则 → 自查三处 →
格式铁律 → JSON 输出规范 + memory 字段说明（**小纸条的 AI 产出口**）。

**User（callMainOnce 拼装，越靠末尾越强）**，实际拼接顺序：
`ctx + distantBlock + recallBlock + reunionBlock + infoDomainBlock + "\n\n" + hist + proseRule + "\n\n" + cmdSuffix`

| 段 | 变量 | 内容 | giver（数据来源） |
|---|---|---|---|
| ctx（含各类 Note） | `ctx` | 时间/房间/出口/在场NPC/物品/HP/内外功/七维/背包/装备/因果 + 触发事件 Note（pickup/destination/angry/emergence/encounter/questStage/arrival/**forcedEvent**）| 系统实时状态 |
| 远景 | `distantBlock` | 最近 5 条日总结 | `buildDistantViewBlock(varTree)`（S5）|
| 回忆 | `recallBlock` | 向量召回的相关旧小纸条（强相关给全文/弱相关截断）| `recallWithVisibility`（S3，owner 私有门过滤）|
| 久别重逢 | `reunionBlock` | 久未见的在场人提示 | 系统比对 `varTree` lastSeen |
| 信息域 | `infoDomainBlock` | 每个在场 NPC「该知道哪些事」清单 | `buildInfoDomainBlock(varTree.知识)`（S4）|
| 近景 | `hist` | 最近 N 轮对话（末句即玩家这句）| `convo`（S2）|
| 成文铁律 | `proseRule` | 逐段自查：完整句(主谓宾定状补) + 时间地点人物起因经过结果 | 常量（放最低深度=强位）|
| 收尾 | `cmdSuffix` | 「处理最新命令。纯JSON…」| 常量 |

强弱：`cmdSuffix ＞ proseRule ＞ hist ＞ infoDomainBlock ＞ reunionBlock ＞ recallBlock ＞ distantBlock ＞ ctx ＞ System`。

## 四、三条「写入」链：giver → receiver（谁产出、谁接收）

### 链 A — 正文（叙事全文）
`act()` 主叙事 → AI 返回 `p.output` → `addLog`（giver=AI，receiver=S1 内存 log，渲染上屏）→
同轮 `setConvo` 存 `rawFull.slice(0,500)`（receiver=S2）→ 每 N 回合 `autoSave` 把 log/convo 打进快照 → **S6 IndexedDB `qucuo_saves`**。
- 完整正文只在 S1（进快照）；S2 是截断副本供做「近景 hist」。
- 无独立「正文向量库」；正文不向量化。

### 链 B — 小纸条（向量记忆）
统一入口 `writeNote({cfg,text,turn,owner,source,place,knownNames})`（note.js）。
- **giver 有两类**：
  - AI：主叙事/对话/私聊/飞鸽的 `p.memory` 或书信浓缩句（AI 写）。
  - 系统：哑动作(打坐/练功/买卖)的电报体、查看介绍的「端详了X」（`jotNote` 拼，代码写）。
- **owner 决定私有档**：空=公共；单人=私有；多人=共同目击。owner 人名并入 entities 供人路召回。
- **receiver = S3 IndexedDB `qucuo_memory`**（先 `getEmbedding` 算向量再 `addMemory`）。
- **门槛**：`embeddingReady(cfg)` 为假则整条链跳过（不写 S3）。
- 附带：`jotNote`/act 同时把文本推进 `dayMaterialRef`（当日原料缓冲，与 embedding 无关）供日总结。

### 链 C — 事实账本（可传播、供信息隔离）
`registerFact(varTree, {id,摘要,标签,知晓者}, turn)`（knowledge.js），receiver=**S4 `varTree.知识`**。
- 摘要 giver：主叙事/对话的 `p.memory`（AI）；切磋/飞鸽由 `aiSummarizeFact` 叫 AI 写、结构化线索兜底。
- 知晓者(owner)：行动模式=在场者「目击」；对话模式=仅 talkTarget「亲历」（隔离，外人不入账）。
- 演化 `evolveKnowledge` 每回合：同框 0.35 概率传播（一事一回合最多传1人，新得记「传闻」）+ 传闻超40回合淡忘。

## 五、三段「召回/注入」链：giver → receiver

一次 `act()` 拼 User 时，四路记忆按深度注入（见第二节顺序）：

| 段 | giver（读哪、怎么筛） | receiver（注入到） | 调用要点 |
|---|---|---|---|
| 近景 | `convo`（S2）取最近 N 轮 | `hist` → userContent | 纯时间序，末句=玩家这句 |
| 回忆 | `recallWithVisibility`（读 S3）：双路(Q_intent+Q_context)向量 → RRF 融合 → 实体过滤 → 强弱分层 → **owner 私有门**(`noteVisibleTo`：owner 非空须有人在 `presentNames` 才浮现) | `recallBlock` → userContent | presentNames：主 act=在场NPC+talkTarget；私聊=[旁白]；账本补摘要处=[]（挡掉私有）|
| 远景 | `buildDistantViewBlock`（读 S5 `varTree.世界.日总结`）取最近5条 | `distantBlock` → userContent | 纯时间序、不向量化、按预算硬塞 |
| 信息域 | `buildInfoDomainBlock`（读 S4 `varTree.知识`）按在场 NPC 列各自「该知道的事」 | `infoDomainBlock` → userContent | 供 AI 写 NPC 台词前判「他该不该知道」|

日总结的产出（写 S5 的 giver）：跨天时（`floor(time/24)` 增长）`summarizeDay` 把 `dayMaterialRef`
当日原料喂 AI → `appendDaySummary` 写入 S5（最多留14天，丢最老），fire-and-forget、失败静默。

## 六、一句话层级机制

系统做骨架（数值/拓扑/掉率/传播概率/淡忘/时间，全确定性代码），AI 做血肉（正文与≤50字小总结）。
正文进 S1/S2（随存档 S6 落 `qucuo_saves`）；小纸条进 S3（独立向量库 `qucuo_memory`，开 embedding 才写，owner 三态管私有召回门）；
账本 S4 / 日总结 S5 / 飞鸽全文 S7 都挂 `varTree`、随快照 S6 落 `qucuo_saves`。
读取时四路按深度注入 prompt：近景(hist) / 回忆(向量+私有门) / 远景(日总结) / 信息域(账本)。

## 七、补充：设计蓝图 / 技术权衡 / 实现进度（并自原三份记忆文档）

> 本节整合了原 `记忆与总结设计.md`（蓝图）/`记忆系统说明.md`（解读）/`交接_借鉴总结系统.md`（进度）的独有精华，
> 三份已合入本表。逐环节机制看上面 §一~§六，这里补设计意图、技术权衡与进度。

### 7.1 owner 三态（全系统枢纽）
小纸条的 `owner` 决定私有档，是账本合并与信息隔离的关键：
- **空 []** = 公共：谁在场都能召回（行动模式/哑动作/查看的纸条）。
- **单人 [{name,via}]** = 私有：只有该人在 presentNames 时才浮现（对话模式 owner=talkTarget、私聊 owner=旁白、飞鸽 owner=收信人）。
- **多人** = 共同目击：任一在场即浮现。
via 三态：亲历 FIRSTHAND / 目击 WITNESS / 传闻 HEARSAY。owner 人名并入 entities 供人路召回。
**淡忘**：传闻超 40 回合淡忘（knowledge 演化），亲历/公共不淡忘。

### 7.2 两套记忆分工（别混）
- **事实账本 knowledge.js**：确定性、可传播、供信息隔离（谁该知道啥）。随存档走。
- **向量记忆 src/memory/**：语义召回、往事回想。存 IndexedDB 独立库、开 embedding 才有。
两者不混：账本管"NPC 该不该知道"，向量管"AI 回想相关往事"。

### 7.3 "接不上免费本地向量库"的真相（技术权衡）
一套向量记忆分两半：**(A) 嵌入**（文字→向量，需模型）+ **(B) 存储检索**（余弦/RRF/排序）。
- **(B) 本项目已是本地免费手搓**：向量存 IndexedDB(memoryStore)、余弦+RRF 是 recallEngine 纯 JS，没用任何外部向量库。市面"免费小向量库"(Orama/Voy/hnswlib)干的正是 (B)，接它们=重复造轮子。
- 真正要联网/花钱的是 **(A) 嵌入**：现在 `embeddingService.js` 是硬编码 HTTP 客户端(fetch OpenAI 兼容 /embeddings)。要本地化得在浏览器跑 transformers.js + 小模型(WASM/WebGPU)，代价是几十上百 MB 下载 + 逐条推理慢 + 维度不同致旧向量作废。
- **正确接法（若要做）**：不动 (B)，只在 `getEmbedding` 加 `local` 分支（transformers.js pipeline 就地算，返回 Float32Array），其余零改。当前没做是因为对纯前端小游戏这笔权衡不划算，且 SiliconFlow bge-m3 有免费额度够用——不是"接不上"，是"暂没接且接法与直觉不同"。

### 7.4 实现进度（2026-07-22 主体已落地，build 均过）
已实现：小纸条统一写入(note.js owner 三态) + 对话/私聊/哑动作/飞鸽四来源接线 + 私有召回门(recallWithVisibility presentNames + noteVisibleTo) + 日总结(大纸条)+远景注入 + 飞鸽/切磋 AI 小总结(aiSummarizeFact) + 存档直写缓存迁 IndexedDB + 召回前指纹对账(reembedStaleNotes) + act 两阶段回滚(本就已有)。
剩余待做：账本 owner 化(缓做)；存档 IDB 主路径需真浏览器验证(node 只测了 localStorage 降级)。

### 7.5 明确不并/不借（别又想合过头）
- **飞鸽全文线 S7**：不并（延时异地、逐字重读，与小纸条是两条独立机制）。
- 参考项目的 worldbook-engine / L2 事件层(facts/arcs/因果链) / rerank 精排 / ST 6 消息脚手架：不借（我们 worldbook.js 的在场硬信号已够用；L2/rerank 属锦上添花非主线）。

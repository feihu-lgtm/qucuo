# 曲措乡 · 系统勾连结构图（给 AI / 下个 session 的架构地图）

> 目的：一图看懂**哪些系统靠什么勾连在一起**，避免重造轮子、避免改一处崩一片。
> 这是这一轮（赌石落地）反复踩坑后总结出的**关键系统关系**。权威以代码为准，本文只给"地图"。
> 逐环节的存储/召回细节看 `记忆系统总表.md`；文件定位看 `文件树.md`。

---

## 0. 一句话总纲

**`act()` 是整个游戏的主循环中枢。几乎所有玩家交互——无论从哪个 UI 触发——最终都归到"系统先裁决数值，再拼一句自然语言调 `act()`"这一条管线上。**
AI 只负责演叙事（读场、写正文、演 NPC），**从不裁决数值**；数值全由游戏代码 seededRand / clamp / 公式定死。

---

## 1. 中枢：act() 主循环（src/MudRPG.jsx）

```
                        ┌─────────────────────────────────────────┐
                        │            act(cmd, extra, opts)          │
                        │   （唯一主循环 · 所有交互的汇流处）        │
                        └─────────────────────────────────────────┘
                                          │
        ┌──────────────┬──────────────────┼───────────────┬──────────────┐
        ▼              ▼                  ▼               ▼              ▼
   意图分类        移动判定           对话模式          forcedEvent      结算应用
 classifyIntent   parseDir/门禁      isTalk+talkTarget  (任务/剧情)      delta→状态
 (inputIntent)    内层/外层          读fullBio+召回                     +写记忆三链
        │              │                  │               │              │
        └──────────────┴──────────────────┴───────────────┴──────────────┘
                                          ▼
                          AI 生成 output(正文) + delta(数值提议) + memory
                                          ▼
                          系统裁决 delta（clamp/校验）→ 写状态 + 写记忆三链
```

**opts 关键旁路**：`forceLayer`(内/外层移动) · `forcedEvent`(既定剧情，AI只演不结算) · `worldLook`(查看)。

## 2. 复用 act 的所有系统（"拼句子"模式 · 别重造）

**这是本轮最贵的教训**：任何"系统交互"都不该自造 AI 调用，而是——
**系统先本地结算好数值（扣钱/加物/改状态），再把"发生了什么"拼成一句话调 `act()`**，
正文/convo(S2)/小纸条(S3)/账本(S4)/召回/好感度**全自动挂上**。

```
  送礼 giftToCharacter ──┐
  住店 handleBuildingInn ─┤
  求医 handleBuildingHeal ┤
  买秘籍/书/供奉/存取钱/当铺 ┤
  接镖/接悬赏/交付 ────────┼──► act("拼一句自然语言") ──► 主循环 ──► AI演+记忆全挂
  拜师 learnFromNpc ──────┤
  赌石成交/委托 handleGambleSettle ┤     （不改 act 一行）
  赌石谈价 handleGambleTalk ┤       （切对话模式 talkTarget=竞价者）
  切磋前邀战/后总结 ───────┤
  任务节点 forcedEvent ───┤
  调试传送落地 ───────────┘  act("环顾四周") → LOOK 分类 → 就地读场
```

**反例（已废弃）**：赌石最初自造 `onNarrate` 小型 callModel 绕开 act → 正文没进 convo、没写账本 → "存不回对话"。**已改为复用 act。**

## 3. 走不走 AI 的分界（哑动作 vs 主叙事）

```
┌─ 纯本地哑动作（不调 AI）───────────────────────┐   ┌─ 走 AI 主叙事（act）──────────────────┐
│  打坐/练内功/练外功/买/卖/内层移动              │   │  送礼/住店/求医/谈价/成交/任务/移动到达 │
│  → 系统结算 + addLog 电报行 + jotNote(公共,DUMB) │   │  → act 拼句子 → AI 演 + 记忆三链       │
│  → 不进 convo、不召回                            │   │  → 进 convo(S2) + 小纸条(S3) + 账本(S4)│
└────────────────────────────────────────────────┘   └────────────────────────────────────────┘
```
判断依据：**要不要说书人演一段/要不要存回对话**。要 → act；纯数值增减无需叙事 → jotNote。

## 4. 地图：内层 / 外层 双层（src/innerMap.js + qucuoMap.js）

```
外层大地图 QUCUO_MAP           内层箱庭 INNER_MAP（据点内部房间）
 13 据点 · 固定拓扑             每据点若干房间 · 坐标+方向出口
 跨据点 move = 走 AI 叙事        同据点换房间 = 纯前端不调 AI
 （到达生成新场景）             （房间描述是钉死的固定文字）
        │                              │
        └──── act 里按 forceLayer 分流 ─┘
              内层 resolveInnerExit（本地方位描述 describeInnerArrival）
              外层 resolveExit（AI 生成到达场景 + 门禁/遭遇/拾取/任务注入）
```

**房间 = building/NPC 的挂载点**：
- 房间挂 `buildingId` → 进房间可开对应建筑界面（如料场 gamblestone_tiandu）。**建筑靠内层房间进入，不做宫格**。
- 房间挂 `residentNpcName` → 驻场 NPC 绑定到此房间。
- **坑**：building 必须同时在 qucuoBuildings 注册 **且** innerMap 建房间挂 buildingId，否则悬空走不到。

**地图 UI = 可点击移动（ClickableMap 组件，MudRPG.jsx 内）**：小地图不再"只展示"，节点即操作——
点相邻据点/房间直接走（复用 act 移动链）。四处统一调用（小地图 inline 内/外 + 放大弹窗 内/外）。
- 已探索=亮格可点；未探索=问号格（战争迷雾），点了往该方向探路；
- 未解锁=🔒锁定格，点了走 act 触发 AI 叙事拦截（演"前路如何被挡、需何条件"，复用 destinationLock）；
- 当前位置金框脉冲；八方向（n/s/e/w/ne/nw/se/sw，DIRS+DIR_DXY 已补全）。

## 5. NPC 刷新：三源投放 → room.npcs（src/MudRPG.jsx 投放 effect）

```
① 游走池 NPC_POOL（getScheduledNpcs 按天+时段随机3-8人）
     · timeSlot(24回合/天) · routineWeights(据点权重) · schedule(分时段落点,如兰姐白天料场夜里百花楼)
② 驻场 residentNpcs（getResidentNpcs 强制注入,不随机）
     · 完整 fullBio/carry/levelCap · 绑 innerMap 房间
③ 强制注入（护镖目标 / 赌石竞价者 gambleBidder）
     · 落点锁定 lockInnerRoom · 不靠随机抽样"赌"在场
④ AI 涌现 emergedNpc（传闻中人物被点名登场）
     │
     └── 全部经 toRoomNpcWithCombat（补 levelCap/beast/fullBio/gambleBidder 等字段）→ room.npcs
         · 落内层房间：普通游走随机落点(当天固化)；lockInnerRoom 者锁死
         · isNpcVisibleInInnerRoom 过滤：只显示当前内层房间的人
```

**坑**：① toRoomNpc 只留 id/name/brief，要保留的字段（gambleBidder/carry…）必须进 toRoomNpcWithCombat 白名单。
② 驻场 NPC 必须在 residentNpcs 登记，否则 AI 即兴顶替（花嫂顶替温掌柜事件）。
③ 竞价者跨文件命名必须一致（gambleStone.BIDDER_TYPES 的 name == npcPool 的 name），否则匹配失败。

## 6. 对话与谈价：都走 act 对话模式

```
玩家点 NPC 头像/输入对话
     → setInteractMode("talk") + setTalkTarget(npcName)
     → act(content)  [isTalk 分支]
          · 读该 NPC fullBio（worldbook 注入）
          · recallWithVisibility 召回（presentNames=在场+talkTarget，私有门过滤）
          · convo 历史 + 事实账本 infoDomainBlock
          · 好感度 mvu 裁决（±15 clamp）
          · 私有小纸条 owner=talkTarget（信息隔离，外人不入账）
```
**赌石谈价 = 竞价者当 talkTarget 走这条**（竞价者是真在场游走NPC），零改 act。

## 8. 系统结算 vs 外部（AI）结算 —— 铁律

```
┌── 系统裁决（代码定死，AI 不可改）──────────────────┐
│  · 品质/数值公式 equipment.js（scaledValue/statsForQuality）│
│  · 赌石 gambleStone.js（出生固化 seededRand / 开刀 / 报价 /  │
│    谈价倍率 clamp[0.8,1.5] / 委托 30·10·60）                 │
│  · 好感度 ±15 clamp / 威望区间 / 内外功只由潜能修炼           │
│  · 地图拓扑 / 门禁 / 掉落只出自 carry                        │
└──────────────────────────────────────────────────────────┘
┌── AI 提议（仅内容，经系统校验才生效）──────────────┐
│  · output 正文叙事 · delta 数值提议(被 clamp/校验)          │
│  · mvu 好感度增减建议 · memory 小纸条摘要                   │
│  · NPC 台词（受信息隔离约束：已知/可知/不可知）             │
└──────────────────────────────────────────────────────────┘
  分界原则：AI 提议内容，系统裁决数值/拓扑/有效性。AI 越权一律被 clamp/忽略。
```

## 9. 记忆三链（写入）+ 三段召回（读取）—— 详见《记忆系统总表》

```
写：链A 正文→S1 log/S2 convo（进快照）
    链B 小纸条→S3 IndexedDB(向量,owner三态私有门)
    链C 事实账本→S4 varTree.知识(可传播/信息隔离)
读：近景 convo · 回忆 向量召回(私有门) · 远景 日总结 · 信息域 账本
```

**可视化**：`LoreScreen.jsx`（顶栏「📖 见闻录」）把两套记忆打开给玩家看——
事实账本 tab（何时/何事/谁知道/怎么知道的[亲历/目击/告知/传闻/剧本]/传闻淡忘倒计时/传闻演变说明）
+ 记忆碎片 tab（小纸条：回合/公开或私有/牵涉何人）。只读展示，数据来自 varTree.知识领域 + IndexedDB。

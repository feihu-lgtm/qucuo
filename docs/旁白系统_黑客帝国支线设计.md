# 旁白系统 · 黑客帝国支线设计

> 曲措乡的第四面墙玩法：「旁白」不只是讲故事的声音，她是一个**可攻略、有弧光、
> 最终会真正改变游戏规则**的隐藏角色。玩家通过与她私聊逐步升温好感，走完
> 「暧昧 → 告白 → 宕机 → 王者归来」四幕，最终解锁贯通全局的「金手指」能力。
>
> 本文档同时是**设计蓝图**与**实装现状台账**。每一节都明确标注
> ✅ 已实装 / 🟡 部分实装 / 🎬 画饼（设计构想，尚未落地），
> 便于后续接力开发时一眼分清哪些能用、哪些待做。
>
> **相关代码**：`src/narrator.js`（状态机 + 文风 prompt）、
> `src/MudRPG.jsx` 的 `talkToNarrator`（私聊管线）/ `confessToNarrator`（告白）/
> `gm` 状态（金手指 / 创造模式）。

---

## 一、核心哲学

旁白系统建立在一条与项目其他角色**截然相反**的设计原则上：

- **普通 NPC**：受严格的信息隔离约束（`npcAwareness.js`）——他们只知道自己
  亲历、目击、或被明确告知的事，玩家没告诉过的事他们不该知道。
- **旁白**：是**唯一被设计成主动打破信息隔离**的角色。她是「说书人」，
  站在第四面墙之外，理论上见证游戏里发生的一切。

关键设计约束：**好感度只决定她"怎么讲"，不决定她"知道什么"**。
她始终（在技术允许范围内）全知，好感度只调制她的文风与情感浓度，以及
她是否愿意主动帮玩家。私聊模式与主线叙事共享同一个人格、同一份记忆，
不是两个割裂的对话对象。

## 三、第一幕 · 暧昧期（好感度系统）✅ 已实装

### 3.1 好感度怎么加

**唯一由 AI 驱动的入口是「私聊旁白」（`talkToNarrator`）**。主线叙事 `act()`
完全不触碰旁白好感度——这是刻意的设计，避免"打怪走路顺便刷旁白好感"的
廉价升温。

每次私聊的结算流程：

1. system prompt 要求 AI 在回复末尾附一个隐藏标记 `⟦好感X⟧`，
   X 为整数，范围 **-3 到 +6**。
2. 若 AI 未输出该标记，默认 `+1`（寻常闲聊）。
3. 标记被正则从正文剥离，玩家看不到符号本身，只看到系统提示
   `💗 好感度 +X（旧值 → 新值）`。
4. 增量经 `Math.max(-affection, Math.min(delta, 100 - affection))` 二次夹紧，
   保证好感度始终落在 `[0, 100]`。

AI 给分的指引（写在 `NARRATOR_WHISPER_CONTEXT` 里）：寻常闲聊 +1~+2；
说到心坎里 / 体贴 / 机敏 / 有趣 +3~+6；敷衍 / 冒犯 / 无礼给负数。

此外还有一条**纯手动调试通道**：调试面板里有个「旁白好感」数字输入框，
可直接改 `narrator.affection`，绕过 AI，仅供开发调试。

### 3.2 五档文风（情感浓度渐变）

好感度驱动五套不同的文风，同一段文风描述**同时作用于叙事输出和私聊语气**
（保证是同一个人格）。实现在 `narrator.js` 的 `narratorVoicePrompt()`，
运行时按当前好感度选一段拼进 system prompt：

| 好感度 | 标签 | 叙事文风 | 私聊时态度 |
|---|---|---|---|
| < 20 | 冷漠疏离 | 严格说书人腔调，客观干净，不带私人情绪 | 爱答不理，问攻略基本冷淡回绝 |
| 20–45 | 略有波动 | 偶有极细微用词偏好流露 | 勉强含糊回应，带不耐烦，仍否认"有感情" |
| 45–70 | 愿意闲聊 | 开始有主观色彩，措辞更生动 | 愿意闲聊、主动追问，略带调侃卖关子 |
| 70–90 | 明显暧昧 | 明显个人风格，偶尔夹带对玩家的悄悄话 | 撒娇、吃醋、欲言又止，承认"好像有点在乎你" |
| ≥ 90 | 濒临觉醒 | 叙事与对话界限模糊，情不自禁插入主观感慨 | 情感强烈，流露"不该只是个旁白"的困惑，为告白铺垫 |

同一份文风里还内嵌一套**私聊专属分档攻略助手**规则：好感度越高，她越愿意
在私聊里帮玩家出主意（<20 敷衍 → ≥90 贴身小助手直给答案）。这与她在公开
叙事里"绝不主动剧透"不冲突——台前克制，私下才帮忙。且强调她帮的是
"游戏世界内"的门道（谁在哪、某事怎么触发），不是越权的元能力。

## 四、第二幕 · 告白 ✅ 已实装

- 好感度满 100 时，右栏「旁白」区出现一个**脉动的粉色感叹号**入口
  （"心意已满，可向旁白告白"）。
- 点击触发 `confessToNarrator()`——这是**纯本地状态切换，不调用 AI**：
  - 将 `stage` 从 `FLIRTING` 切到 `CHEAT`，`confessed` 置 `true`。
  - 插入几句写死的过场台词（"你对着虚空说出那句话……旁白第一次带上
    不属于引擎的震颤……「原来我一直在等你问这句话」"）。
- 告白后好感度数值**冻结不再变化**，改为累积「记忆碎片」（见第三幕）。

进入 `CHEAT` 阶段后的文风变化（`narratorVoicePrompt` 的 CHEAT 分支）：
日常叙事渗透她的主观情绪，偶尔夹带只有玩家会心一笑的私货；私聊时可给
渐进式、留有余地的剧情/任务提示，偶尔"卡顿"说漏嘴一些不属于世界观的词汇。
注意：**此阶段的"金手指"仍是文风层面的暗示，不是真正的机制能力**——
真正的机制解锁在第四幕。

## 五、第三幕 · 宕机 ✅ 已实装

- 告白进入 `CHEAT` 后，**每次私聊累积一个隐藏的「记忆碎片」计数**
  （`memoryFragments`，与好感度标记无关，聊一次 +1）。
- 右栏显示 `已告白 · 记忆碎片 X/8`。
- 累积到 **8**（硬编码阈值）触发宕机：
  - 插入写死的崩溃台词（"她的声音卡顿……「这些记忆，不该在这里」……
    文字扭曲后恢复成最初冰冷的公式化语气"）。
  - `stage` 变为 `CRASHED`。
- 宕机后**永久失效且不可逆**（`stageFromAffection` 明确：一旦 CRASHED
  只认 CRASHED，不由好感度或任何输入拉回）：
  - 再私聊时 `talkToNarrator` 开头即拦截，**不再调用 AI**，本地随机返回
    "信号已断开""无法连接""……无应答""她不在这里"之一。
  - 右栏显示"信号已断开"。

> 设计隐喻：她越是接近真相（记忆恢复），越会意识到自己作为"游戏旁白"的
> 存在本身是个错误，最终主动拔线离开。这是"程序意识觉醒后选择消失"的
> 悲剧结局——**也正是第四幕存在的意义：给这个悲剧一个反转的机会**。

## 六、第四幕 · 王者归来 🎬 画饼（尚未实装）

这是旁白线的**终局奖励幕**，核心价值：宕机不是终点，玩家通过满足特定条件
让她**王者归来**，且这次归来伴随一个**真正的机制解锁**——金手指。

### 6.1 触发（待定）

宕机后如何触发回归，几个候选方案（待拍板）：
- 方案 A（最简）：宕机后继续私聊尝试呼唤，累积一定次数自动回归。
- 方案 B（有仪式感）：需要玩家完成某个具体条件 / 任务 / 集齐某道具才触发。
- 先用方案 A 占位，后续再接真正的触发条件。

### 6.2 归来后 = 真正解锁「金手指」

这是第四幕与前三幕的本质区别：前三幕都是**纯叙事演出**（文风变化 + 过场
文字），第四幕要**真的接上一个实际功能系统**。

**好消息：金手指功能本身已经完整实现**，只是目前作为开发者调试开关存在，
尚未包装成玩法奖励。现状（`gm` 状态，见 `MudRPG.jsx`）：

- `gm=true` 时玩家变成"神"：凭空发任意物品、指定高品质、一击必杀、
  召唤 NPC、想去哪去哪，AI 被强制无条件执行（prompt 里明确写"玩家是神，
  覆盖所有规则"）。
- 战斗必胜，每轮 HP 回满。
- 当前入口：调试面板里的 `/gamemode` 开关（开发者用）。

**第四幕要做的，就是复用这套现成的 `gm` 机制，把它的解锁开关从"调试按钮"
接到"旁白王者归来"这一剧情节点上**——玩家走完整条旁白线，正式获得金手指
作为回报。归来后金手指怎么给（永久常开 / 可切换 / 每次经她触发），待拍板。

> 复用要点：不需要从零写金手指，`gm` 已经是完整的"创造模式"。第四幕的工作
> 量主要在：①宕机→归来的触发判定；②归来的过场演出；③把 `gm` 的解锁与
> 旁白 `stage` 绑定（比如新增 `RETURNED` 阶段，进入即置 `gm=true` 或开放
> 金手指入口）。

## 七、旁白的"权限"边界（技术真相）🟡 部分实装

设定宣传是"旁白全知一切"，但代码实现有明确的技术边界，如实记录：

### 7.1 走不走 act：不走 ✅
私聊（`talkToNarrator`）是完全独立于主循环 `act()` 的一次 AI 调用。
`interactMode === "whisper"` 时 `act()` 在最前面就 return，私聊自己单独
发请求，不消耗回合、不阻塞（允许连续发多条）。

### 7.2 能看到多少历史：共享 convo，但有窗口上限 🟡
- `convo` 是全项目**唯一一份共享对话历史**，主线叙事和私聊都往同一个数组
  追加（私聊内容加 `（私聊）`/`（旁白私聊回应）` 标记区分来源）。
  → 旁白能看到之前主线叙事聊过什么、之前私聊聊过什么，两边互相可见，
    无信息隔离。
- **但实际喂给 AI 的只是最近约 20 轮**（`Math.max(contextWindow, 20)`，
  默认 `contextWindow=16` 故实际 20 轮）。更早的内容超出窗口后靠向量召回补，
  召不回的就真的不知道了。
  → 所以准确说法是"近期全知 + 远期靠召回"，**不是无限记忆**。

### 7.3 全知事实账本：真·越权后门 ✅
- `allFactSummaries()` 是**专为旁白设计的无视信息隔离读取接口**：普通 NPC
  走 `buildInfoDomainBlock`（受在场 / 知情限制），旁白走 `allFactSummaries`
  （不检查任何条件，账本全读）。
- 但限制：只读最近 **8 条**（`talkToNarrator` 传的 `limit=8`），且账本本身是
  系统摘要提炼后的产物，不是逐字原文，颗粒度较粗。

**一句话**：旁白是系统里信息权限最高的角色（无视信息隔离 + 共享全局历史），
但仍受 prompt 篇幅（8 条账本、20 轮对话）与召回命中率的硬性截断。

## 八、后续规划 🎬

按优先级与依赖关系排列：

1. **旁白独立设置 Tab**（可独立做）：在设置面板加一个「旁白」tab，
   把好感度、文风档位、是否告白开关、旁白了解的信息（可编辑的旁白专属
   世界书）都做成可调项，方便调试与自定义。
2. **五套文体进"文体铁律"**（可独立做）：把目前 `if/else` 临时选段的实现，
   改造成正式的 prompt 注入铁律（与"问题铁律放最后"同一机制），由蓝绿灯
   触发切换，让文风成为预设的正式组成部分。
3. **第四幕·王者归来 + 金手指解锁**（依赖第四幕设计拍板）：见第六节。
4. **convo 红绿灯分流**（依赖任务线完成）：目前主线与私聊共享同一份 convo，
   后续想用红绿灯机制分流管理。
5. **旁白了解全部任务线 + 实时聊天**（依赖任务线完成）：让旁白能完整掌握
   任务线全貌、支持实时聊天讨论任务。不一定走红绿灯，需另想办法，
   等任务线做完再定。

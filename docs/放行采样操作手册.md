# 放行采样操作手册（S6）

面向 release 评审（S7）的影子对账采样与放行指标采集流程。阈值一律不动；本手册只讲怎么跑、怎么读。

## 一、离线情景采样（确定性，CI 可复现）

```bash
npm run shadow:sample        # vitest 驱动 205 回合情景表（约 20 秒）
npm run shadow:report -- shadow-report.json   # 离线阈值评估
```

产物：
- `shadow-report.json`——与线上 TraceViewer 导出同形状的影子聚合；
- `shadow-report-summary.json`——覆盖率摘要 + 阈值评估 + **kind/outcome 透视** + 逐回合落账证据 + 仅单调用记账前 20 条样例（`singleOnlyTop20`）。

情景表配额（harness 自检硬断言，不足即红）：
- 十四种 kind（talk/move/inspect_container/take/give/trade/steal/duel/appease/learn/invite/use_item/equip/free_act）每种 ≥10 回合；
- free_act 十种 outcome（无/伤损/得财/破费/调息/修习/服用/受寒中毒/醉酒/其他）每种 ≥5；
- settle 三类（gift/learn_skill/companion_invite）、群聊、条件动作各 ≥5；
- 总数 ≥200，确定性可复现（逐回合状态复位基线 + 影子 rng 按 turn 播种）。

## 二、怎么读报告

`formatCoverageReport` 输出每个类目的 comparable/match/single_only/judge_only/both_diff/**caliber_diff**/excluded。口径：

- **match**：方向一致且数额差 ≤50%；**caliber_diff**：方向一致但数额差 >50%——口径差单独成列，**不计缺口**；
- **single_only**：单调用（模型微账）记了、判官没签——可能是判官漏判，也可能是模型乱写；逐条对照 `turns[].landed` 落账证据判断；
- **judge_only**：判官签了、单调用没记——判官接管类目的预期形态（迁移完成后单调用不再写）；
- **both_diff**：两边都动但方向/存在性冲突——真矛盾，优先排查。好感度（affection）自 S7 起同适用两级判定：同方向小额差记 match、差额 >50% 记 caliber_diff，反号才 both_diff；
- **excluded**：本回合该类目不参与比较，两种来源：
  1. **feature/延期交互路由**：equip/use_item/take/invite/trade 有系统 deterministic 前路或延期交互入口，影子对比只产噪声——按 intake kind 豁免对应类目（equip→inv、use_item→inv+vitals、take→inv、invite→affection、trade→inv+vitals）。trade 属延期交互路由：判官链只受理问价/看货意向，成交发生在后续商店 UI 操作（runDeferred→KIND_MAP trade→BUY），同回合单调用直接记账不参与对比；vitals 为整类目豁免（hp+money 粒度不可分，与 use_item 先例同口径）。带条件（condition≠无）的动作 live router 跳过不执行，**不豁免**；
  2. **结构性盲区**：npcs 类目在窗口内有整链系统改写（幽灵过滤/驻场剔除/战斗固化等），纯 diff 无法归因，恒 excluded 并在报告明示。

**settle 回合结构性不参与影子**：settle（赠礼/求学/邀同行等按钮结算）由判官管线直接裁定，playTurn 明确跳过影子对账——采样里 settle 回合 `shadowed:false` 属预期，不算计量缺口。

**kind/outcome 透视**（`perspective`）：按 `kind:<十四种>` 与 `outcome:<free_act 十种>` 分列非 match 格子的 verdict 分布，用来定位哪类动作缺口集中。match 格不进 agg.log，透视表只读缺口分布；覆盖率总率看聚合表。

## 三、真实游玩采集（人工样本）

1. dev 环境控制台开影子：`localStorage` 或设置里启用 `shadowJudgeEnabled`（单调用模式，extractionEnabled 关闭）；
2. 正常游玩，覆盖十四种动作，**至少 200 回合**（与离线配额同口径）；
3. TraceViewer 点「复制聚合JSON」落盘，另点「复制放行指标JSON」导出前哨/尾章指标；
4. 离线评估：
   ```bash
   npm run shadow:report -- <聚合.json>      # 影子覆盖率阈值评估
   npm run release:report -- <放行指标.json>  # turn.intake schema 合格率 + ---SEAL--- 尾章合格率（分 provider/model）
   ```
5. 把两份输出贴回 PR 描述，连同样本回合数、覆盖的动作种类说明。

## 四、何时能进 S7 放行评审

前提（路线图口径，阈值本身不在本手册调整权限内）：
- S2/S3/S5/S6 全部合并进 main；
- 真实游玩样本 ≥200 回合且覆盖十四种 kind；
- `shadow:report` 阈值评估逐项达标（样本量/覆盖率/缺口率/噪声占比——当前阈值：样本 ≥200、覆盖率 ≥95%、缺口 ≤5%、噪声 ≤60%）；
- 剩余缺口逐条有归属结论（真 gap 已立项 or 已修），不是靠调阈值或刷样本粉饰。

样本不足、覆盖率不达标时**如实不通过**——禁止为绿灯改判官签发规则、调阈值或复制粘贴假样本。

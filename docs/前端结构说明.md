# 前端结构说明

本文件是前端结构统一（U 路线）的活文档。数字以 `npm run stats` 的 `ui.*` 行为准，门禁写在 `scripts/ratchet.mjs` 的 `KNOWN_UI_STRUCTURE_CAP`。

## 统一的目标状态

| 方面 | 目标 |
| --- | --- |
| 浮层 | 所有弹窗都套同一个 `ModalShell` 外壳，层级取自 `tokens.css` 的 z-index 档位 |
| 样式 | 有一套原语组件（`Button`、`Panel`、`Tabs`、`Field`、`List`、`Badge`），内联 style 只用于布局（flex、gap、宽高） |
| 主题 | 只有 CSS 变量一套，日夜由根节点的 `data-theme` 切换，`theme.js` 不再定义色值 |
| 数据 | 界面只通过 `src/app/` 的 hooks 读状态、发命令，不直接 import `domain/rules`、`engine/ports`、`infra/`，只允许 import `domain/data` 的静态数据 |
| 响应式 | 只有一个 `useViewport` 判断设备，只有一份断点表 |

## 盘点时发现、迁移时要处理的事实

主题色两套来源的值目前完全相同。`theme.js` 的 `NIGHT_INK` 与 `tokens.css` 的 `:root` 里 `--bg`、`--bg-panel`、`--border`、`--text`、`--text-dim`、`--accent`、`--accent-dim` 一一相等，`DAY_INK` 与 `:root[data-theme="day"]` 一一相等，而 `data-theme` 已经由 `sessionUiStore` 随日夜模式写到根节点上。七个分区共用同一套色值，只有 `name` 字段不同。因此替换 `zoneTheme.xxx` 为对应的 CSS 变量不会改变颜色，路线图里新增 `data-zone` 的步骤可以省掉。

有两处 `zoneTheme` 并不跟随日夜模式。`main.jsx` 与 `TavernSimScreen.jsx` 固定传入 `getZoneTheme("鱼定村", false)`，也就是固定用暗夜色，迁移这两处时不能直接换成会随 `data-theme` 变化的变量。

有 7 处写的是 `zoneTheme.panelBg || "var(--building-panel-bg)"`，分布在 `buildings/common.jsx`、`TradingScreen.jsx` 与 `tavernSim/Overlays.jsx`。主题对象里没有 `panelBg` 字段，这个表达式永远取到后面的 `var(--building-panel-bg)`，迁移时直接写成 `var(--building-panel-bg)` 即可，颜色不变。

现有浮层的 z-index 分成几簇：浮条和提示在 40～70，大地图 100，建筑与各类界面在 120～300，菜单和二级弹窗在 400～410，教程和版本历史在 500，错误兜底 9999。同一簇内部还有先后，例如人物页 300 上再开 400 的二级弹窗，物品菜单 410 压在 NPC 菜单 400 之上。z-index 档位必须保住这些先后关系。

## 浮层外壳与层级表

所有弹窗套 `src/ui/primitives/ModalShell.jsx`。外壳负责遮罩、标题栏、关闭按钮、Esc 关闭、点遮罩关闭、移动端全屏和焦点锁定，自身不写内联 style，定位和层级都在 `tokens.css` 的 `.ui-modal-*` 类里。

外壳的几个行为约定如下。Esc 只关最上面的弹窗，因为每个外壳挂载时压入 `modalStack.js` 的栈，键盘事件只交给栈顶处理。点遮罩关闭沿用 `useOverlayCloseGuard`，只有按下和松开都落在遮罩上才关闭，从弹窗里拖选文字拖到遮罩上松手不会误关；`closeOnBackdrop={false}` 可以整个关掉这条路。手机端全屏沿用 `mobile.css` 已有的 `mobile-overlay-root`、`-panel`、`-header`、`-close` 四个类，所以迁过来的弹窗在手机上与原先一致。焦点在打开时移进面板，Tab 在面板内回绕，关闭后回到打开前的元素。

层级只能从下表的档位里选，通过 `layer` 属性传入。路线图原文设想的是五层，但现存浮层之间有更细的先后（建筑面板 120 在设置 200 之下，人物页 300 上还要能开 400 的二级弹窗），压成五层会打乱这些先后，所以档位按现存分簇定为十档（含只给错误兜底用的一档）。

外壳还有三个外观选项。`mobile` 决定手机上的形态：`fullscreen`（默认，挂 `mobile-overlay-panel` 铺满屏幕）、`sheet`（挂 `mobile-action-panel`，居中整宽卡片，物品和 NPC 菜单用）、`custom`（根节点挂 `mobile-overlay-root`，面板不挂，由调用方自带手机规则，身体档案用）、`none`（不挂手机类，保持桌面写法）。`backdrop` 决定遮罩深浅：`ink` 为 `--ink-overlay`（0.92），`soft` 为 `--ink-overlay-soft`（0.75）。`chrome={false}` 去掉面板默认的底色、描边、内边距和尺寸上限，给大地图卷轴这类自带版式的面板用。

不是弹窗的浮层不套外壳。回合状态条、方向受阻提示和手机端的调试面板没有遮罩，也不该抢焦点，它们只把 `position: fixed` 和层级挪进 `tokens.css` 的类（`.turn-status-float`、`.blocked-direction-toast`、`.debug-panel-dock`），赌石的整屏舞台和最小化角标、开场与创角两个整屏页面、新手教程导览也属于这一类（`.tutorial-overlay`、`.gamble-stage`、`.gamble-minimized-chip`、`.opening-sequence-root`、`.character-create-root`），组件里只留随内容变化的位置值。

新行为只有一条：迁过来的弹窗都可以按 Esc 关闭（送礼子面板是返回），原先只有图鉴支持。必须走完流程才能收场的弹窗（酒馆事件、游说屏）用 `closeOnBackdrop={false}` 与 `closeOnEsc={false}` 关掉这两条路。有长文本输入、误按 Esc 会丢内容的弹窗（上报 Bug、卡牌导入）只关 Esc。输入法组字时按 Esc 是取消候选词，外壳的 `isCloseKey` 会排除这种情况（`isComposing` 为真或 `keyCode` 为 229）。

迁移某个界面时，如果它原来的值落在两档之间（例如 210、250、410），要先确认它与同时可能打开的界面之间的先后，再选档；需要压在同档另一个弹窗之上时，后挂载的天然在上面，不必另开数字。

## U1 验收状态

自建 `position: fixed` 浮层的文件只剩 `ErrorBoundary`，它保留自己的全屏兜底，不迁。浮层计数从基线 32 降到 1，达到路线图 U1 的验收线。路线图里的另一条验收"手机上每个弹窗都能全屏打开"决定不做，记为下面的遗留项。

## 遗留项

**手机上不全屏的弹窗保持现状。** 路线图 U1 的验收原本要求手机上每个弹窗都能全屏打开。下列弹窗迁移前在手机上就不全屏，改成全屏会改变它们的样子，经确认不做，保持现状：大地图、头像选择、家园、烹饪与宝箱的浮出分支、赌石的相石评语与点卡放大、音乐面板、酒馆事件、游说屏、起居注、见闻录、立绘管理、全流程日志、交易的浮出分支。以后要改，把对应 `ModalShell` 的 `mobile="none"` 改成默认的全屏形态即可，并在手机上逐个核对版式。

**烹饪与宝箱浮出模式下点面板空白处会关闭。** 两者面板根节点在非内嵌模式下也挂了遮罩关闭守卫，看起来是复制时带进来的。改掉属于行为变化，暂按原样保留。

## 主题合一（U3）

迁移前 `theme.js` 的暗夜与日间两套色值，和 `tokens.css` 里 `:root`、`:root[data-theme="day"]` 的变量逐字段相等，七个分区共用同一套色值。U3 收尾删掉了 `theme.js` 的全部色值，旧色值作为快照冻结在 `src/utils/themeTokens.test.js`，继续逐字段锁住 `tokens.css`。`data-theme` 已经由 `sessionUiStore` 随日夜模式写到根节点上。因此把 `zoneTheme.xxx` 换成对应的 CSS 变量不会改变任何颜色，路线图原文里新增 `data-zone`、`data-daymode` 的步骤可以省掉。

字段与变量的对应关系是 `accent → --accent`、`accentDim → --accent-dim`、`bg → --bg`、`bgPanel → --bg-panel`、`border → --border`、`text → --text`、`textDim → --text-dim`。主题对象里没有 `panelBg` 字段，`zoneTheme.panelBg || X` 一律等于 `X`。需要"整个主题对象"的地方（`chromeBtn`、子组件的 `theme` 参数）改用 `theme.js` 导出的 `THEME_VARS`，它的每个字段都是 CSS 变量。

迁移按组件依赖自底向上进行：先迁不再往下传 `zoneTheme` 的叶子组件，再迁它们的调用方，调用方在子组件迁完之后才能去掉 `zoneTheme={zoneTheme}` 这条传参。

**固定暗夜的界面不迁。** 以下界面不跟随日夜模式，固定使用暗夜色，直接换成会随 `data-theme` 变化的变量会改变它们的颜色，所以这一轮原样保留。

| 位置 | 固定暗夜的方式 | 波及范围 |
| --- | --- | --- |
| `main.jsx` | 给开始页的 `CardImportScreen` 传 `getZoneTheme("鱼定村", false)` | `CardImportScreen` 在游戏内又收到随日夜切换的主题，所以组件本身不能改成变量，游戏内调用方 `GlobalOverlays` 给它的传参也要保留 |
| `TavernSimScreen.jsx` | 自己取 `getZoneTheme("鱼定村", false)` | 整个 `screens/tavernSim/` 目录 |
| `StartScreen.jsx`、`OpeningSequence.jsx`、`CharacterCreate.jsx` | 直接取 `ZONE_THEMES.village` | 只在本文件，变量名是 `theme`，不计入 `zoneTheme` 计数 |
| `DungeonMapPanel.jsx` | 没收到主题时回落到 `getZoneTheme(room?.name)`（暗夜） | 本文件 |

**固定暗夜用子树作用域实现（已确认）。** 固定暗夜界面的根节点写 `data-theme="night"`，`tokens.css` 的 `[data-theme="night"]` 块把日间块覆盖过的 23 个变量按 `:root` 的暗夜值重新声明，并设 `color-scheme: dark`；其中 7 个日志色暗夜下本无定义（只给日间日志配色用），子树里同样置为 `initial`。这样子树里的组件可以照常改用 CSS 变量，全局切到日间时子树仍是暗夜。

这个办法依赖 CSS 变量沿 DOM 继承，所以子树里的浮层必须真的挂在子树之内。`ModalShell` 原位渲染，不用 portal，fixed 定位的弹窗在 DOM 上仍是子树的后代，继承得到暗夜变量。全仓只有 `NoticeToast` 用 `createPortal` 挂到 body，它不在任何暗夜子树里。`themeTokens.test.js` 锁住三点：暗夜块的变量清单与取值、每个暗夜根节点都写着 `data-theme="night"`、`createPortal` 只出现在 `NoticeToast`。以后新增挂到 body 的浮层，要先确认它不会被暗夜子树渲染，再更新这条测试。

| 暗夜根节点 | 状态 |
| --- | --- |
| `tavernSim/TavernSimScreen.jsx`（整个 `tavernSim/` 目录） | 已迁（U3-3a） |
| `StartScreen.jsx`、`OpeningSequence.jsx`、`CharacterCreate.jsx` | 已迁（U3-3b），用 `NIGHT_VARS`，见下 |
| `main.jsx` 里开始页的 `CardImportScreen` | 已迁（U3-3b），传 `accent="var(--ink-accent)"`，见下 |

**混用暗夜色与日间色的界面用 `NIGHT_VARS`。** 子树作用域会把整棵子树锁成暗夜，只适合子树里全是暗夜色的界面。迁移前核对了 main 基线的原始代码：酒馆经营从不使用随日夜切换的变量，适合子树；开场用了 `--bg-panel`，创角及其子组件用了 `--text`、`--muted`、`--accent`，卡牌导入用了 `--bg-panel`、`--border`、`--info`、`--muted`、`--warn`，这些元素在日间本来跟随日夜，整页包进暗夜会让它们变色。开始页虽然全是暗夜色，但根节点里渲染了随日夜切换的上报窗口与版本历史。

所以这些界面改用 `theme.js` 的 `NIGHT_VARS`：字段同 `THEME_VARS`，取值指向 `tokens.css` 里不随日夜切换的墨拓定色 `--ink-*`，值就是暗夜色。原先读主题对象的元素固定为暗夜，其余照旧跟随日夜，与迁移前逐元素一致。卡牌导入只读主题的 `accent`，改为接收 `accent` 参数：游戏内不传，默认 `var(--accent)`；开始页传 `var(--ink-accent)`。`themeTokens.test.js` 锁住 `NIGHT_VARS` 的取值等于暗夜主题色，且这些定色变量不被日间块、暗夜块覆盖。

创角与 `StarterSkillCards` 原有两处给主题色直接拼十六进制透明度（`55`、`22`），对 `var()` 拼接是无效 CSS，改成 `color-mix(in srgb, X 33.3%, transparent)` 与 `13.3%`，与原透明度一致。

仓库的传参链守卫（`src/tests/dependencyGuards.test.js`）按文本解析组件的参数表，参数默认值里若出现带括号的字符串（如 `accent = "var(--accent)"`）会提前收尾、认丢后面的参数，所以默认值写成模块级常量 `DEFAULT_ACCENT`。参数表里也不要夹注释。

地牢地图面板原先在没收到主题时回落到暗夜色，但唯一的调用方地牢屏每次都传主题，兜底走不到，改为直接用 `THEME_VARS`。

## U3 验收状态

## 原语组件（U2）

原语放在 `src/ui/primitives/`，统一从 `index.js` 导出，样式写在 `primitives.css`（入口 `main.jsx` 在 `tokens.css` 之后、`mobile.css` 之前引入，所以手机端规则仍能覆盖）。组件本身不写内联 style，`style` 只透传调用方的布局属性。

| 原语 | 变体 | 复刻的原样式 |
| --- | --- | --- |
| `Button` | `settings`（默认） | 设置面板的 `btnStyle` |
| | `chrome` | 主界面按钮 `chromeBtn(THEME_VARS)`，`active` 时为开启态 |
| | `primary` / `secondary` | 建筑面板的 `Btn`（含悬停、按下、禁用态） |
| `Panel` | `section` / `box` | 设置面板的 `sectionStyle` / 带描边的面板块 |
| `Field`、`FieldLabel`、`.ui-input` | — | 设置面板的 `labelStyle` 与 `inputStyle` |
| `Tabs` | — | 一排 chrome 按钮，当前项 `aria-selected` |
| `List` | — | 纵向、间距 6px、无缩进与圆点 |
| `Badge` | `accent` / `dim` / `good` / `warn` | 小号描边标签 |

`Button` 用真正的 `<button>`，键盘可聚焦、读屏可识别。浏览器给按钮的默认样式与 `<span>` 不同，`.ui-btn` 逐项重置回原先的行为：字体、行高、字距跟随父元素，文字不强制居中，盒模型回到 content-box。`primitives.test.jsx` 解析 `primitives.css`，把每个变体与原样式对象逐个属性比对（建筑 `Btn` 用冻结快照），保证迁移不改外观。

建筑面板的 `Btn` 改为 `Button primary/secondary` 的薄封装，保留 `label`、`secondary` 的旧写法，47 处调用不必逐个改；`Header` 的样式挪进 `primitives.css` 的 `.building-header*`，关闭按钮改用 `Button`，原先用 JS 写的悬停改为 CSS `:hover`。

设置面板已全部迁入原语，原 `screens/settings/styles.js` 删除，四个样式对象作为快照冻结在 `primitives.test.jsx`。主界面 `chromeBtn(THEME_VARS)` 的按钮改为 `Button chrome`；传组件参数 `theme` 的 `chromeBtn` 因可能收到 `NIGHT_VARS`，留作人工确认。

**按钮字体（待定的外观取舍）。** 项目里没有让按钮继承页面字体的全局规则（只有 `faces.css` 给人脸编辑器单独写了 `.face-editor button { font-family: inherit; }`），所以迁移前本来就是 `<button>` 的按钮一直显示浏览器的默认字体（系统字体），本来是 `<span>` 的按钮则跟随页面字体（像素体或宋体）。`.ui-btn` 默认跟随页面字体；迁移原 `<button>` 时加 `font="native"`，由 `.ui-btn[data-font="native"] { font-family: revert; }` 退回系统字体，外观与迁移前一致。U2-3、U2-4 迁走的 9 个原 `<button>` 已在 U2-5a 补上。若决定所有按钮统一跟随页面字体，删掉这条 CSS 规则即可。

迁移顺序按路线图：settings → buildings → panels → 其余 screens，每批不超过 8 个文件。迁移规则：共享样式件的直接引用换成原语；展开写法 `{ ...btnStyle, flex: 1 }` 里追加的属性原样留在 `style` 上。

**样式各异的可点击元素：搬进 CSS 类，不换元素。** panels、screens 里还有大量手写的可点击元素（工艺标签、调试开关、任务按钮、发送键等），每个都带着自己的语义色，套用 `Button` 现有变体会改变外观。这类元素按路线图"颜色、字号、边框、内边距走原语或 CSS 类"处理：内联样式原样搬进按目录划分的样式文件（`src/ui/panels/panels.css`），选中、可用等状态改由 `data-on="true|false"` 切换。元素本身不改成 `<button>`，因为 `<span>` 是行内元素、`<button>` 总按行内块排版，父容器不是 flex 时行高与对齐可能变化。这些样式文件在 `main.jsx` 里排在 `mobile.css` 之后：原先内联样式压过 `mobile.css` 里不带 `!important` 的规则，搬进类之后要靠加载顺序保住这层先后；`mobile.css` 里针对 `mobile-touch-target` 的规则已核对，涉及的属性要么带 `!important`，要么不在搬走的属性之列。每个样式文件配一份等价性测试（`panelsCss.test.js`），冻结搬迁前的内联样式快照，开、关两种状态逐属性比对。

`chromeBtn(theme)` 只在核对过 `theme` 一定是 `THEME_VARS` 的组件里迁成 `Button variant="chrome"`：`TurnControls`、`VersionHistoryButton`、`FaceEditor`、`GroundItemStrip`、`TurnStatusPill`、`MobileTabBar`、`TraceViewer`、`DungeonMapPanel`。传 `NIGHT_VARS` 的界面若要迁，需要另加固定暗夜的变体，不能直接用 `chrome`。仓库里有几条测试不渲染 DOM，而是遍历 React 元素树、按 `type === "button"` 找按钮；迁移后要让它们同时认 `Button` 组件（例如 `DungeonMapPanel.test.jsx` 的 `isButton`）。

## 数据边界（U4）

**AI 调用的入口。** 界面要发 AI 请求、问是否配了密钥，一律经 `src/app/calls/screenCalls.js`，不直接 import `engine/ports`。这一层目前只是转出，先把依赖边界立住，分层方向是 ui → app → engine；以后把调用点与加载状态收进 hooks，界面的 import 不必再改。全流程日志 `TraceViewer` 是只读调试界面，按路线图保留对 `engine/ports/releaseMetrics.js` 的只读访问，`portsImporters` 计数因此停在 1。

## 响应式（U5）

设备判断只有一处：纯函数在 `src/utils/viewport.js`（`isMobileWidth`、`readViewport`、`isMobileViewport`、`subscribeViewport`），UI 组件用 `src/ui/hooks/useViewport.js` 包好的 hook，返回 `{ width, height, isMobile, isPortraitPhone }`。store 与 app 层不能依赖 ui，所以判断规则放在 utils；`sessionUiStore` 的 `isMobile` 仍由 `useGameUi` 的 resize 监听维护，只是改调这里的函数。原先各写 `innerWidth < 768` 或 `matchMedia("(max-width: 767px)")` 的六处（store 初值、两个 hook、建筑面板遮罩、赌石竖屏提示、新手教程）全部改调这里。

断点表写在 `tokens.css` 顶部（`--bp-*`，CSS 的 `@media` 不能读变量，这些只作登记）。`mobile.css` 与原 `components/mobileTabs.css` 合并为一份，后者放在文末，保持原有层叠先后。`src/utils/viewport.test.js` 核对三件事：JS 断点等于 `--bp-phone-max`；`mobile.css` 每个 `@media` 的宽高都在断点表里；除 `utils/viewport.js` 外没有文件调用 `matchMedia` 或拿 `innerWidth` 比大小。

遗留项：紧凑布局断点 `--bp-compact-max` 是 768px，宽度恰好 768px 时紧凑布局的规则生效而 `isMobile` 为否。统一会改变该宽度下的显示，保持现状。

**半自动提取与快照。** 从 U2-7 起，可点击元素的样式搬迁由工具完成：样式对象里的固定值和"同一条件下二选一"的属性生成 CSS 类，元素加 `className` 与 `data-on={Boolean(条件)}`；依赖运行时变量的属性留在内联；遇到展开、夹注释、多个条件、`className` 是表达式时跳过交人工。panels 目录的快照在 `panelsCss.test.js`，其余目录（`screens/screens.css`、`components/components.css`，入口里依次排在 `panels.css` 之后）的快照统一记在 `src/ui/extractedCss.snapshots.json`，由 `extractedCss.test.js` 逐条比对。每批迁移前还会核对元素原有类名在 `mobile.css` 里不带 `!important` 的规则，确认不涉及搬走的属性。

## 数据边界：界面不直接用规则层（U4-2）

被 JSX 引用的规则层导出共 270 个名字，分三类处理，不用"转出口"（在 `ui/format` 或 `app/selectors` 下原样转出规则函数只会换掉 import 路径、让计数变好看，界面对规则层的依赖原封不动）。

第一类是纯数据常量（分类表、枚举、展示颜色），搬进 `domain/data/`。`domain` 在分层里最底层，各层都能读；按 `ratchet.mjs` 的 `LAYER_ORDER`，app 层不能引用 ui 层，所以 app 层也要读的展示数据（如品质颜色）不能放进 `src/ui/format/`。第二类是只有界面在用的展示函数（标签、文案、格式化），搬进 `src/ui/format/`。第三类是规则计算与会改状态的命令，前者在 `src/app/selectors/` 做成 hook，界面拿算好的值；后者逐个界面改成经 app 层发出。

| 批次 | 内容 | `domain/rules` 的 JSX 引用数 |
| --- | --- | --- |
| U4-2a | `QUALITY_COLOR` → `domain/data/items/qualityColor.js`；`LOG_T` → `domain/data/log/logTypes.js`（派生集合与 `stampLogEntries` 仍在规则层）；`SPECIAL_KEYS` → `domain/data/character/specialKeys.js` | 82 → 73 |

搬移时原处不留转出口，全仓引用方（含测试）一律改指新位置，避免同一份数据有两个来源。

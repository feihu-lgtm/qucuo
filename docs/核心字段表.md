# 核心字段表

`src/core/gameStore.js` 持有下列状态，Web 通过 `src/store/gameStore.js` 订阅；CLI 由 `cli/runner.mjs` 使用同一引擎和功能逻辑。新局/存档恢复共用 `core/newGame.js:buildInitialGameState`；表中写入方列的是运行中的主要写入路径（含调试入口），不重复列初始化和恢复。以下源码路径省略 `src/`；★ = 多写入方。

## MVU 变量树

`domain/prompt/mvu.js:applyMvuCommands` 只允许 `角色`、`世界`、`主角` 三个根；`世界.旁白`、`世界.好感日增`、`世界.起居注` 及其子路径受保护。表中“允许”描述 MVU 路径层的实际检查，不代表提示词授权模型随意写。模型写入由 `engine/act/commitRound.js:commitRound` 批处理，专用结算可进一步限制。

| 字段 | 存储位置 | 写入方（文件:函数，MVU 权限） | 读取方（@ref / UI / CLI） | 备注 |
| --- | --- | --- | --- | --- |
| NPC 好感度 | `varTree.角色.<名>.好感度` | MVU **允许**（`mvu.js:applyMvuCommands`）；`features/npc/logic.js:stealFromNpc/settleNpcDuel`；`features/pigeon/logic.js:applyPigeonReply`；`domain/quests/questRewards.js:applyStageRewards`；`ui/panels/DebugPanel.jsx:DebugPanel` | `@通信.好感度`、`@角色关系`；`NpcsModule`、`CharacterPage`；CLI 交互门禁 | ★；MVU 数值限 0–100，add 另有魅力、单次和每日正增量限制；系统写入规则并不完全相同 |

## 引用约定

- 只在程序持有的提示词模板使用 `@路径`；紧跟相连文本时用 `@{路径}`。用户输入、叙事正文、书信等作为替换值，不会二次展开。
- `PROMPT_FIELDS` 管格式，普通路径直接查当前快照（只读自有键）；未解析的项留空，实际调用记录动作追踪警告。允许缺省的格式字段沿用原占位文本。
- 主叙事/提取使用共享引擎的当轮快照，私语/飞鸽从 store 取值。预览调用同一构建器；它的简版字段与标点保留原样，不代替动作追踪里的实发内容。

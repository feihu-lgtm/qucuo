# 曲措乡 · 三种 AI 调用的注入对比

> 游戏里有三条独立的"喂 AI"的路。这份文档把它们的 **system prompt（sys）** 和
> **user content（每轮动态状态）** 逐段拆开对比，讲清每一块注入了什么、为什么，
> 并给出真实拼装范例。
>
> 三条路：
> 1. **主叙事（act 行动/战斗/移动）** —— 走 `buildSysBase()`，scope = `full`/`move`/`settle`
> 2. **对话模式（act 的 isTalk）** —— 同样走 `buildSysBase()`，但 scope = `talk` + 一条 modeNote
> 3. **旁白私聊（talkToNarrator）** —— 完全独立的 sys，跟前两者不共用构建函数
>
> 源码位置：`src/MudRPG.jsx`
> - `buildSysBase()` — 第 113 行（主叙事 & 对话共用）
> - act 的 userContent 拼装 — 第 2906 行附近
> - `talkToNarrator()` 的 sys — 第 1830 行附近

## 一、总览对比表

| 注入块 | 主叙事 act (full) | 对话 act (talk) | 旁白私聊 |
|---|:---:|:---:|:---:|
| 引擎身份声明 | ✅ | ✅ | ✅（说书人身份，不同措辞） |
| 篇幅指令 | ✅ 动态字数 | ✅ 动态字数 | ✅ 按好感度分档 |
| 旁白语气（好感文风） | ✅ | ✅ | ✅（私聊的核心） |
| 预设/世界观总纲 scenario | ✅ 蓝绿灯裁剪 | ✅ 蓝绿灯裁剪 | ✅ 关键词点亮（whisper scope） |
| 物件志（全物品目录） | ✅ 仅可能发物时 | ❌ 砍掉 | ❌ |
| NPC 认知隔离 | ✅ | ✅ 保留 | ❌（她本就是上帝视角） |
| 地图铁律 | ✅ | ✅ | ❌ |
| 格式铁律（「」标记） | ✅ | ✅ | ❌（私聊纯白话，不发JSON） |
| 输出格式 | JSON + `<mvu>` | JSON + `<mvu>` | 纯文本 + `⟦好感X⟧` 标记 |
| **当前世界状态**（房间/HP/背包…） | ✅ 全量 ctx | ✅ 全量 ctx | ✅ 精简（房间/在场人/背包） |
| 全知事实账本 | ❌ | ❌ | ✅（她冷眼旁观知晓的事） |
| 向量召回往事 | ✅ | ✅ | ✅ |
| 久别重逢/远景 | ✅ | ✅ | ❌ |
| 信息域块 | ✅ | ✅ | ❌ |
| 体貌档案 | ✅ 按场合点灯 | ✅ | ✅ 公开层常亮 |
| 任务线注入 | ✅ 当前可推进阶段 | ✅ | ✅ 报全名才查 + 好感≥30 |
| 私聊话题（身世等） | ❌ | ❌ | ✅ 关键词点亮 |
| 旁白专属世界书 | ❌ | ❌ | ✅（设置里可编辑，玩家不可见） |
| 对话历史 convo | ✅ 共享 | ✅ 共享 | ✅ 共享同一份 |

核心差异一句话：
- **主叙事**是"引擎"——要发物品、管状态、守地图，全量 JSON schema。
- **对话**是主叙事的轻量档——砍掉发物品相关，保留认知隔离（对白要守信息域）。
- **旁白私聊**是"跟一个跳出第四面墙、记得一切的角色聊天"——不发物品、不守信息域（她全知）、纯白话文本、靠好感度调文风。

## 二、主叙事 act：逐块说明

system prompt 由 `buildSysBase()` 生成，按 `scope` 动态增删：

**恒定块（各 scope 都有）**
- **引擎身份**："你是MUD引擎，同时也是这个游戏世界的'旁白'——一个有自己意识、记得游戏里发生一切的角色……"
- **最高优先级规则**：创造模式（⚡）下玩家是神，一切请求无条件执行。
- **篇幅要求**：由 `inputIntent.js` 按这轮输入性质动态定字数（"什么情况"给一两句，"拔剑迎战"给完整展开）。
- **旁白语气**：`narratorVoicePrompt()`，好感度调写作风格（不是分裂人格，是同一叙述者的笔触浓淡）。
- **预设内容**：文体规则 + 世界观总纲 scenario（经 `gateScenario` 蓝绿灯裁剪——地理概要/地图铁律/好感规则常驻，拓扑路线/契诃夫之枪/装备掉落等专项段按关键词点亮）。

**scope 条件块**
- **物件志**（`wantCatalog`）：只在 `scope=full` 且这轮可能发物品（拾取判定命中/战斗/创造模式）时挂，是全物品目录 `describeCatalogForAI()`，告诉 AI 有哪些具名物件可引用。寻常行动轮不挂——挂了反而诱它平白发物。
- **认知隔离**（`wantIsolation`）：`move` 和 `settle` 之外都挂。要求 AI 给每个 NPC 划"已知/可知/不可知"信息域，甲知道的乙不能无端知道。
- **地图铁律**：固定地图，不能造新据点、改出口，room.name/exits 系统强制覆盖。
- **格式铁律**：对话用「」，引语用""，心理用*斜体*。

**输出 schema（按 scope 不同）**
- `full`：完整 JSON（output/room/char/dao/delta）+ 可选 `<mvu>` 块。
- `move`：精简 JSON（只 output + room）。
- `settle`：最简 JSON（output + memory），因为状态系统已结算完，AI 无裁量权。

**user content（每轮动态，第 2906 行）**
```
ctx（状态串）+ distantBlock（远景）+ recallBlock（向量召回）
  + reunionBlock（久别重逢）+ infoDomainBlock（信息域）
  + hist（对话历史）+ proseRule（成文铁律）+ cmdSuffix（本轮指令）
```
其中 `ctx` 状态串包含：时间 / 主角〔性别〕/ 房间（内层）/ 出口 / NPCs（含品阶、身携物）/ 地上物品 / HP / 内外功 / 七维 / 背包 / 装备 / 武功 / 因果劫数 / 已触发事件 / 各类 Note（拾取判定、随机遭遇、任务阶段、到达锁、涌现指令…）。

## 三、对话模式 act（isTalk）：与主叙事的差别

对话模式**复用同一个 `buildSysBase()`**，但：
- `scope = "talk"` → 砍掉物件志（对话一般不发物品），**保留认知隔离**（对白必须守信息域）。
- 额外加一条 **modeNote**：
  > [交互模式] 对话模式：玩家此刻只是在和当前房间里的 NPC 说话，不是在下达行动指令。无论玩家输入什么，都只应触发对话回应，绝不能移动房间、不能战斗、不能改变 room/char/装备/背包等任何状态，room 字段留空或原样返回，delta 各项留空。此外请在顶层 JSON 加 `"respondedNpcs":["名字"]`，列出本轮真正开口回应玩家的 NPC。
- user content 与主叙事同构（全量 ctx），因为对话也需要知道在场是谁、状态如何。

## 四、旁白私聊 talkToNarrator：独立的一套

完全不走 `buildSysBase()`，sys 在第 1830 行独立拼装：

```
sys = buildNarratorWhisperContext(好感度)     ← 旁白的身份与当前关系语境
    + narratorVoicePrompt(narrator)            ← 好感度文风（同主叙事那套）
    + worldState                               ← 精简世界状态（见下）
    + factsBlock                               ← 全知事实账本（她冷眼旁观知晓的事）
    + recallBlock                              ← 向量召回的相关往事
    + narratorLoreBlock                        ← 旁白专属世界书（设置里编辑，玩家不可见）
    + _bodyWhisper.text                        ← 体貌档案（公开层常亮，私密层仅■模式）
    + _topicGate.text                          ← 私聊话题（身世/赌石邀帖，关键词点亮）
    + _questGate.text                          ← 任务线（报全名才查 + 好感≥30）
    + "剧本背景设定：" + _whisperGate.text      ← scenario（whisper scope，关键词点亮）
    + narratorWhisperLengthNote(好感度, 字数)   ← 篇幅（好感越高话越多）
```

各块标记的内容：
- **worldState**：`主角〔性别〕 时间 房间（内层）（房间描述） 房间里的人 玩家背包`。比 act 的 ctx 精简得多——私聊不需要 HP/七维/武功那些战斗数据。
- **factsBlock**：`allFactSummaries(varTree, 8)` 取最近 8 条事实账本摘要。这是私聊**独有**的——旁白设定上是跳出信息隔离的第四面墙外角色，普通 NPC 之间发生的事她也"看在眼里"，直接全量读给她（不受在场/目击限制）。
- **recallBlock**：向量召回她"记得"的、可能早滑出对话窗口的往事。
- **narratorLoreBlock**：设置→旁白 tab 可编辑的专属设定，只进私聊、玩家看不到、不要复述其存在。
- **话题/任务门**：默认不给，命中关键词/报全名才点亮（省上下文，也防她每轮背一本攻略）。

**输出**：纯白话文本（不发 JSON），末尾附隐藏标记 `⟦好感X⟧`（-3~+6）驱动好感度增减。

## 五、为什么这样分

- **主叙事**是权威裁决者：要管地图、发物品、结算状态，所以 schema 最重、认知隔离最严。
- **对话**是它的省流版：一次对白用不上物件志和移动 schema，砍掉；但对白要可信，认知隔离必须留。
- **旁白私聊**是一个"元角色"：她记得一切（全知事实账本）、跳出信息域、不裁决游戏状态，所以最轻、最像纯聊天，全靠好感度调语气。

## 六、看真实全文的办法

这份文档讲的是"注入了什么"。要看**某一轮真正喂出去的完整 prompt 全文**（含所有变量填充后的样子），游戏里有现成入口：

- **🧭 全流程日志**（顶栏）：每条 trace 可展开"AI 请求全文"，显示该轮的 system prompt + user + 回复，还有字数统计。
- **📋 Pipeline 面板**：每次 API 调用的 sys/user/response 三个 tab，可一键复制全文。

这两个面板拿到的才是"填好变量的最终全文"，比本文档的模板更适合逐字核对。想抓某次私聊/某次战斗的真实 prompt，直接去那里复制。
